## A. 기존 명령 수정

### A-1. `analysis ui --tobe` — TOBE 이벤트 수 세기 (범위 표기·중복·생략)

**현상**
TOBE 화면에 `// [E5]~[E9] lunarName·… Collapse`처럼 범위로 적었더니 E5~E9(5개)가 2개로 세어졌다. C01-2에서 결과가 `10/5`로 나와 범위를 풀어 쓰고 나서야 `10/7`이 됐다.

**원인**: `src/yunhee/tools/analysis/ui.py` L78·L85
```python
t_ev = len(re.findall(r"\[E\d+\]", f_text))
```
- `[E5]~[E9]`는 E5·E9 두 개만 센다(범위 무시).
- 같은 E-id가 주석 두 군데에 있으면 두 번 센다(중복).
- `[E1 생략]`은 세지 않는다(이것은 맞다 — 생략은 구현이 아님). 하지만 표에 생략 수가 안 나와 "빠진 것"과 "일부러 뺀 것"을 구분할 수 없다.

**수정**
1. TOBE 파일에서 E-id를 **집합**으로 모은다.
   - 단일: `\[E(\d+)\]` → {n}
   - 범위: `\[E(\d+)\]\s*[~∼-]\s*\[E(\d+)\]` → {a..b} (a ≤ b일 때만)
   - 생략 단일: `\[E(\d+) 생략\]` → 생략 집합
   - 생략 범위: `\[E(\d+)\]\s*[~∼-]\s*\[E(\d+) 생략\]` → 생략 집합에 {a..b}
   - 같은 번호가 구현 집합과 생략 집합에 다 있으면 **구현**으로 친다.
2. TOBE 이벤트 수 = 구현 집합 크기. 생략이 하나라도 있으면 칸을 `10/7 (생략 3)`처럼 쓴다. 생략이 없으면 지금처럼 `10/7`.
3. AS-IS 쪽 세기(L57 `ev_cnt`)는 색인 md의 `[E0] …` 줄을 세는 것이라 그대로 둔다.
4. 버튼·그리드 세기는 바꾸지 않는다.

**기대 (검증 ID `A-1 ui 범위·중복·생략`)**
스크립트가 임시 폴더에 아래 내용의 `Emp02_TabPage_Others.tsx`를 만들고 `yunhee analysis ui Emp00_Tab_TransInfo --tobe <임시 폴더>`를 실행한다:
```tsx
// [E0] 화면 열림
// [E4] 저장
// [E4] 저장 (같은 E-id 두 번째 주석)
// [E5]~[E9] 콤보 Collapse
{/* [E1]~[E3 생략] 사진 */}
```
→ 표 줄에 `| Emp02_TabPage_Others | 1/0 | 10/7 (생략 3) | 0/0 |`가 있어야 한다.
그리고 실제 폴더 `--tobe frontend/src/pages/emp`에서 `Emp02_TabPage_Others`는 `10/7 (생략 3)`이어야 한다(현재 파일은 `[E1 생략]·[E2 생략]·[E3 생략]`과 `[E5]·[E6]·[E7]·[E8]·[E9]`로 적혀 있다).

**pytest**: `tests/test_analysis.py`에 위 문자열로 집합 계산 함수(예: `_tobe_event_ids(text) -> (impl:set, skipped:set)`)를 단위 시험.

### A-2. `analysis sql` (md) — DML 문의 테이블·출력 별칭이 틀림

**현상**
```
$ yunhee analysis sql emp02_others.upsert
### `emp02_others.upsert` (server/emp/mapper/emp02_others.xml:66)
- **파라미터**: birthday, chnName, decCtzNo, …
- **테이블**: upsert                    ← 틀림. upsert는 WITH 절 CTE 이름. 실제 테이블 emp02_others가 없음
- **함수**: f_create_seq, to_encrypts
- **출력 별칭**: f_create_seq, to_encrypts   ← 틀림. INSERT … SELECT의 값 목록이지 출력 컬럼이 아님
```
그래서 이 세션에서는 매퍼 XML을 `sed`로 열었다. (`-o code`로 본문을 볼 수 있다는 것도 md 출력에 안내가 없어 몰랐다.)

**원인**: `src/yunhee/tools/analysis/sql.py` L136-143
- 테이블을 `FROM x`·`JOIN x`에서만 찾는다 → `SELECT * FROM upsert`의 `upsert`는 잡고, `UPDATE emp02_others`·`INSERT INTO emp02_others`·`DELETE FROM`(이건 FROM이라 잡힘)의 대상은 못 잡는다.
- CTE 이름(`WITH name AS (`, `, name AS (`)을 빼지 않는다.
- 출력 별칭(`select_output_names`)을 statement 종류와 관계없이 낸다.

**수정**
1. statement 태그 종류를 쓴다(`<select>`/`<insert>`/`<update>`/`<delete>`). 태그 종류는 이미 statement 객체에 있을 것이다(없으면 XML 태그명에서).
2. 테이블 후보 정규식에 추가: `\bUPDATE\s+([a-zA-Z0-9_]+)`, `\bINSERT\s+INTO\s+([a-zA-Z0-9_]+)`, `\bDELETE\s+FROM\s+([a-zA-Z0-9_]+)`.
3. CTE 이름 집합 = `\bWITH\s+(?:RECURSIVE\s+)?(\w+)\s+AS\s*\(` 와 `,\s*(\w+)\s+AS\s*\(`(WITH 절 안). 테이블 목록에서 CTE 이름을 뺀다. CTE가 있으면 줄을 하나 더 낸다: `- **CTE**: upsert`.
   - **select에도 적용한다.** 지금 `analysis sql emp00_trans_info.selectByText`의 테이블 줄은 `emp01_person, emp02_others, org00, emp00, emp04_add_title, emp08_license, org00`인데, `emp00`·`org00`은 include(`common.emp00_trans_info`·`common.org00_org_info`)가 만든 CTE 이름이다. 고친 뒤: `- **테이블**: emp01_person, emp02_others, emp04_add_title, emp08_license, …`(CTE 빠짐) + `- **CTE**: emp00, org00`.
   - 같은 이름이 두 번 나오는 것(`org00`이 두 번)도 고친다: 지금은 `set(re.findall(...))`이 (FROM 그룹, JOIN 그룹) **튜플**의 집합이라 `('org00','')`와 `('','org00')`가 따로 남는다. 이름으로 중복을 없애고 **처음 나온 순서**로 쓴다(지금의 정렬 순서는 의미가 없다).
4. `<insert>`·`<update>`·`<delete>`이면 `출력 별칭` 줄을 내지 않는다. 대신 `- **변경 대상**: UPDATE emp02_others, INSERT emp02_others`(본문에 나온 순서, 중복 제거).
5. `<select>`가 아닌 statement의 md 마지막에 한 줄 안내를 붙인다: `- 본문: yunhee analysis sql emp02_others.upsert -o code`.
6. `<select>`는 3번(CTE·중복) 말고는 출력을 바꾸지 않는다.

**기대 (검증 ID `A-2 sql DML 테이블` / `A-2 sql select 회귀`)**
```
$ yunhee analysis sql emp02_others.upsert
### `emp02_others.upsert` (server/emp/mapper/emp02_others.xml:66)
- **파라미터**: birthday, chnName, …
- **테이블**: emp02_others
- **CTE**: upsert
- **함수**: f_create_seq, to_encrypts
- **변경 대상**: UPDATE emp02_others, INSERT emp02_others
- 본문: yunhee analysis sql emp02_others.upsert -o code
```
- `테이블: emp02_others`가 있고, `테이블:` 줄에 `upsert`가 **없고**, `출력 별칭`이 **없어야** 한다.
- select: `yunhee analysis sql emp00_trans_info.selectByText`의 `테이블:` 줄에 `emp01_person`·`emp04_add_title`이 있고 `org00`·`emp00`이 **없으며**, `CTE:` 줄에 `emp00`·`org00`이 있고, `ORDER BY` 줄은 그대로, `변경 대상` 줄은 없다. (이 SQL은 지금도 `출력 별칭` 줄이 없다 — 바뀌지 않아도 된다.)

3. (선택, 하면 좋음) 클라이언트 `analysis method` 요약에서 `서비스 X` 항목 다음에 `callback: result.getResult(…)`가 있고, 서버 X가 1번 경고 대상이면 그 줄 뒤에 ` ⚠ 서버가 결과를 넣지 않음`을 붙인다.

### A-6. 새 절 `analysis screen --section layout` — 폼 레이아웃(줄·칸 폭·라벨·읽기 전용)

**현상**
폼 탭(그리드 없는 화면)은 TOBE에서 원본 배치를 그대로 따라야 하는데(AssetERP_1 원칙 12), 어떤 analysis 출력에도 "몇 번째 줄에 어떤 라벨의 칸이 몇 px"인지가 없다. 지금 색인의 `입력·하위 화면` 줄은 필드 이름과 위젯 종류만 있다. 그래서 이 세션에서 원본 L40-359(약 320줄)를 통째로 읽었다 — **이 세션에서 토큰을 가장 많이 쓴 곳**이다. C01-3~C01-6(급여계좌·겸직 등)도 폼이 많아 효과가 크다.

**만들 것**

**파싱 규칙** (클래스 파일 하나 안에서)
1. **레이아웃 데이터 변수**: `HorizontalLayoutData\s+(\w+)\s*=\s*new\s+HorizontalLayoutData\s*\(\s*([-\d.]+)\s*,\s*([-\d.]+)` → 변수 → (폭, 높이). `VerticalLayoutData`도 같은 방식.
2. **컨테이너**: `(HorizontalLayoutContainer|VerticalLayoutContainer)\s+(\w+)\s*=\s*new` → 컨테이너 변수와 종류.
3. **add 호출**: `(\w+)\.add\s*\(` 를 찾고 `split_args`(기존 `analysis/common.py`)로 인자 2개를 나눈다.
   - 첫 인자가 `new FieldLabel(<필드>, <라벨식>)`이면 → 칸 = `라벨{필드}`. 라벨식에서 첫 문자열 리터럴(`setHtmlStyle("한자명")` → `한자명`)을 쓴다.
   - 첫 인자가 변수 하나이고 그 변수가 컨테이너면 → 하위 컨테이너(재귀로 펼침).
   - 그 밖의 변수 하나(`image`, `anchorHire`, `blankLabel1`)면 → 칸 = `{변수}`.
   - 둘째 인자가 1번의 변수면 그 (폭, 높이), `new HorizontalLayoutData(270, -1, …)`처럼 인라인이면 그 자리에서 숫자를 읽는다. 둘째 인자가 없으면 크기 없음.
   - 크기 표기: 폭만 있으면 `350`, 높이가 -1이 아니면 `550×150`. 폭이 -1이면 `auto`. 숫자는 원문 그대로(`1`은 `1`).
   - `new Margins(20)` → `m20`, `new Margins(0, 50, 0, 0)` → `m0,50,0,0`. **여백은 컨테이너 줄(hlc·layout)에만** 쓰고 줄 안의 칸에는 쓰지 않는다.
4. **최상위 찾기**: `form.setWidget(X)`·`cp.add(X)`·`this.add(X)` 중 X가 2번의 레이아웃 컨테이너면 X를 루트로(Others: `form.setWidget(hlc)` L296). X가 `ContentPanel` 등 레이아웃 컨테이너가 아니면(Person: `cp.add(hlc)`) **다른 레이아웃 컨테이너의 add 인자로 쓰이지 않은 레이아웃 컨테이너**를 루트로 한다(Person: `hlc`). 그런 것이 여럿이면 각각 따로 출력한다.
5. **라벨 폭**: `\.setLabelWidth\(\s*(\d+)\s*\)` → `라벨 폭: 100 (L297)`.
6. **읽기 전용·비활성**: 클래스 전체에서 `(\w+)\.setReadOnly\(true\)` → readOnly, `(\w+)\.disable\(\)` / `\.setEnabled\(false\)` → disable. 처음 나온 순서로 `변수(readOnly, disable)`.

| `docker logs t3600-tomcat` | 콘솔 패턴이라 ANSI 색 코드(`\x1b[...m`)가 있고 모든 앱이 섞인다. **쓰지 않는다**(파일을 읽는다) |

**줄 형식** (파일 패턴 `%d{yyyy-MM-dd HH:mm:ss.SSS} [traceId] [tenant] [userId] [clientIp] [%thread] %-5level %logger{36} - %msg%n`):
```
2026-10-08 06:33:44.317 [95694936e2a3b376] [admin] [kfstest:admin] [172.18.0.1] [http-nio-8080-exec-236] INFO  kr.co.kfs.asseterp.access - PUT /AssetERP_1/api/v1/emp/others 200 117ms
```

정규식:
```python

    r"^(\d{4}-\d\d-\d\d \d\d:\d\d:\d\d\.\d{3}) \[([^\]]*)\] \[([^\]]*)\] \[([^\]]*)\] \[([^\]]*)\] \[([^\]]+)\] (TRACE|DEBUG|INFO|WARN|ERROR)\s+(\S+) - (.*)$"

```
- MDC가 없으면 `[SYSTEM] [-] [-] [-]`. trace가 `SYSTEM`인 줄은 요청에 속하지 않는다.
- **여러 줄 메시지**: 정규식에 안 맞는 줄(스택 트레이스 `\tat …`, `Caused by: …`)은 바로 앞 줄의 계속이다.
- 감사 로그 패턴은 `%d ${MDC} %msg` (level·logger 없음): `2026-10-08 10:07:27.942 [SYSTEM] [-] [-] [-] event=LOGOUT result=SUCCESS user=user1 target=- detail=""`.
- 접근 로그 줄: logger `kr.co.kfs.asseterp.access`, msg `^(\w+) (\S+) (\d{3}) (\d+)ms$`.
- MyBatis 줄 (logger는 `%logger{36}`로 줄여져 `k.c.k.a.b.e.m.E.selectOthers`처럼 매퍼 클래스 이름이 첫 글자만 남는다):
  - `==>  Preparing: <SQL 한 줄>`
  - `==> Parameters: 202211220747066(Long), TEST(String), null, 1997-07-29(LocalDate), …`
  - `<==      Total: 1` (select) / `<==    Updates: 0` (insert·update·delete)
  - logger 마지막 마디 = statement id(`selectOthers`).

실제 한 요청(같은 값 PUT, 13줄)의 앞부분(긴 줄은 잘라 표시):

### B-2. 설정

우선순위: 명령 옵션 > `.yunhee.toml`의 `[log]` > `.env.local`(yunhee-cli 설치 폴더, 지금 `api` 설정과 같은 파일) > 기본값.

| 키 (`[log]` / 환경변수) | 기본값 | 뜻 |
|:---|:---|:---|
| `docker` / `YUNHEE_LOG_DOCKER` | `t3600-tomcat` | 값이 있으면 `docker exec <이름> …`으로 읽는다. 빈 문자열이면 로컬 파일 |
| `dir` / `YUNHEE_LOG_DIR` | `/home/kdy987/tmp/asseterp-data/logs` | 로그 폴더(컨테이너 안 경로 또는 로컬 경로) |
| `app` / `YUNHEE_LOG_APP` | `AssetERP-backend` | 파일 접두어 |
| `tz` / `YUNHEE_LOG_TZ` | docker면 `UTC`, 로컬이면 시스템 시간대 | 로그 시각의 시간대 |
| `context` / `YUNHEE_LOG_CONTEXT` | `/AssetERP_1` | 접근 로그 경로 앞의 컨텍스트(요청 경로 비교 때 떼어 냄) |

- 옵션: `--source docker|local`, `--dir`, `--app`, `--file <경로>`(파일 하나를 직접 — 시험용, B-6). `--file`이면 docker·dir·app을 무시한다.
- 모든 출력의 첫 줄(머리): `[log · docker:t3600-tomcat · /home/kdy987/tmp/asseterp-data/logs · AssetERP-backend · UTC]` 또는 `[log · file:<경로>]`. (호스트 파일을 잘못 보는 사고를 막는 것이 목적이다.)

**읽는 방법(성능)**: info 로그가 하루 수 MB다. 매번 통째로 가져오지 않는다.
- trace: `docker exec C grep -F -h '[<id>]' <info> <error>` (컨테이너 안에서 grep, 결과만 받는다).
- 최근 N분: `docker exec C tail -n 20000 <파일>`을 받아 파이썬에서 시각으로 거른다. 모자라면(첫 줄 시각 > 기준) `-n`을 두 배로 늘려 한 번 더(최대 200000).
- `--archived`일 때만 `zgrep -F`로 `archived/yyyy-MM/*.gz`까지.
- `docker exec` 실패(컨테이너 없음·권한)면 명확한 오류 한 줄 + Exit 2. 로컬로 자동 전환하지 않는다(함정 1).

### B-3. 하위 명령

모듈: `src/yunhee/tools/log_reader.py`(파서·소스), `cli.py`에 `log` 그룹. 출력은 모두 markdown 비슷한 텍스트, 마지막에 `원문: yunhee log trace <id> --raw` 같은 안내 한 줄.

#### (0) 공통 시간 범위 옵션 — `trace`를 뺀 모든 하위 명령(`req`·`errors`·`tail`)

"이 시각 이후 것만" 보는 것이 가장 자주 쓰는 경우다(배포 직후, 화면 확인 스크립트를 돌린 뒤, 사용자가 "방금 3시 10분쯤 안 됐다"고 할 때). 아래 옵션을 공통으로 둔다. 하나도 없으면 각 명령의 기본값(`req` 24h, `errors` 1h, `tail` 10m).

| 옵션 | 뜻 | 예 |
|:---|:---|:---|
| `--since <기간>` | 지금부터 거슬러 올라간 기간. 단위 `s`·`m`·`h`·`d` | `--since 30m` |
| `--from <시각>` | 이 시각 **이상** | `--from 15:10`, `--from "2026-10-08 15:10"`, `--from 2026-10-08T06:10:00Z` |
| `--to <시각>` | 이 시각 **미만** | `--to 15:20` |
| `--since-deploy` | 마지막 배포(앱 시작) 이후. 로그에서 마지막 `Started \w+ in [\d.]+ seconds` 줄(logger가 `…AssetErpApplication`)의 시각 | 배포 직후 오류 확인 |
| `--since-run [<run id>\|last]` | `yunhee run`으로 돌린 명령의 **시작 시각** 이후(`.yunhee/runs` 기록을 쓴다). 인자가 없으면 `last` | `yunhee run "./deploy.sh"` 뒤 `yunhee log errors --since-run` |

규칙:
1. **입력 시각의 시간대는 사용자(호스트) 시간대**(지금 KST)로 읽는다. 끝에 `Z`·`UTC`·`+09:00` 같은 표시가 있으면 그것을 따른다. 그 뒤 로그 시간대(설정 `tz`, docker면 UTC)로 바꿔 비교한다. 예: `--from 15:10`(KST) → 로그에서는 `06:10:00` 이상.
2. 날짜 없이 `HH:MM[:SS]`만 주면 **오늘**(호스트 날짜). 그 시각이 지금보다 뒤면 어제로 본다.
3. `--since`·`--from`·`--since-deploy`·`--since-run`은 시작점이라 **함께 쓰면 오류**(Exit 2, "시작 시각 옵션은 하나만"). `--to`는 어느 것과도 같이 쓸 수 있다.
4. `--since-deploy`인데 오늘 파일에 시작 줄이 없으면 "오늘 로그에 배포(앱 시작) 기록 없음 — --archived 또는 --from"과 Exit 1. 여러 번 배포했으면 **마지막** 것. 머리 줄에 `· 배포 06:33:29 UTC (15:33:29 KST)`를 붙인다.
5. `--since-run`인데 runs 기록이 없으면 Exit 1. 머리 줄에 `· run 20261008_063253_04047c (./deploy.sh) 시작 15:32:53 KST 이후`를 붙인다. (runs 기록의 시작 시각은 호스트 시간대다 — 규칙 1처럼 바꾼다.)
6. 여러 줄 레코드(스택)는 **첫 줄의 시각**으로 판단한다.
7. 머리 줄에 실제 범위를 쓴다: `· 범위 2026-10-08 06:10:00 ~ 06:20:00 UTC (15:10 ~ 15:20 KST)`.
8. 읽기 방법(B-2): 시작 시각이 정해지면 `tail -n`을 늘려 가며 **받은 첫 줄의 시각 ≤ 시작 시각**이 될 때까지 받는다(최대 200000줄). 시작 시각이 오늘 파일 첫 줄보다 앞이면 "오늘 파일은 06:00부터 — 그 전은 --archived"를 한 줄 알리고 오늘 것만 본다(`--archived`면 그날 gz까지 `zcat`).
9. `--file`과 함께 쓸 때는 `--tz`(기본 시스템 시간대)로 파일 시각의 시간대를 준다.

#### (1) `yunhee log trace <traceId> [--sql] [--raw] [--no-mask]`
그 trace의 모든 줄(info + error)을 시각 순으로 모아 요약한다.
```
[log · docker:t3600-tomcat · /home/kdy987/tmp/asseterp-data/logs · AssetERP-backend · UTC]
요청: PUT /api/v1/emp/others → 200 (117ms) · kfstest:admin · 172.18.0.1 · 06:33:44 UTC (15:33:44 KST) · trace 95694936e2a3b376
SQL 5:
  1. CompanyMapper.findByCompanyCode (admin) → Total 1
  2. EmpOthersMapper.selectOthers (202211220747066, 28000) → Total 1
  3. EmpOthersMapper.upsertOthers (202211220747066, TEST, ******-*******, 1997-07-29, … 20개) → Updates 0
  4. EmpOthersMapper.selectOthers (202211220747066, 28000) → Total 1
WARN/ERROR: 없음
원문: yunhee log trace 95694936e2a3b376 --raw
```
- 요청 줄은 접근 로그 줄(`kr.co.kfs.asseterp.access`)에서. 없으면 `요청: (접근 로그 없음 — 진행 중이거나 제외 경로)`.
- **매퍼 이름 되살리기**: logger `k.c.k.a.b.e.m.E.selectOthers`의 마지막 마디가 statement id, 그 앞 마디(`E`)는 매퍼 단순 이름의 첫 글자다. 현재 폴더 아래 `**/src/main/resources/mapper/*.xml`에서 `id="selectOthers"`를 가진 매퍼 중 namespace 단순 이름이 그 글자로 시작하는 것을 고른다. 하나면 `EmpOthersMapper.selectOthers`, 여럿이거나 없으면 logger 원문(`k.c.k.a.b.e.m.E.selectOthers`). 매퍼 XML 목록은 한 번 읽어 캐시.
- 파라미터: 값이 6개 이하면 다 보이고, 넘으면 앞 4개 + `… N개`. 각 값은 `(Type)`를 뗀다. 60자 넘는 값은 57자 + `…`.
- 같은 statement가 연속으로 같은 파라미터면 한 줄로 합치고 `×2`.
- `--sql`: 각 SQL 아래에 `?`를 파라미터로 바꾼 실행 가능한 SQL을 붙인다(문자열·날짜는 작은따옴표, `null`은 NULL, 숫자는 그대로). 이것을 파일로 저장하면 `yunhee sql -f`로 다시 돌릴 수 있어야 한다(SELECT만 — DML은 `--sql`이어도 주석으로 막아 `-- (DML: 실행하지 마세요)`를 앞에 붙인다). `--sql`이어도 마스킹은 유지(마스킹한 SQL은 실행용이 아님을 한 줄로 경고).
- `--raw`: 원문 줄 그대로(마스킹은 유지, `--no-mask`일 때만 원문).
- ERROR/WARN 줄이 있으면 `WARN/ERROR 2:` 아래에 `시각 레벨 logger - 메시지 첫 줄` + 예외면 `Caused by` 마지막 것 한 줄.
- trace를 못 찾으면 `trace <id>: 로그에 없음 (오늘 파일만 봄 — 지난 날은 --archived)` + Exit 1.

#### (5) `yunhee api … --log` 와 trace 표시 (`src/yunhee/tools/api_client.py`)
- **항상**: 응답 헤더에 `X-Trace-Id`(헤더 이름은 설정 `[log] trace_header`, 기본 `X-Trace-Id`)가 있으면 `yunhee api` 첫 줄 태그에 붙인다: `[AssetERP_1 · tenant=admin · company=kfstest · trace=95694936e2a3b376]`. `compare`도 같은 방식으로 API 쪽 trace를 표시.
- `--log`: 호출이 끝나면 0.5초 기다린 뒤(로그 비동기 기록 — `asseterp.log.async.max-flush-time=5000`이므로 못 찾으면 1초 간격으로 최대 5번 다시) `log trace <id>`의 요약(머리 줄 제외)을 응답 요약 아래에 붙인다.
- 로그인 요청의 trace는 붙이지 않는다(호출한 API 것만).

### B-4. 마스킹 (기본 켬)

파라미터 값과 `--raw` 줄에서:
| 대상 | 정규식 | 바꾼 값 |
|:---|:---|:---|
| 주민·외국인등록번호 | `\b\d{6}-?[1-8]\d{6}\b` | `******-*******` |
| 비밀번호처럼 보이는 Preparing 컬럼에 대응하는 값 | Preparing에서 `?` 순서와 컬럼 이름을 맞출 수 있으면 컬럼 이름에 `password`/`passwd`/`pwd` | `****` |
| JWT | `eyJ[\w-]+\.[\w-]+\.[\w-]+` | `eyJ…(JWT)` |
- `--no-mask`일 때만 원문. 마스킹한 경우 머리 줄 끝에 `· 마스킹 3`처럼 개수.

### B-5. 하지 말 것

- 로그 파일을 지우거나 비우거나 회전시키지 않는다. `docker exec`에는 `cat`/`tail`/`grep`/`zgrep`/`ls`만 쓴다.
- 호스트 파일로 조용히 대체하지 않는다(B-1 함정 1).
- 요약 문장을 LLM으로 만들지 않는다(`errors --explain`만 예외).

### B-6. 시험 (pytest + 검증 스크립트)

**pytest** `tests/test_log_reader.py` — 픽스처 `tests/fixtures/log/AssetERP-backend-info.log`, `…-error.log`를 만든다. 내용은 B-1의 실제 13줄을 바탕으로 하되 **주민번호는 가짜 `900101-1234567`**로 바꾼다. 시험:
1. 줄 파서: 13줄 → 레코드 13, 여러 줄 스택(픽스처 error에 `\tat …` 3줄 + `Caused by:` 1줄)이 앞 레코드에 붙는다.
2. trace 요약: 요청 줄·SQL 개수·`Updates 0`이 경고 아님.
3. 매퍼 이름 되살리기: 가짜 mapper 폴더(`tests/fixtures/log/mapper/EmpOthersMapper.xml`에 namespace `x.EmpOthersMapper`, `id="selectOthers"`) → `EmpOthersMapper.selectOthers`.
4. 마스킹: `900101-1234567`이 출력에 없고 `******-*******`가 있다. `--no-mask`면 반대.
5. errors 묶기: 같은 메시지(숫자만 다름) 3줄 → `×3`.
6. 시간대: UTC 06:33:44 → `15:33:44 KST`.
7. 시간 범위(B-3(0)): KST 입력 `15:11` → UTC `06:11:00` 비교, `HH:MM`만 주면 오늘·미래면 어제, 시작 옵션 둘이면 오류, 스택 줄은 첫 줄 시각으로, `--since-deploy`는 마지막 `Started … in` 줄.
