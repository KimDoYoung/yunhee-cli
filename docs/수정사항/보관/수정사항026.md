# 수정사항 026 — 연결 컴포넌트가 화면 분석에서 빠짐, `api --log` 파라미터에 이름이 없음 (대상 0.2.9)

- 작성: 2026-10-13, yunhee **0.2.9** 기준. 반영하면 **0.3.1**.
- AssetERP_1 A13(시스템 공통코드 관리)·A14(고객사 공통코드)에서 두 번 반복해 찾았다. 1은 결함(화면 범위·UI 대조가 모자라게 나옴), 2는 빠진 기능이다.

## 1. 연결 컴포넌트(`components/`)가 `analysis screen`·`ui`에서 빠짐

**재현**
```
cd AssetERP_1
yunhee analysis screen Sys08_Tab_CodeKindClient --list
→ 클래스 3개: Sys08_Tab_CodeKindClient / Sys09_Grid_Code / Sys01_Lookup_SelectSingle
   (copyChk()가 여는 Sys01_Lookup_SelectMulti가 없음)
yunhee analysis screen Sys01_Lookup_SelectMulti --list
→ [ERROR] 색인 화면 파일을 찾을 수 없습니다: Sys01_Lookup_SelectMulti.md
yunhee analysis ui Sys08_Tab_CodeKindClient --tobe frontend/src/pages/sys
→ 3개 클래스만 대조 (SelectMulti 버튼 3·이벤트 5·그리드 1이 빠짐)
```
- A13도 같다: `Sys08_Tab_CodeKindAdmin`의 `Sys09_Lookup_CodeKind`(코드목록 조회창)가 `--list`·`ui`에 없고 `analysis screen`으로 못 연다.
- 그래서 두 번 모두 버튼 문구·레이아웃을 AS-IS 소스 Read(offset/limit)로 보충했고, 결과확인 UI 대조표(06 항목 10)에 그 클래스를 손으로 더했다. `--list`는 "이번에 할 클래스"를 정하는 첫 명령이라, 빠지면 화면 범위 자체를 놓칠 수 있다.

**원인**
- 색인에는 있다. `index-src`가 이 클래스들을 화면 파일 안의 `### 클래스` 절이 아니라 **연결 컴포넌트**로 분리해 `docs/as-is/src/sys/components/Sys01_Lookup_SelectMulti.md`, `…/components/Sys09_Lookup_CodeKind.md`에 따로 쓰고(AssetERP_1 색인에 components 파일 150개), 화면 파일에는 링크 한 줄만 둔다:
  `- 연결 화면·컴포넌트 (각 파일 참고): [`Sys01_Lookup_SelectMulti`](../../sys/components/Sys01_Lookup_SelectMulti.md)`
  (메서드 표에도 `copyChk() … 조회창 Sys01_Lookup_SelectMulti 열기`로 나온다)
- `tools/analysis/screen.py` L27·L30과 `tools/analysis/ui.py` L73·L75가 `**/screens/{이름}.md`만 glob한다 → components 파일은 직접 열 수도 없다.
- `screen.py` L42-51은 화면 파일의 `### 클래스` 절만 클래스로 센다 → 링크로만 있는 연결 컴포넌트는 `class_stats`에 들어가지 않는다.
- 분리 기준은 짐작: 필드로 선언된 조회창(`Sys01_Lookup_SelectSingle lookup = …` 필드)은 `###` 절로 들어오고, 메서드 안 지역 변수로 만드는 조회창(`copyChk()` 안 `new Sys01_Lookup_SelectMulti()`)은 연결 컴포넌트가 되는 것으로 보인다. 원본 화면에서는 둘 다 그 화면이 여는 팝업이라 같은 범위다.

**수정**
1. `screen.py`·`ui.py`의 파일 찾기를 `screens/` 다음에 `components/`도 찾게 한다(`**/screens/{n}.md` → 없으면 `**/components/{n}.md`). `analysis screen Sys01_Lookup_SelectMulti --list|--section …`이 열려야 한다.
2. `--list`: 화면 파일의 "연결 화면·컴포넌트" 링크(그리고 메서드 표의 `조회창 X 열기`)에서 이름을 모아, components 파일의 통계(줄·버튼·이벤트·그리드)를 같은 표에 **구분 표시해서** 더한다. 예:
   ```
   | Sys01_Lookup_SelectMulti (연결) | 41 | 3 | 5 | 1 |
   ```
   합계에 넣을지는 옵션으로: 기본은 합계에 포함(원본 화면이 여는 팝업이므로 06 항목 10 대상), `--no-linked`면 지금처럼 뺀다.
3. 링크 대상이 다른 도메인(예: 전자결재 `Apr01_Edit_ApprDoc`)이면 05 §2 규칙상 범위 밖("의존")이므로 `--list`에 `(연결·다른 도메인)`으로만 보이고 합계에서 뺀다.
4. `--section …`·`--class <연결 컴포넌트>`도 components 파일 내용으로 동작하게 한다.
5. `analysis ui … --tobe`: 2번과 같은 기준으로 연결 컴포넌트를 대조표에 행으로 넣는다(TOBE 쪽은 같은 이름 `.tsx`를 찾는다).
6. `agent-guide`·`analysis --list`의 screen/ui 설명에 "연결 컴포넌트 포함(`(연결)` 표시)"를 적는다.

**기대 (검증 ID `026-1`)**
```
yunhee analysis screen Sys08_Tab_CodeKindClient --list
→ 4행: … + `Sys01_Lookup_SelectMulti (연결)` 버튼 3·이벤트 5·그리드 1
yunhee analysis screen Sys01_Lookup_SelectMulti --class Sys01_Lookup_SelectMulti --section buttons
→ 조회 / 확인 / 취소
yunhee analysis screen Sys08_Tab_CodeKindAdmin --list
→ … + `Sys09_Lookup_CodeKind (연결)`
yunhee analysis ui Sys08_Tab_CodeKindClient --tobe frontend/src/pages/sys
→ Sys01_Lookup_SelectMulti 3/3, 5/5, 1/1 행이 있음
```
- pytest: 링크가 없는 화면은 지금과 같은 출력, 다른 도메인 링크는 합계 제외, `--no-linked`.

## 2. `api --log`·`log trace`의 SQL 파라미터에 이름이 없음

**재현**
```
yunhee api POST /api/v1/sys/code-kinds/202407241733135/codes/copy -b '{"companyId":0,"companyIds":[28000]}' --log
→ 2. SysCodeMapper.copyCodes (28000, 0, 202407241733135) → Updates 0
```
- 매퍼는 `copyCodes(sourceCompanyId=0, newCompanyId=28000, codeKindId)`이다. 출력은 SQL 안 `?` 순서(SELECT 목록의 `#{newCompanyId}`가 WHERE의 `#{sourceCompanyId}`보다 앞)라서 `(28000, 0, …)`이 되어 **원본 회사와 대상 회사가 바뀐 것처럼 보인다.** 결과가 맞는지 판단하려면 매퍼 XML을 다시 열거나 `log trace --sql`로 바인딩된 SQL을 봐야 했다.
- 같은 타입 값이 여럿인 저장 SQL(회사 ID 두 개, 날짜 두 개 등)에서 자주 생긴다.

**원인**
- `tools/log_reader.py` L845-847이 MyBatis `==> Parameters:` 줄의 값만 저장하고, L855-867 `parse_params`가 값을 쉼표로 이어 붙인다. MyBatis 로그에는 이름이 없으므로 이름을 붙이려면 매퍼 XML이 필요하다.
- statement는 이미 `recover_mapper_name(g["logger"])`(L872)로 `SysCodeMapper.copyCodes`까지 알고 있다.

**수정**
1. 로거 이름(`…mapper.SysCodeMapper.copyCodes`)으로 TOBE 매퍼 XML(`sql-check --tobe`가 쓰는 위치, 기본 `backend/src/main/resources/mapper`)에서 그 statement를 찾아, 본문의 `#{…}`를 **나온 순서대로** 뽑는다(`<include>`·`<foreach>`·`<if>`가 있으면 펼칠 수 있을 때만. 개수가 `Parameters:` 값 수와 다르면 이름을 붙이지 않고 지금처럼).
2. 개수가 맞으면 `이름=값`으로 낸다: `SysCodeMapper.copyCodes (newCompanyId=28000, sourceCompanyId=0, codeKindId=202407241733135) → Updates 0`. 중복 이름(`#{companyId}` 두 번)은 그대로 두 번.
3. 매퍼를 못 찾거나(프로젝트 밖·다른 base) 개수가 안 맞으면 지금 출력 그대로(조용히 대체).
4. 6개 넘으면 줄이는 규칙(L865-867)은 이름이 붙은 뒤에도 같게.
5. `log trace`·`log req --trace`·`api --log`가 같은 함수를 쓰므로 함께 바뀐다.

**기대 (검증 ID `026-2`)**
```
yunhee api POST /api/v1/sys/code-kinds/202407241733135/codes/copy -b '{"companyId":0,"companyIds":[28000]}' --log
→ SysCodeMapper.copyCodes (newCompanyId=28000, sourceCompanyId=0, codeKindId=202407241733135) → Updates 0
yunhee api GET /api/v1/sys/code-kinds -p sysYn=false --log
→ SysCodeKindMapper.searchCodeKinds (kindName=%, sysYn=false) → Total 39   (이름은 매퍼 #{…} 그대로)
```
- 데이터를 바꾸지 않는 호출이다(첫 번째는 원본 회사 0에 그 코드구분 코드가 0건 → Updates 0).
- pytest: `<foreach>`로 개수가 달라지는 statement는 이름 없이 그대로, 매퍼 XML이 없을 때 그대로.
