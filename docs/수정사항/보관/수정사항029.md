# 수정사항 029 — `sql-check --old`: 주석이 다른 statement에 붙음, `test` 식까지 소문자로 비교·표시, diff 줄이 너무 김 (대상 0.3.3)

- 작성: 2026-10-15, yunhee **0.3.3** 기준. 반영하면 **0.3.4**.
- 수정사항028 반영본(0.3.3)을 028 검증 항목대로 시험하다 찾았다(AssetERP_1). 028 항목은 모두 통과했고 pytest 153/153, 027 항목 회귀 없음.
- 1·2는 결함, 3은 출력 개선이다. 우선순위: **2 > 1 > 3** (2는 비교 결과 자체가 틀릴 수 있다).
- 새 top-level 명령은 만들지 않는다. 모두 `tools/as_is/sql_drift.py` 안에서 고친다.

## 1. statement 앞 주석을 찾는 범위가 앞 statement 본문과 `<sql>` 조각까지 포함함

**재현**
```
cd AssetERP_1
yunhee sql-check --old ~/oms-data/src/Asset-ERP --tobe backend/src/main/resources/mapper --only-tobe
→ - `SysCompanyMapper.searchCompanies` ← sys01_company.SELECT (미존재) · sys01_company.selectByName (바뀜)
```
- `SysCompanyMapper.xml`의 순서:
  - L12 `<!-- 그리드 컬럼만. 이름 컬럼은 AS-IS SELECT의 f_cdnm 식 그대로, … -->` — **`<sql id="companyColumns">`(L13)의 설명**
  - L48 `<!-- AS-IS selectByName: … -->`
  - L49 `<select id="searchCompanies">`
- L12 주석은 `<sql>` 조각 설명인데 `searchCompanies`의 출처로 읽혔고, 설명 문장 속 `SELECT`가 statement ID가 됐다.

**원인**
- `extract_tobe_as_is_refs` L119: statement 경계를 `<(select|insert|update|delete)` 로만 나눈다 → `<sql id=…>`는 경계가 아니라서 그 앞 주석이 다음 select에 붙는다.
- L126-127: `chunk_before = raw[앞 statement 여는 태그 끝 : 지금 statement 시작]` — 앞 statement **본문 안의 주석**도 지금 statement 것으로 읽힌다. statement 단위 반영 표시(L134-136)도 같은 범위를 보므로, 앞 statement 본문 안에 `(IDMS-IC)`가 있으면 다음 statement가 반영된 것으로 잘못 나온다.
- L149: `AS-IS` 뒤 첫 단어를 무조건 ID로 받는다(`SELECT의` → `SELECT`). 제외 목록이 `server/common/xml/mapper`뿐이다.

**수정**
1. statement 앞 주석 범위 = **바로 앞 요소(`</select>`·`</insert>`·`</update>`·`</delete>`·`</sql>`·`<mapper …>`)의 끝 ~ 지금 statement 시작**. 사이에 있는 주석만 그 statement 것으로 본다. `<sql>`도 경계로 넣는다.
2. 주석에서 읽은 ID는 새·옛 원본의 그 namespace에 **있는 statement 이름일 때만** 출처로 쓴다. 없으면 `(미존재)`로 내지 말고 무시한다(설명 문장의 단어일 가능성이 크다). 원본 어디에도 없는 ID가 `이름 L숫자`·`이름(L숫자)` 꼴로 적혀 있을 때만 `(미존재)`.
3. `(IDMS-IC)` 반영 표시도 1의 범위 안에서만 찾는다. `<!--[\s\S]*?AS-IS[\s\S]*?\(IDMS-IC\)[\s\S]*?-->`(L135)는 `-->`를 넘어 다음 주석·SQL까지 이어 맞을 수 있으니, 주석 하나 안에서만 찾는다.

**기대 (검증 ID `029-1`)**
```
yunhee sql-check --old ~/oms-data/src/Asset-ERP --tobe backend/src/main/resources/mapper --only-tobe
→ 출력에 `(미존재)` 없음 (SysCompanyMapper.searchCompanies ← sys01_company.selectByName (바뀜) 만)
```
- pytest: ① `<sql>` 앞 주석이 다음 `<select>`에 붙지 않음 ② 앞 `<select>` 본문 안의 `<!-- AS-IS x (IDMS-IC) -->`가 다음 statement를 반영 표시로 만들지 않음 ③ 설명 주석 `AS-IS SELECT의 …` → 출처 없음(미존재 아님).

## 2. 정규화가 `test="…"` 같은 XML 속성(OGNL 식)까지 소문자로 바꿈 — 비교·표시 모두

**재현**
```
yunhee sql-check --old ~/oms-data/src/Asset-ERP --tobe backend/src/main/resources/mapper --only-tobe
→ - `EmpCareerMapper.selectCareers` ← emp07_career.selectByPersonId (바뀜)
    + <choose> <when test="extraddtitleyn == true"> and coalesce ( emp07_extr_add_title_yn , 'false' ) = 'true' </when> </choose>
```
- 원본은 `test="extrAddTitleYn == true"`다. 표시만이 아니라 **비교도** 이 소문자 문자열로 한다.

**원인**
- `normalize_sql_for_drift` L37-48: `'…'` 리터럴과 `#{…}`·`${…}` 밖을 모두 `.lower()` 한다. XML 태그 안의 속성 값(`test="…"`, `refid="…"`, `collection="…"`, `item="…"`, `property="…"` 등)도 밖으로 취급된다.
- OGNL·속성 값은 대소문자를 구분한다(`isSeparateAddTitle`과 `isseparateaddtitle`은 다른 파라미터). 그래서 원본에서 파라미터 이름의 대소문자만 바뀐 경우를 "같음"으로 놓친다. 또 `get_diff_summary`가 정규화한 문자열로 diff를 만들어서 화면에도 소문자로 나온다.

**수정**
1. 소문자로 바꾸지 않는 부분에 **XML 태그 전체**(`<…>` 안, 태그 이름·속성 이름·속성 값)를 더한다. 소문자로 바꾸는 것은 태그 밖의 SQL 본문 중 리터럴·파라미터를 뺀 부분만이다.
2. diff 표시는 정규화한 문자열이 아니라 **공백·주석만 정리한 원형**으로 만든다. 같음/바뀜 판정만 소문자로 바꾼 문자열로 하고, 화면에 보이는 토큰은 원문 대소문자로 낸다.

**기대 (검증 ID `029-2`)**
```
yunhee sql-check --old … --tobe backend/src/main/resources/mapper --only-tobe
→ EmpCareerMapper.selectCareers 아래 diff에 `test="extrAddTitleYn == true"` (원형), 키워드도 원문대로(`AND COALESCE (…)` 등)
yunhee sql-check --old ~/oms-data/src/Asset-ERP -o json
→ 바뀜 수 373과 같거나 조금 많음 (속성 대소문자만 바뀐 statement가 다시 "바뀜"으로 잡힘)
```
- pytest: ① SQL 키워드 대소문자만 다름 → 같음(028-4 그대로) ② `test="isA == true"` → `test="isa == true"` → 바뀜 ③ diff 출력 토큰이 원문 대소문자.

## 3. diff 요약 한 줄이 너무 김

**재현**
```
yunhee sql-check --old … --tobe backend/src/main/resources/mapper --only-tobe
→ SysCompanyMapper.selectCompanyMenuYn 아래 diff 줄이 1,681자 (f_cdnm 식 15개가 한 덩어리로 "-")
```

**원인**
- `get_diff_summary` L62-75: 변경 덩어리를 3개까지 자르지만 덩어리 하나의 길이는 제한하지 않는다.

**수정**
1. 덩어리 하나를 토큰 30개(또는 200자) 정도에서 자르고 `… (+N토큰)`을 붙인다. 줄 전체도 400자 안팎에서 자른다.
2. 덩어리가 3개를 넘으면 끝에 `· 외 N곳`을 붙인다(지금은 말없이 버린다).
3. 전체 원문은 지금처럼 `analysis sql <ns.id> -o sql`로 본다. `-o json`의 `diff`도 같은 요약을 쓰고, 자르지 않은 목록이 필요하면 `diff_full` 배열을 둔다.

**기대 (검증 ID `029-3`)**
```
yunhee sql-check --old … --tobe backend/src/main/resources/mapper --only-tobe
→ 들여쓴 diff 줄이 모두 400자 정도 이하, 잘린 줄에 `(+N토큰)` 또는 `외 N곳`
```
