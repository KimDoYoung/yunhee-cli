# 수정사항 033 — `yunhee sql` 출력 형식(tsv·csv·json)·파일 저장, `drift --record` 일괄 기록, `index-src` 요약 표기, 메뉴 TSV 생성 (대상 0.3.8)

- 작성: 2026-10-16, yunhee **0.3.8** 기준. 반영하면 **0.3.9**.
- 계기: 032(drift)를 AssetERP에 적용하면서(`menus.tsv` 재생성, 완료·확인 화면 40개 baseline 일괄 기록) 손으로 이어 붙인 곳이다. `drift`·`index-src`의 032 항목은 모두 잘 동작했고, 아래는 **손 작업이 남은 곳**이다.
- 우선순위: **1 > 2 > 3 > 4**.
- 새 top-level 명령은 만들지 않는다.

## 1. `yunhee sql`이 마크다운 표로만 출력됨 — 파일 저장·후처리용 형식이 없음

**재현** (`AssetERP/docs/as-is/menus.tsv` 만들기, `docs/as-is/src/README.md`의 "메뉴 TSV 만들기")
```
yunhee sql "WITH RECURSIVE t AS (…) SELECT … ORDER BY t.sort" -n 2000 --timeout 30 > menus.md
→ rows=506
  | a | b | c | d |
  | --- | --- | --- | --- |
  | 1001 | 문서분류 > … | Dcr01_Tab_ClassTree | true |
```
- README의 절차는 `psql -h localhost -U kdy987 … > menus.tsv`인데, `psql`은 이 환경에서 비밀번호를 기다리며 멈춘다(`PGPASSWORD`·`.pgpass` 없음, 터미널 없는 실행이라 입력 불가). `yunhee sql`은 접속 정보를 이미 알고 있어 접속은 된다.
- 그래서 `yunhee sql` 출력(마크다운)을 Python으로 ` | `에서 잘라 TSV로 바꿨다. 값에 `|`·줄바꿈이 있으면 깨지는 방식이다(이번엔 506행 전부 4칸이라 괜찮았다).
- 기본 행 수 제한이 5라서 `-n 2000`을 줘야 하고, 줄이 잘려도 파일에는 `(총 N행 중 M행만 표시)` 꼬리말이 섞일 수 있다.

**수정**
1. `-o/--output table|tsv|csv|json` 추가. 기본값은 지금과 같은 `table`(마크다운)이다 — 기존 사용법·훅·문서는 그대로 동작한다.
   - `tsv`: 헤더 한 줄 + 데이터. 값 안의 탭·줄바꿈·백슬래시는 `\t`·`\n`·`\\`로 이스케이프(PostgreSQL `COPY … TEXT`와 같은 규칙). NULL은 빈 칸(`--null <문자열>`로 바꿀 수 있다).
   - `csv`: RFC 4180(따옴표·`""` 이스케이프), UTF-8, BOM 없음.
   - `json`: 객체 배열(`[{"컬럼": 값, …}]`), 숫자·불리언은 JSON 타입 그대로, NULL은 `null`.
   - `--no-header`(tsv·csv).
2. `--out <파일>`: 결과를 파일에 쓰고, 화면에는 요약 한 줄만 낸다(`rows=506 → docs/as-is/menus.tsv`). 기존 파일은 덮어쓴다. 상위 폴더가 없으면 만든다. 읽기 전용 강제·`--timeout`·`--rollback` 규칙은 그대로.
3. 행 수 제한: `table`은 지금처럼 `--limit` 기본 5. `tsv`·`csv`·`json`일 때는 **기본값을 제한 없음**으로 한다(파일로 받는 용도). 사용자가 `-n`을 주면 따르고, 잘리면 stderr에 `⚠ 506행 중 3행만 출력` 한 줄을 낸다(데이터에는 섞지 않는다).
4. `--timeout` 기본(10초)은 그대로. 단 `tsv`·`csv`·`json`에서 타임아웃이 나면 **부분 파일을 남기지 않는다**(임시 파일에 쓰고 성공하면 이동).
5. 마크다운 표 값 처리 개선(참고): 값에 `|`가 있으면 `\|`로 이스케이프한다(지금은 표가 깨진다).

**기대 (검증 ID `033-1`)**
```
yunhee sql -f menus.sql -o tsv --out docs/as-is/menus.tsv --no-header
→ rows=506 → docs/as-is/menus.tsv
wc -l docs/as-is/menus.tsv                       # 506
cut -f3 docs/as-is/menus.tsv | head -2           # 클래스명
yunhee sql "select 'a|b' x, E'c\td' y" -o tsv    # x<TAB>y / a|b<TAB>c\td
yunhee sql "select 1 n, null v" -o json          # [{"n": 1, "v": null}]
yunhee sql "select 1" -o xml                     # Exit 2, 지원 형식 안내
```
- pytest: ① tsv 이스케이프(탭·줄바꿈·백슬래시)와 NULL ② csv 따옴표·쉼표·줄바꿈 ③ json 타입(int·bool·null) ④ `--out` 성공 시 요약 한 줄, 타임아웃이면 파일 없음 ⑤ `-n` 없을 때 tsv는 전체, table은 5행 ⑥ `|` 포함 값의 표 이스케이프 ⑦ `--rollback`과 `-o json` 함께 쓰기 ⑧ 지원하지 않는 형식은 Exit 2.

## 2. `drift --record`를 화면마다 한 번씩 돌려야 함 — 일괄 기록 옵션이 없음

**재현** (완료 26개 + 확인 14개를 기록할 때)
```
python3 …                                  # 01-변환목록.md의 표를 파싱해 ID·클래스 목록 만들기
for id cls …; do yunhee drift --record "$cls" --id "$id" --note-file "docs/work/$id-작업기록.md"; done
```
- 목록은 매번 `docs/01-변환목록.md`의 표(열 위치가 A표·C표마다 다르다)를 직접 파싱했다. 명령 40번을 따로 실행하고, 각 명령이 색인을 다시 읽는다.
- 앞으로도 ID를 `완료`로 바꿀 때마다 같은 명령을 쓰고, 다른 PC에서 기준이 빠졌는지 확인할 때도 같은 목록이 필요하다.

**수정**
1. `yunhee drift --record-from <마크다운 표 파일> [--status 완료,확인] [--id-col ID] [--class-col 클래스] [--status-col 상태] [--note-dir docs/work --note-suffix -작업기록.md]`:
   - 표에서 `ID`·`클래스`·`상태` 열을 **헤더 이름으로** 찾는다(열 위치가 표마다 달라도 된다). 클래스 칸의 백틱·링크는 벗긴다. 상태가 `--status` 목록에 있는 행만 대상.
   - 각 행에 `--record`와 같은 동작. 색인을 한 번만 읽는다.
   - 한 행이 실패해도(클래스가 색인에 없음 등) 나머지를 계속하고, 끝에 `기록 N개 · 건너뜀 M개(사유)`를 요약한다. 건너뛴 행은 ID·사유를 나열.
   - `--dry-run`: 쓰지 않고 대상 목록·건너뜀만 보여 준다.
2. `.yunhee.toml`에서 기본값 설정: `[drift] done_from = "docs/01-변환목록.md"`(032에서 이미 거론), `record_status = ["완료", "확인"]`, `note_dir = "docs/work"`, `note_suffix = "-작업기록.md"`. 설정이 있으면 `yunhee drift --record-all` 한 줄로 끝난다.
3. 이미 baseline이 있고 의존 파일 해시가 같으면 건너뛴다(`변경 없음`). 해시가 다르면 `--force` 없이는 덮어쓰지 않고 "기준 변경: 원본이 바뀜 — drift로 먼저 확인" 경고(실수로 변경분을 기준에 흡수하는 것을 막는다).

**기대 (검증 ID `033-2`)**
```
yunhee drift --record-from docs/01-변환목록.md --status 완료,확인 --dry-run
→ 대상 40개 · 건너뜀 2개 (A34: 상태 대기, A36: 상태 보류 — 상태 필터)
yunhee drift --record-from docs/01-변환목록.md --status 완료,확인
→ 기록 40개 · 작업기록 40개 갱신 · 건너뜀 0개
yunhee drift --record-from docs/01-변환목록.md --status 완료,확인     # 다시 실행
→ 변경 없음 40개
```
- pytest: ① 헤더 이름으로 열 찾기(A표·C표 열 순서 다름) ② 백틱·링크 제거 ③ 상태 필터 ④ 클래스가 색인에 없으면 건너뛰고 계속 ⑤ `--dry-run`은 파일·baseline을 쓰지 않는다 ⑥ 이미 같은 기준이면 변경 없음 ⑦ 해시가 달라졌으면 `--force` 없이 거부 ⑧ `AS-IS 기준:` 줄 중복 없음.

## 3. `index-src` 요약 줄의 "화면 N개"가 두 가지 의미로 쓰임

**재현**
```
yunhee index-src ~/work/IDMS-IC -t … --menus docs/as-is/menus.tsv
→ 소스 546a87d (ioc, 2026-10-16 17:13) clean · 화면 488개 · 의존 파일 3,279개 기록
→ 클라이언트 클래스: 2755개, 메뉴 화면: 488개, 프레임: 15개, 컴포넌트: 160개
yunhee drift --all
→ … / 화면 503개 (동일 503 …)
```
- 같은 색인인데 요약은 488, `drift`와 `_source.json`(`screens_count`)은 503이다. 488은 `menus.tsv`에 연결된 화면이고, 503 = 488 + 프레임 15이다. 처음 보면 숫자가 어긋난 것으로 읽힌다(이번 세션에서 실제로 헷갈렸다).

**수정**
1. `index-src` 첫 요약 줄을 `화면 503개(메뉴 488 + 프레임 15)`로 쓰고, `_source.json`에 `screens_menu`·`screens_frame`·`screens_count`를 분리해 둔다.
2. `drift`의 머리 줄도 `화면 503개(메뉴 488 · 프레임 15)`로 같은 규칙을 쓴다.
3. 메뉴 TSV를 안 줬을 때(메뉴 연결이 없을 때)는 `메뉴 화면: 연결 안 됨(--menus 없음)`으로 표시한다(이번에 `--menus` 없이 만든 색인은 503개 전체가 화면으로 셈되었다).

**기대 (검증 ID `033-3`)**: 요약 줄의 숫자가 `_source.json`·`drift`와 같은 값을 쓰고 구성(메뉴·프레임)이 괄호에 나온다.
- pytest: ① 세 곳이 같은 총계 ② `--menus` 없을 때 문구 ③ `_source.json` 필드.

## 4. 색인 `README.md`의 "메뉴 TSV 만들기" SQL을 명령으로 쓸 수 없음 (낮은 우선순위)

**현상**: `index-src`가 만드는 `README.md` 끝에 메뉴 TSV 만드는 `psql` 명령이 들어 있지만, 훅이 색인 파일을 통째로 `cat`/`grep`하는 것을 막고 있어 `Read(limit)`로 줄 범위를 찾아 읽어야 했다. 그리고 그 명령은 1번에서 본 대로 `psql` 비밀번호 때문에 이 환경에서 실행되지 않는다.

**수정**
1. 같은 SQL을 `yunhee sql`로 쓰는 형태로 README에 바꿔 적는다: `yunhee sql -f <(…)`가 아니라, SQL 파일을 `yunhee` 패키지 안에 두고 `yunhee sql --builtin menus -o tsv --out docs/as-is/menus.tsv --no-header`로 부른다(내장 SQL 이름 `menus`).
2. 또는 `index-src --menus-from-db <환경변수 이름>`: `--menus` 파일이 없으면 DB의 `sys06_menu`에서 바로 읽어 `{target}/../menus.tsv`를 만든다(출력 폴더 밖이라 지워지지 않는 기존 규칙 유지).
3. 둘 중 하나만 해도 된다. 2번이 한 단계 더 줄이지만, 1번이 `menus.tsv`를 따로 쓰는 다른 명령(`yunhee analysis` 등)에도 쓰이므로 호환이 좋다.

**기대 (검증 ID `033-4`)**: 새 PC(T3600)에서 `git pull` 직후 `psql` 없이 두 줄(`yunhee sql --builtin menus …` → `yunhee index-src …`)로 색인을 만들 수 있다.
- pytest: ① 내장 SQL이 `sys06_menu`가 있는 DB에서 4열 TSV를 낸다 ② 사용자 쿼리와 같은 읽기 전용 강제 ③ `--builtin` 이름이 없으면 목록 안내(Exit 2).
