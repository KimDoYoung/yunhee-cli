## 24. 구현함. `sql-check --tobe`가 파일 경로를 거부하고 `--only` 오류 문구가 원인을 가린다

**재현**
```bash
yunhee sql-check --tobe backend/src/main/resources/mapper/EmpYearLeaveMapper.xml
# [ERROR] TOBE 매퍼 디렉터리를 찾을 수 없습니다: …EmpYearLeaveMapper.xml
yunhee sql-check --tobe backend/src/main/resources/mapper --only EmpYearLeave
# [ERROR] backend/src/main/resources/mapper 아래에서 검증할 매퍼 SQL을 찾지 못했습니다.
yunhee sql-check --tobe backend/src/main/resources/mapper --summary   # 통과 (이름 전체 일치: --only EmpYearLeaveMapper 가 맞았을 것)
```

**실제 결과**: 새 매퍼 하나만 검사하려다 호출을 3번 했다. `--only`는 "매퍼 이름 또는 glob"인데 부분 문자열이면 아무것도 못 찾고, 오류 문구가 "디렉터리에 SQL이 없다"로 읽혀 원인(필터 불일치)을 알 수 없다.

**수정 제안**
1. `--tobe`에 XML 파일 경로를 주면 그 파일만 검사.
2. `--only` 결과가 0건이면 `--only 'EmpYearLeave' 와 일치하는 매퍼가 없습니다 (후보: EmpYearLeaveMapper, …)`로 후보를 보여 준다. 부분 문자열도 허용하면 더 좋다.

**합격 기준**: 파일 경로 하나로 `✅ n / ❌ m`이 나온다.

## 25. 구현함. `port-sql`은 UNION·큰 CTE·공용 조각이 낀 조회에서 쓸 수 없는 결과를 낸다 (17번 재확인)

**재현**
```bash
yunhee port-sql emp01_person.selectByYearList --cols empNo,korName,… --getter-defaults --package kr.co.kfs.asseterp.biz.emp.dto
```

**실제 결과**: `<sql id="personColumns">`에 이 화면과 무관한 `emp01_person` 공용 열(`password`·`mobile_telno` …)을 만들어 `SELECT <include refid="personColumns"/> FROM (…) a`로 바꾸고, `⚠ SQL 열 없음` 12개(그리드 열 대부분)와 전부 `String`인 DTO를 냈다. 결국 `analysis sql <id> -o sql` 덤프를 스크립트로 `:name → #{name}` 치환해 `<![CDATA[ ]]>` 안에 넣는 쪽이 정확하고 빨랐다(월차 목록 123줄 UNION 포함, `sql-check` 4/4·6/6 통과).

**수정 제안**
1. `port-sql --raw`(또는 `--verbatim`): 원본 SQL을 **한 글자도 바꾸지 않고** `:name → #{name}`(단 `::` 캐스트 제외 `(?<!:):(\w+)`)만 치환해 `<sql id>` + CDATA로 낸다. 컬럼 대응 시도·바깥 SELECT 변환은 하지 않는다.
2. 원본 첫 줄이 `SELECT *`이고 조인이 있으면 `*`가 조인 테이블 열을 중복으로 만든다는 경고를 낸다(서브쿼리로 감싸 쓸 때 모호 열 오류 방지).
3. `INSERT … SELECT` 변환 옵션(`--insert-into <table> --insert-cols a=expr,…`): 조회 SQL을 서버가 반복 INSERT하는 AS-IS 패턴(S07 sys99_print 출력, S08 [생성])이 흔하다.

**합격 기준**: 위 두 SQL이 `--raw`로 수정 없이 `sql-check`를 통과한다.
