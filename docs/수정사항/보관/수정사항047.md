- 계기: AssetERP **EE10·EE11**(결산회기관리, 거래유형 등록) 변환 세션(2026-11-03, yunhee **0.7.2**)에서 겪은 것. 대체 수단(`yunhee api DELETE`로 시험 행을 만들고 지움)으로 끝냈다.
- 재현 환경: `cd AssetERP`(저장소 `framework-sprt/AssetERP`), DB `asseterpdb`. 대상 코드: `backend/src/main/resources/mapper/ActAccountNumMapper.xml`(EE10에서 새로 만든 매퍼).

- 이번 세션에서 확인하고 **제외한 것**: `sql-check --tobe`가 느린 것(`--only`·`--changed`·`--summary`가 이미 있었다 — 쓰지 않은 내 잘못), `analysis ui --tobe`가 폴더 하나만 받는 것(`--tobe`를 반복하면 된다), `compare -c`에 회사 ID를 준 것(오류 힌트가 알려 줬다).

## 1. `mapper-run`이 `<foreach>`가 있는 문장에 목록 값을 줄 방법이 없다

**어떤 경우**
- 삭제 문장이 목록을 받는다:

```xml
<delete id="deleteAccountNums">
    DELETE FROM act09_account_num
     WHERE act09_company_id = #{companyId}
       AND act09_account_num_id IN
    <foreach collection="accountNumIds" item="accountNumId" open="(" separator="," close=")">#{accountNumId}</foreach>
</delete>
```

- 이 문장을 `--rollback`으로 시험하려고 목록을 여러 방식으로 줬다.

```
yunhee mapper-run "…/ActAccountNumMapper.xml#deleteAccountNums" -p companyId=1 -p accountNumIds=1 --rollback
→ ( :accountNumId )
  -- 필요: accountNumId
  ❌ 파라미터 부족 (1건): accountNumId

… -p accountNumIds=1,2        → ( :accountNumId,:accountNumId )   ❌ 파라미터 부족 (1건): accountNumId
… -p 'accountNumIds=[1,2]'    → ( :accountNumId,:accountNumId )   ❌ 파라미터 부족 (1건): accountNumId
… -p accountNumIds=1 -p accountNumIds=2 → ( :accountNumId )       ❌ 파라미터 부족 (1건): accountNumId
```

- `foreach`의 `collection`(`accountNumIds`)은 인식해서 쉼표로 나눠 자리 수만큼 `:accountNumId`를 펼치지만, **그 자리를 채울 값은 `item` 이름(`accountNumId`)이라는 단일 파라미터를 요구**한다. 목록 값을 받을 입구가 없다.

**왜 문제인가**
- `--rollback`으로 "쓰기 문장이 이 DB에서 도는지"를 확인하는 것이 05 §7의 규칙인데, 삭제처럼 `foreach`를 쓰는 문장은 이 경로로 확인할 수 없다. 이번에도 INSERT/UPDATE는 `mapper-run`으로, DELETE는 시험 행을 실제로 만들었다 지우는 API 호출로 확인했다(03 원칙 2의 "시험용 행은 그 세션 안에 지운다"에 기대는 방식이라 `mapper-run`보다 위험하다).
- `IN (…)` 삭제는 AssetERP의 CRUD 그리드 화면 거의 전부(`deleteXxxs`)가 쓰는 모양이다.

**고칠 것**
1. `foreach`의 `collection` 이름으로 준 값(`-p accountNumIds=1,2` 또는 `-p accountNumIds=[1,2]`)을 쉼표로 나눠, 펼친 자리마다 하나씩 바인딩한다. `item` 이름의 파라미터는 요구하지 않는다.
2. 요소 타입은 숫자로 읽히면 숫자, 아니면 글자로 둔다(기존 `-p` 값 해석 규칙을 따른다).
3. `--help`에 한 줄: "`<foreach>`는 `-p <collection>=a,b,c`로 준다".

**검증 방법**
- (a) `yunhee mapper-run "backend/src/main/resources/mapper/ActAccountNumMapper.xml#deleteAccountNums" -p companyId=28000 -p accountNumIds=1,2 --rollback` → `DELETE 0 (롤백됨)`(없는 ID라 0건)이 나와야 한다.
- (b) 실제 행으로: `yunhee sql "select act09_account_num_id from act09_account_num where act09_company_id=28000 limit 2"`로 ID 두 개를 얻어 `-p accountNumIds=<id1>,<id2> --rollback` → `DELETE 2 (롤백됨)`, 그 뒤 `yunhee sql "select count(*) from act09_account_num"`이 그대로(7)여야 한다.
- (c) 요소가 하나(`-p accountNumIds=1`)여도 `( ? )` 하나로 펼쳐져 동작해야 한다.
- (d) 회귀: `foreach`가 없는 문장(`#insertAccountNum`, `#selectByRetrieve`)의 동작과 `--compare`는 그대로여야 한다.
- (e) 단위 테스트: `collection` 값 파싱에 `1`, `1,2`, `[1,2]`, `a,b`(글자), 빈 값, 공백이 든 값을 넣은 표 테스트.
