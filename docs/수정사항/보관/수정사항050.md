# 수정사항 050 — `screen-desc` 정확도·속도·출력 크기 개선

- 계기: AssetERP에서 `screen-desc` 평가(2026-11-10, yunhee **0.8.2**). 사용자 의견: "너무 느리고 너무 번거롭지 않나".
- 재현: `cd AssetERP && yunhee screen-desc 1077` / `yunhee screen-desc 1029` / `yunhee screen-desc 1077,1029`
  - #1077 관리자 > 01. 고객관리 > 메뉴 관리 (`Sys06_Tab_Menu`): 8KB, 77줄
  - #1029 사원정보 관리 (`Emp00_Tab_TransInfo`): 30KB, 183줄
- 시급도: 1·2번 높음(틀린 값 → 대조 시 거짓 경보), 3번 중간, 4번 중간.
- 평가 요약: 쓰는 법은 간단하다(화면번호 하나 → 메뉴 경로·TOBE/AS-IS·팝업·탭·API·SQL·테이블·이벤트가 한 문서). 화면 파악·사용자 보고용으로 좋다. 문제는 **틀린 값이 섞인 것**, **매번 7초**, **큰 화면의 출력 크기**다. 지금은 AS-IS/TOBE 버튼·그리드 대조에 쓸 수 없어 `analysis ui <화면> --tobe …`를 계속 쓴다.

---

## 1. 버튼·그리드 열 수를 정확히 센다 (우선순위 높음)

#1077에서 TOBE 코드와 대조해 확인한 것:

| 항목 | screen-desc 출력 | 실제 |
|:---|:---|:---|
| 메인 화면 버튼 | 2개(새로고침, 일괄복사) | `루트매뉴 등록`·`하위매뉴 등록`(`<Button type="register">`, `Sys06_Tab_Menu.tsx:172-174`) 등이 빠짐 |
| 팝업 그리드 열 수 | `Sys06_Lookup_CopyMulti` 0 | `<MultiGrid columnDefs={cols01}>`·`{cols02}` 2개(`:140`, `:155`) |

- `<Button type="…">`는 type 값과 관계없이 모두 센다(`AssetERP/docs/button-types.md`의 약 30개 type).
- `columnDefs`에 변수를 넘겨도 같은 파일의 그 변수 정의(배열·`useMemo`)를 따라가 열을 센다. `MultiGrid`·`SingleGrid` 등 공통 그리드 부품을 모두 그리드로 본다.
- 그리드 공통 버튼(`gb.*`, `AssetERP/docs/grid-style.md`)도 버튼으로 센다. #1029 탭페이지(`Emp05_TabPage_Academic` 등)의 버튼이 `-`로 나오는 것이 이 때문으로 보인다(대조는 안 함).
- 셀 수 없는 경우는 `0` 대신 `?`(못 셈)로 적는다. `0`은 "없음"으로 읽혀 거짓 경보가 된다.

## 2. TOBE 참조 테이블은 화면이 쓰는 SQL ID에서만 모은다 (우선순위 높음)

- #1077 TOBE 참조 테이블이 24개(AS-IS 3개). `ast02_detail`·`pay04_formula`·`ics30_compliance` 등은 `SysCompanyMapper.xml`의 회사 생성 SQL에 있는 테이블로, 이 화면과 상관없다.
- 매퍼 **파일 전체**가 아니라 "호출 API → 서비스 → 실제 호출한 SQL ID"의 SQL 본문에서만 테이블을 뽑는다(§5에 나온 SQL ID 16개).
- AS-IS 참조 테이블과 같은 기준이 되어야 둘을 비교할 수 있다.

## 3. 속도: 매번 7초 (우선순위 중간)

| 실행 | 시간 |
|:---|:---:|
| `screen-desc 1077` | 7.3초 |
| `screen-desc 1029` | 6.8초 |
| `screen-desc 1077,1029` | 6.7초 |
| `yunhee --version` | 0.3초 |

- 화면 수와 관계없이 일정하다 → 매번 TOBE·AS-IS 전체를 다시 훑는 준비 비용으로 보인다(CPU 100%대).
- 제안: TOBE 색인(파일 → 컴포넌트·버튼·그리드·API, API → SQL ID → 테이블)을 캐시하고 파일 mtime이 바뀐 것만 다시 만든다. 목표 1초 이하.

## 4. 출력 크기 줄이기 (우선순위 중간)

## 5. 덧붙임 (낮음)

- AS-IS 이벤트 `[E6] copyButton[일괄복사].Select (L133) → retrieve()`는 팝업을 띄운 뒤 닫히면 새로고침하는 흐름인데, `retrieve()`만 보여 오해하기 쉽다. 원본 L136 `new Sys06_Lookup_CopyMulti()` → L137 `lookup.open(callback)` → L140 콜백 안 `retrieve()`. 팝업 열기 호출이 있으면 함께 적는다(예: `→ new Sys06_Lookup_CopyMulti().open → (콜백) retrieve()`).
