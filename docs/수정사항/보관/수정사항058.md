# 수정사항 058 — `yunhee mark`: 캡처 PNG 위에 번호 원·강조 상자·화살표·말풍선을 그려 매뉴얼 이미지를 만든다

- 계기: 수정사항057(`screen-capture --boxes`)과 짝이다. 057이 "무엇이 어디에 있는지"(`*.boxes.json`)를 내면, 이 명령이 그 이름으로 가리켜 **그림을 그린다**.
  처음에는 별도 프로젝트 `mim`으로 만들려 했으나, 규격을 두 저장소 사이에서 맞출 필요가 없고 Chromium·`uv` 환경이 이미 있어 **yunhee에 넣기로 했다**(2026-11-12 사용자 결정).
- 시급도: 중간. 057이 먼저 되어야 `target`(이름 지정)이 쓸모 있다. 057 전에도 좌표를 직접 주면 단독으로 쓸 수 있으니 **구현 순서는 어느 쪽이 먼저여도 된다.**
- 상세 규격: **`docs/boxes-json-규격.md` 11절** (요청 요약은 이 문서, 요소·키·기본값·예시는 그 절을 따른다).
- 참고 구현: A-Man 이미지 편집기 `~/work/aman/frontend/src/components/imageditor/` (`ActionImageEditor.tsx`, `canvasDrawHelpers.ts`, `arrowStamp.ts`, `calloutStamp.ts`, `image_items_defaults.ts`).

## 1. 요청 요약

```bash
yunhee mark <png> <draw.json> [--boxes <파일>] [--out <png>] [--json]
```

- `draw.json`의 요소(`items`)를 PNG 위에 그려 새 PNG를 만든다. `--out` 생략 시 `<이름>-alpha.png`. **원본 PNG는 덮어쓰지 않는다.**
- 요소 이름과 `style` 키는 **A-Man 이미지 편집기와 같다**: `circle-number` · `box` · `arrow` · `text` · `callout`(+ 우리가 더한 `mask` · `crop`).
  그래서 사람이 손으로 만든 기존 매뉴얼 이미지와 같은 모양이 나온다.
- 위치는 `x, y, width, height`를 직접 주거나, `boxes.json`의 요소 이름을 `target`(arrow는 `from`/`to`)으로 준다. `--boxes` 기본은 PNG와 같은 이름의 `.boxes.json`.

## 2. 꼭 지켜야 할 것 (규격서 11절)

| 항목 | 요구 |
|:---|:---|
| 좌표 기준 | `circle-number`의 `x,y` = 원 **중심**(반지름 = `fontSize×1.05`). `box`·`text`·`callout` = **왼쪽 위**. `arrow`의 `x,y` = 시작, `width,height` = **끝점까지의 차이**. (A-Man 코드 그대로) |
| 기본 모양 | A-Man `SYSTEM_ITEM_DEFAULTS` 값 그대로(규격서 11.6). 번호 원 `#ef4444`/글자 흰색/테두리 `#f59e0b` 3/크기 28/약한 그림자, 상자 `#ef4444` 굵기 2/모서리 7, 화살표 `#ef4444` 굵기 3/머리 2 등. |
| 그리는 순서 | `mask` → 나머지 `items`(배열 순서) → `crop`. |
| `crop` | 영역 밖 요소는 버리고 안쪽 좌표는 옮긴다(A-Man 편집기와 같은 동작). 출력 크기가 바뀐다. |
| 이름 해석 | `target`이 boxes.json에 없으면 **오류**(후보 이름을 보여 준다). `#2`가 있는데 이름만 쓰면 첫째를 쓰고 경고. 직접 좌표가 있으면 그쪽이 우선. |
| 위치 지정 | `anchor`(`top-left`(기본)…`center`)·`offset [dx,dy]`·`side`/`gap`(callout·text)·`padding`(box 기본 4). arrow `from`/`to`가 이름이면 상대 요소를 향한 변의 가운데. |
| 검사 | PNG 실제 크기가 boxes.json `image-size`와 다르면 오류. |

## 3. 구현 권장

- **Playwright(헤드리스 Chromium)로 Canvas 2D에 그린다.** yunhee가 이미 Chromium을 쓰고, A-Man의 `drawArrow`·`drawCallout`·`roundRect` 코드를 거의 그대로 옮길 수 있어 모양이 같다. 한글 글꼴도 브라우저가 처리한다.
- Pillow도 가능하나(화살표 머리·그림자·말풍선 꼬리를 다시 구현해야 하고 모양이 달라지기 쉬움) 새 의존성이 생긴다. 어느 쪽이든 규격은 같으므로 구현자가 고른다.

## 4. 처음 구현 범위

`circle-number` · `box` · `arrow` · `text` · `callout` · `mask`(`fill`만) · `crop`.
나중: `orthogonal-arrow` · `bracket-arrow` · `block-arrow-stamp` · `symbol` · `image`, `mask`의 `blur`·`pixelate`.

## 5. 수용 기준(이렇게 되면 끝)

1. 규격서 11.8의 예 `draw.json`을 PNG와 boxes.json에 적용하면 번호 원·상자·화살표·말풍선·가림이 요소 위에 정확히 겹쳐 그려진다.
2. **같은 `items`를 A-Man 이미지 편집기와 `yunhee mark`로 각각 그려 눈으로 같은 모양**이다(번호 원 크기·그림자, 상자 모서리, 화살표 머리).
3. `--out` 생략 시 `<이름>-alpha.png`가 만들어지고 원본은 그대로다. 없는 `target`은 후보 이름을 보여 주며 실패한다.
4. `crop`이 있으면 영역 밖 요소가 사라지고 안쪽 요소의 위치가 맞는다.
5. `--json`이 해석된 최종 요소(이름 → 좌표)를 출력한다.
6. 버전을 올리고 `changelog`에 줄을 남긴다(수정사항056 §2). 테스트를 둔다(작은 PNG로 그린 결과의 특정 픽셀 색·위치 확인).

## 6. 열린 질문 (규격서 11.10과 같다)

- `crop` 뒤에 boxes.json도 새 이미지 기준으로 옮겨 저장할지.
- 이미지 가장자리에서 번호 원이 밖으로 나갈 때 안쪽으로 밀지 그대로 잘릴지.
- `mask` 기본 색.
