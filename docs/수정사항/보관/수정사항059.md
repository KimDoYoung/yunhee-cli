## 1. 팝업에 가려진 본 화면 요소가 함께 저장된다 (높음)

| 캡처 | 요소 수 | `area: main` | `area: modal` |
|:---|---:|---:|---:|
| `05_popup_01_등록.png` (전체) | 321 | 약 308 | 13 |
| `05_popup_01_등록.png` (`--modal-only`, 630×427) | 122 | 109 | 13 |

- 팝업(모달 + 어두운 막) 뒤에 있는 본 화면의 버튼·그리드 헤더·행 아이콘이 모두 들어 있다. PNG에는 보이지 않는 요소다. `--modal-only`에서는 잘린 팝업 영역 안에 본 화면 요소의 상자가 겹쳐 그려진다.
- 규격서 3절("가려져 PNG에 안 보이는 요소는 넣지 않는다")을 어긴다. 모달이 열린 사진에서 `target`으로 "조회"를 부르면 보이지도 않는 버튼에 번호 원이 붙는다.
- 고칠 것: 요소의 **중심점(또는 상자 안 여러 점)에서 `document.elementFromPoint`가 그 요소(또는 그 자손)가 아니면 가려진 것으로 보고 뺀다.** 모달·Lookup이 열려 있으면 `area: main` 요소는 사실상 전부 빠진다(막이 덮으므로). 빼는 대신 `"covered": true`로 남기는 방법도 있으나 기본은 **빼기**(파일도 가벼워진다).

## 2. 1번 때문에 요소 이름이 캡처 방식마다 달라진다 (중간)

- 같은 팝업의 같은 선택칸이 **전체 캡처에서는 `책무구분#2`, `--modal-only` 캡처에서는 `책무구분`**이다(본 화면에 같은 이름 요소가 있느냐에 따라 번호가 달라진다). 같은 `draw.json`이 두 방식에 모두 쓰이지 않는다.
- §1을 고치면 풀리지만, 한 화면에 같은 이름이 여럿일 때 번호 순서가 DOM 순서이므로 **레이어(본 화면 → 모달) 단위로 번호를 따로 매겨 달라**(모달 안 요소는 모달 안에서만 `#n`).
- 같은 이름이 모달 이름과 겹치는 경우도 있다: 팝업의 `책무` 텍스트영역이 모달 이름 `책무` 때문에 `책무#2`가 된다(§6).

## 3. 아이콘 컬럼의 헤더·셀 이름이 컬럼 ID로 나온다 (중간)

- 헤더 글자가 없는 컬럼의 이름이 AG Grid 컬럼 ID 그대로다: `헤더:__rownum`, `헤더:ag-Grid-SelectionColumn`, `헤더:editDetail`, `헤더:editLaw`, … (#1412 그리드 19개 헤더 중 7개 정도). 사람이 "세부내용 수정 아이콘"을 가리킬 수 없다. (규격서 10절 열린 질문 2번)
- 셀 이름도 같다: `grid1.행1.__rownum`, `grid1.행1.ag-Grid-SelectionColumn`, `grid1.행1.editDetail#2`, `grid1.행1.수정#2`.
- 고칠 것(제안, 우선순위 순):
  1. `__rownum` → `헤더:번호`, `ag-Grid-SelectionColumn` → `헤더:선택` (알려진 내부 ID는 고정 매핑).
  2. 글자 없는 컬럼은 **바로 왼쪽 헤더의 글자 + 아이콘 이름**: `editDetail` → `헤더:세부내용 수정`(헤더 `세부내용` 옆의 수정 아이콘), `editLaw` → `헤더:연결법규 수정`. 왼쪽 헤더가 없으면 아이콘 이름(`edit`·`search`)이나 `aria-label`·`title`.
  3. 그래도 못 정하면 현재처럼 컬럼 ID를 쓰되 `헤더:ID:editDetail`처럼 ID임을 알 수 있게 한다.
- 셀·아이콘 이름도 같은 규칙을 따른다: `grid1.행1.세부내용 수정`이 헤더 이름과 일치해야 한다.

## 4. 행 체크박스 이름·크기가 일관되지 않다 (낮음)

- 한 행의 체크박스 두 개가 `grid1.행1.체크` / `grid1.행1.체크#2`로 나뉜다. 앞쪽은 행 선택 체크박스(`[135,178,16,29]`, 높이 29), 뒤쪽은 **공통책무 열의 값 체크박스**(`[1262,185,16,16]`)다.
  → 행 선택은 `grid1.행1.선택`, 값 체크박스는 **그 컬럼 이름**(`grid1.행1.공통책무`)으로.
- 행 선택 체크박스의 높이가 29로, 값 체크박스(16×16)와 달리 셀 높이에 가깝다. 체크박스 자체의 상자(16×16)로 맞춰 달라.

## 5. `mark`: 모르는 `type`이 오류가 아니라 조용히 무시된다 (중간)

| 재현 | 결과 |
|:---|:---|
| `{"version":1,"items":[{"type":"foo"}]}` 를 `yunhee mark <png> <draw.json>` | `🎨 Mark: …-alpha.png (1개 요소 마킹)` 으로 **성공, 종료코드 0** |

- 규격서 11.5절은 "모르는 `type`은 오류"다. 오타(`circel-number`·`rectangle`)가 아무것도 그려지지 않은 이미지로 이어지고, 성공으로 보이므로 알아차리기 어렵다.
- 고칠 것: 알려진 type(`circle-number` `box` `arrow` `text` `callout` `mask` `crop`) 밖이면 **오류 + 종료코드 1 + 출력 파일 안 만듦**. 오류 메시지에 비슷한 type 후보를 보여 준다(`target` 오류처럼 `difflib`). 알려진 type이지만 아직 구현하지 않은 것(`orthogonal-arrow` 등)은 "아직 지원하지 않음"으로 구분해 알린다.
- 같은 뜻으로, 알려진 `style` 키가 아닌 키(오타)는 경고하면 좋다(선택).

## 6. 팝업 안 폼 요소 이름: 체크박스 라벨 없음 · 라벨이 모달 이름과 겹침 (중간)

- `--modal-only` 캡처의 `05_popup_01_등록` 모달 안 요소 이름: `책무`(모달), `책무:제목`, `세부내용(0건)`, `연결규정(0건)`, `저장`, `닫기`, `책무유형`, **`책무#2`**, `책무구분`, `사용시작일`, `사용종료일`, **`checkbox`**, **`checkbox#2`**.
  - `checkbox`·`checkbox#2`는 화면의 `공통책무`·`CEO책무` 체크박스다. 규격서 5절 3항("체크박스는 옆 라벨 글자")과 다르다. 라벨은 이 화면에서 체크박스 **왼쪽**에 있다(AntD `Form.Item` 라벨).
  - `책무#2`는 라벨 `책무` 옆의 텍스트영역인데, 모달 자신의 이름이 `책무`라서 번호가 붙었다.
- 고칠 것
  1. 체크박스·라디오는 **같은 `Form.Item`(또는 같은 줄) 안의 라벨 글자**를 이름으로 쓴다(왼쪽·오른쪽 모두). 못 찾으면 `aria-label`·`title`, 마지막에 `checkbox#n`.
  2. 모달 이름과 안의 요소 이름이 같으면 모달 쪽에 접미사를 둔다(`책무` 모달은 `[모달]책무`나 `책무(팝업)` 등 일정한 규칙). 요소 이름은 라벨 글자를 우선한다.
  3. textarea는 `kind`를 `input`으로 두되 이름은 라벨 글자(`책무`)로 한다.

## 7. `mark`: 대상 바깥에 놓는 `anchor` 지원 (낮음, 편의)

- 번호 원의 기본 크기(`fontSize` 28 → 반지름 약 29px, A-Man 기본값)가 작은 버튼(높이 32px)보다 커서 `anchor: "top-right"`처럼 모서리에 붙이면 **버튼 글자를 가린다**. 지금은 `style.fontSize`를 18로 줄이고 `offset: [0,-14]`로 위로 올려 쓰고 있다(그러면 글자가 보인다).
- 요청: **대상 상자 바깥에 완전히 놓는 위치**를 `anchor`에 더한다. 예 `outside-top-left` `outside-top` `outside-top-right` `outside-bottom-…` `outside-left` `outside-right`. 원(또는 글자·`symbol`)이 대상 상자에 닿지 않고 `gap`(기본 4px)만큼 떨어져 놓인다. 기존 `anchor` 값의 동작은 그대로.
- 이 기능이 없어도 `offset`으로 쓸 수 있으므로 **낮음**이다. 규격서 11.4절 `anchor` 표에 값을 추가한다.

## 수용 기준

1. `05_popup_01_등록.boxes.json`(전체·`--modal-only` 모두)에 `area: main` 요소가 **없다**(또는 `covered: true`). (§1)
2. 팝업의 책무구분 선택칸 이름이 두 캡처 방식에서 **같다**(`책무구분`, `#2` 없음). (§2)
3. #1412 `02_searched.boxes.json`의 grid-header·셀 이름에 `__rownum`·`ag-Grid-SelectionColumn`·`editDetail`·`editLaw`·`editRule`이 없다. (§3)
4. 행 체크박스는 `grid1.행1.선택`, 값 체크박스는 컬럼 이름이고, 상자는 모두 체크박스 크기에 맞는다. (§4)
5. `{"type":"foo"}`는 오류·종료코드 1·출력 파일 없음이고 비슷한 type 후보를 보여 준다. (§5)
6. 팝업의 `공통책무`·`CEO책무` 체크박스가 그 이름으로 나오고, 텍스트영역은 `책무`(모달과 구분됨)로 나온다. (§6)
7. `anchor: "outside-top-left"`로 번호 원이 버튼 위쪽 바깥에 놓이고 버튼 글자를 가리지 않는다. (§7)
8. 검증 방법: `box`로 PNG에 상자를 그려 눈으로 겹치는지 확인한다(가려진 요소가 안 그려져야 한다). 이 겹침 검사를 yunhee 테스트에 둔다(규격서 9절). 아래 부록 스크립트를 참고해도 된다.
9. 버전을 올리고 `changelog`에 줄을 남긴다.

## 부록: 겹침 검증 스크립트 (Pillow)

```python
import json, sys
from PIL import Image, ImageDraw
png, js, out = sys.argv[1:4]
kinds = set(sys.argv[4].split(',')) if len(sys.argv) > 4 else None   # 예: button,input,grid-icon
im = Image.open(png).convert('RGB')
d = json.load(open(js))
assert list(im.size) == d['image-size'], (im.size, d['image-size'])
dr = ImageDraw.Draw(im)
col = {'button':'red','icon-button':'orange','input':'blue','select':'purple','date':'green','checkbox':'magenta',
       'modal':'red','modal-title':'brown','grid':'cyan','grid-header':'blue','grid-icon':'orange','grid-check':'magenta',
       'tab':'green','label':'gray','grid-row':'#999999','grid-cell':'#bbbbbb'}
for e in d['elements']:
    if kinds and e['kind'] not in kinds: continue
    x, y, w, h = e['box']
    dr.rectangle([x, y, x + w, y + h], outline=col.get(e['kind'], 'black'), width=2)
im.save(out)
```

사용: `uv run --with pillow python overlay.py 05_popup_01_등록.png 05_popup_01_등록.boxes.json out.png`
