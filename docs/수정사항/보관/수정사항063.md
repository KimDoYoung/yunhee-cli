## 1. `yunhee grep` — 없는 옵션을 쓰면 안내가 없다 (작음)

- 일어난 일: 한 세션에서 `yunhee grep -n …`, `-r`, `-c`를 세 번 썼다. 모두 `No such option`. `AssetERP/CLAUDE.md` 실수 목록에 이미 적힌 항목인데도 반복했다(옵션은 `-l`·`-m`·`-C`뿐).
  건수만 보고 싶을 때(`대기` 줄이 몇 개인가, 새 행이 몇 줄인가)는 `-c`가 없어서 `| wc -l`을 쓰려다 막혔다.
- 고칠 것:
  1. `yunhee grep -c`(파일별 일치 줄 수, 0이면 생략 가능)와 `-n`(줄 번호 — 기본 출력에 이미 줄 번호가 있으면 `-n`은 아무 일도 안 하는 호환 옵션으로 받아 준다)을 더한다. `-r`도 같은 식으로 "폴더는 원래 재귀"라 호환 옵션으로 받는다.
  2. 그래도 모르는 옵션이면 typer 기본 오류에 한 줄을 덧붙인다: `사용 가능한 옵션: -l(파일 이름만) -m(파일당 최대 N줄) -C(앞뒤 문맥) -c(건수) · 패턴은 ERE(a|b)`.
- 확인: `yunhee grep -c '^\| CH-' AssetERP/docs/3-변경반영/변경반영-대장.md` → `파일:건수`. `yunhee grep -n x f` 가 오류 없이 돈다. 틀린 옵션(`--max-count`)이면 위 안내 줄이 보인다.

## 2. `drift --record` — 줄바꿈·공백만 바뀐 파일을 "원본이 바뀜"으로 막는다 (작음)

- 일어난 일: `yunhee drift --record Fnd08_Tab_OrgAuth …` 가 `기준 변경: 원본이 바뀜 — drift로 먼저 확인 (덮어쓰려면 --force)`로 멈췄다.
  `drift Fnd08_Tab_OrgAuth`는 `+415/-415줄`(Org01_Code.java·Fnd08_Page_OrgAuth.java 등 5개 파일)이라 했는데, 이어서 `drift … -o diff`는 "변경된 파일이 없습니다."였다.
  결국 `git -C ~/work/IDMS-IC diff --ignore-all-space --ignore-cr-at-eol --stat <기준>..HEAD -- <5개 파일>`로 직접 풀어서 **줄바꿈(CRLF)만 바뀐 것**임을 확인하고 `--force`를 썼다. 이 확인은 사람이 하지 않아도 되는 일이다.
- 고칠 것:
  1. `drift`의 요약표 `+/-줄`을 계산할 때 `--ignore-cr-at-eol --ignore-space-at-eol`(옵션 `--strict`로 끌 수 있게)을 기본으로 쓴다. 줄바꿈만 바뀐 파일은 표에서 `+0/-0 (줄바꿈만)`으로 구분해 "변경"에서 뺀다(동일로 센다).
  2. `-o diff`가 "변경된 파일이 없습니다."라고 하는 경우와 요약표 `+415/-415`가 어긋나지 않게 한다(같은 비교 함수를 쓴다).
  3. `drift --record`는 줄바꿈만 바뀐 경우 `--force` 없이 기준을 옮기고 한 줄 `줄바꿈만 바뀜 → 기준 이동`을 보인다.
- 확인: 원본 파일 하나를 `unix2dos`로 바꾼 커밋을 만든 뒤 `yunhee drift <화면>` → `+0/-0 (줄바꿈만)`, `drift --record <화면>` → 오류 없이 기록.

## 3. `drift --all --done-only` — 공유 파일 때문에 약 130개 화면이 계속 "변경" (중간)

- 일어난 일: `Fnd00_Fund.java`·`fnd00_fund.xml`이 바뀌어 `drift`가 "공유 변경(영향 화면 수): Fnd00_Fund.java (137) · fnd00_fund.xml (137)"을 냈다. 대장에서 판단해 보니 **바뀐 메서드(`selectBySearchText`)를 부르는 화면은 4개**(`analysis callers`)뿐이고 나머지 약 130개는 해당없음이다.
  그래도 그 130개는 기준선이 안 옮겨져 다음 `drift`에도 계속 "변경"으로 뜬다(수정사항054 `drift-done`이 하려던 바로 그 문제).
- 고칠 것: 수정사항054의 `drift-done <키…>`를 구현할 때 아래를 넣는다.
  1. 대장 키(`CH-…`)가 `해당없음`으로 처리되면, 그 키가 가리킨 **단위**(파일 + SQL ID/메서드)의 기준만 옮긴다. 그 단위를 쓰지 않는 화면은 화면 기준선은 그대로 두되, `drift`가 그 화면의 "공유 변경" 표에서 **이미 판단한 단위는 빼서** 세게 한다(화면을 `동일`로 돌려준다).
  2. `drift --done-only`의 요약줄에 `판단 끝난 공유 변경 n건 제외`를 보여 준다.
- 확인: 위 `Fnd00_Fund` 건을 대장에 처리한 뒤 `yunhee drift --all --done-only --base baseline` → 137개 중 호출 4개만 `변경`(또는 0개), 나머지는 `동일`.

## 4. `biz-event-new` — 뼈대는 맞지만 TODO가 많고 단계 이름에 잡음이 섞인다 (중간)

- 일어난 일: `biz-event-new AST-BZ-0012 --screens 1299 -c kalpa`가 근거·API·yaml 뼈대를 줬다(좋았다). 그런데
  1. "따라 하기" 19단계 중 `leaveYText`, `[YES]`, `[선택>0]`, `[InvestAssetType]`처럼 **버튼이 아닌 것**(입력칸 이름·확인창 응답·조건·콤보 이름)이 단계 이름으로 들어갔다. 팝업(투자한도 창) 단계도 화면 칸이 모두 `#1299`다.
  2. `업무 규칙·주의`에 `TODO` 한 줄과 "권한 검사 확인: PUT … (서비스 …)" 두 줄만 있다. `biz-endpoints`가 이미 아는 **쓰기 API 전체**(이 화면은 POST·PUT·DELETE 6개)와 `검사` 칸(`회사`만)이 없다.
  3. yaml의 `steps`가 `owner-capitals` 3개뿐이다. 같은 화면이 여는 창(`Ast41_Lookup_InvestLimit`)의 API(`invest-limits` 6개)는 "함께 쓰는 클래스"로 알면서 yaml에 안 넣었다.
- 고칠 것:
  1. 단계 표는 **버튼 이벤트(`[이름].Select`)만** 쓰고, 입력칸·확인창(`DialogHide`)·콤보 이벤트는 앞 단계의 "누르는 것 · 입력하는 것" 칸에 합친다. 팝업 단계는 화면 칸에 `#1299 → <창 이름>`을 쓴다.
  2. `업무 규칙·주의`에 `biz-endpoints` 결과를 붙인다: 이 화면과 함께 쓰는 클래스의 컨트롤러 전체, 쓰기 API 표(메서드·경로·검사), `⚠없음`·`'회사'만` 개수와 `다음: yunhee biz-authz <도메인> --path <경로> --probe-write` 한 줄.
  3. yaml `steps`에 함께 쓰는 클래스의 API도 이름만이라도 넣는다(본문은 비워 둠).
- 확인: 같은 명령을 다시 돌려 `grep -c TODO`가 줄었고, 단계에 `[YES]`·`leaveYText`가 없으며, 쓰기 API 6개가 표에 있다.

## 5. `biz-endpoints`·`biz-authz` — `--path` 가 하나뿐이라 화면 하나에 두세 번 돌린다 (작음)

- 일어난 일: 한 화면이 두 컨트롤러(`/ast/owner-capitals`, `/ast/invest-limits`)를 쓰면 `--path`를 따로 주고 두 번 돌리고 결과를 따로 읽는다. `biz-authz`도 같다(권한 훑기 결과가 파일 두 개).
- 고칠 것: `--path`를 반복 지정(`--path owner-capitals --path invest-limits`)이나 쉼표(`a,b`)로 받아 OR로 합친다. `--screen 1299`(화면 번호)를 받아 그 화면이 쓰는 API 경로를 자동으로 고르는 옵션도 있으면 `biz-event-new`와 같은 입력으로 쓸 수 있다(4번과 이어짐).
- 확인: `yunhee biz-endpoints ast --path owner-capitals --path invest-limits` → 표 하나에 9행. `yunhee biz-authz ast --screen 1299 -u 401 -c kalpa --probe-write` → 같은 9행을 한 번에 판정.
