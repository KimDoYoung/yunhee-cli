# 수정사항 024 — `log --since-run`이 run 끝 시각을 기준으로 씀 (대상 0.2.7)

- 작성: 2026-10-12, yunhee **0.2.7** 기준. 반영하면 **0.2.8**.
- 0.2.7 시험 결과: 023 §1~§3 통과(`AssetERP_1/tools/yunhee-018-check.sh` ✅57 / ❌0). 아래는 C01-6 후속 작업에서 화면 스크립트를 돌리다가 찾은 결함이다.

## 1. `--since-run`의 시작 시각이 run이 끝난 시각임

**재현**
```
yunhee run "bash -c 'NODE_PATH=… node tools/screens/C01-fix.js <폴더>'"   # 약 41초, 브라우저로 로그인·조회
yunhee log tail --since-run last
→ [… · run 20261012_042207_994e94 (bash -c …) 시작 13:22:48 KST 이후]
  선택 범위: 요청 0, SQL 0, WARN 0, ERROR 0  (기록 없음)
yunhee log tail --since 5m
→ 04:22:08 ~ 04:22:16 UTC 사이 요청 30개(로그인·메뉴·trans-infos …)
```
- run ID `20261012_042207_…`는 시작 시각(04:22:07 UTC)인데, `yunhee runs`의 Created At은 `2026-10-12 04:22:48`(끝)이다. 머리 줄의 "시작 13:22:48 KST"도 실제로는 끝 시각이다.
- 결과적으로 `yunhee run`으로 돌린 명령이 실행 중에 만든 로그는 **모두 빠진다**. `--since-run`의 용도(배포·스크립트 실행 후 그동안의 로그 보기, 021 B-3(0))를 전혀 하지 못한다. `errors --since-run`도 같다.
- 022 시험 때 `--since-run last`가 0건으로 정상처럼 보인 것은 `yunhee run "true"`(0초)로 시험했기 때문이다.

**원인**
- `cli.py` L282 `run_tracker.save_run(...)`는 명령이 **끝난 뒤** 불리고 `created_at`을 넘기지 않는다 → `store/run_tracker.py` L65 `ts = created_at or datetime.now(UTC).isoformat()`이 끝 시각을 저장한다.
- `data`에는 이미 `start_time`이 있다(같은 함수 L278 `start_time=data.get("start_time")`로 요약에는 넘긴다).
- `tools/log_reader.py` L583 `find_run_time`은 `run["created_at"]`을 시작 시각으로 쓴다.

**수정**
1. `save_run`에 `created_at=<시작 시각 UTC ISO>`를 넘긴다(`data["start_time"]`, 없으면 `now - duration_ms`). `yunhee runs`의 Created At도 시작 시각이 된다(표 머리를 `Started At`으로 바꿔도 좋다).
2. `find_run_time`은 `(시작, 끝)`을 돌려준다: 끝 = 시작 + `duration_ms`. `--since-run`은 시작부터 보고, `--to`가 없으면 끝은 열어 둔다(run 뒤의 로그도 보고 싶은 경우가 많다 — 배포 후 기동 오류 등). 머리 줄: `· run <id> (<명령>) 13:22:07~13:22:48 KST 이후`.
3. 이미 저장된 기록(끝 시각이 들어간 것)을 위해: `created_at`과 run ID의 `yyyyMMdd_HHmmss`가 1초 넘게 다르면 run ID 쪽을 시작으로 쓴다. run ID 시각의 시간대(지금 UTC로 보임)를 확인하고 맞춘다.
4. 정렬(`ORDER BY created_at DESC`)이 시작 시각 기준으로 바뀌어도 `get_last_run`이 "가장 최근에 **시작한** run"이 되는 것뿐이라 문제없다. 같은 시각에 두 run이 겹치면 `id DESC`를 두 번째 정렬 키로.

**기대 (검증 ID `024-1 since-run 시작`)**
```
yunhee run "bash -c 'yunhee api GET /api/v1/emp/persons/1/careers >/dev/null; sleep 3'"
yunhee log tail --since-run last
```
→ `GET /api/v1/emp/persons/1/careers` 줄이 나온다. 머리 줄 시각이 run ID 시각과 같다.
- pytest: `save_run`이 넘긴 `created_at`을 그대로 저장하는지, `find_run_time`이 `created_at`이 끝 시각인 옛 기록에서 run ID 시각을 쓰는지.
