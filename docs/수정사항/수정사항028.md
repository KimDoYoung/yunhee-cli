# 수정사항 028 — compare가 `buildGridXxx()` 그리드를 못 찾음, `sql-check --old`의 TOBE 주석 해석·잡음 (대상 0.3.2)

- 작성: 2026-10-15, yunhee **0.3.2** 기준. 반영하면 **0.3.3**.
- 수정사항027 반영본(0.3.2)을 027 검증 항목대로 시험하다 찾았다(AssetERP_1). 027-1·027-2는 통과, pytest 151/151 통과.
- 1·2는 결함, 3은 027-4 기대가 설계와 맞지 않아 생긴 빈틈(규칙 추가), 4는 출력 잡음, 5는 작은 것.
- 우선순위: **1 > 2 > 3 > 4 > 5**.
- 새 top-level 명령은 만들지 않는다(027과 같음). 모두 기존 `compare`·`sql-check` 옵션 안에서 고친다.

## 1. `compare`가 `buildGridXxx()` 이름의 그리드를 못 찾음

**재현**
```
cd AssetERP_1
yunhee compare GET /api/v1/sys/persons/29035/roles -c kfstest --sql sys04_role.selectByUserId \
  --param userId=29035 --param companyId=28000 --grid Sys04_Tab_RoleAdmin
→ fields ⊇ grid cols ⚠️ (Sys04_Tab_RoleAdmin#buildGrid, 2컬럼)  (missing: companyName, locationName)
yunhee compare … --grid 'Sys04_Tab_RoleAdmin#buildGridRole'
→ ⚠ 그리드 못 찾음: Sys04_Tab_RoleAdmin#buildGridRole
yunhee compare … --grid 'Sys04_Tab_RoleAdmin#gridRole'
→ ⚠ 그리드 못 찾음: Sys04_Tab_RoleAdmin#gridRole
```
- 색인에는 두 그리드가 있다: `- 그리드 \`gridCompany\` (buildGridCompany()):`, `- 그리드 \`gridRole\` (buildGridRole(), 체크박스(다중)):`, Grid Spec `const buildGridCompany = () => [`, `const buildGridRole = () => [`.
- `analysis grid Sys04_Tab_RoleAdmin`·`analysis ui`는 맞다(GridBuilder 선언·불릿 기준). compare만 틀린다.

**원인**
- `tools/comparator.py` `_extract_all_grids`: 불릿 정규식 `\((build\w*Grid)\(\)` — 메서드 이름이 `Grid`로 **끝나야** 맞는다. `buildGridRole()`은 안 맞는다.
- Grid Spec 쪽도 `const (build\w*Grid)`가 `\b` 없이 `buildGridCompany`의 앞부분 `buildGrid`에 맞아, 메서드 이름이 `buildGrid`로 잘리고 두 그리드가 같은 이름이 된다(그래서 라벨이 `#buildGrid`).
- 결과: 그리드를 하나(그것도 gridCompany)만 얻어 "API 필드와 가장 많이 겹치는 그리드" 선택이 동작하지 않는다.

**수정**
1. 메서드 이름 패턴을 `build\w*` + 이름 안에 `Grid` 포함(`build\w*Grid\w*`)으로 넓히고 Grid Spec은 `const (build\w*Grid\w*)\s*=`처럼 이름 전체를 잡는다. `analysis`의 `count_as_is_grids`와 **같은 정규식을 공유**한다(지금은 compare만 따로 놀아서 생긴 일).
2. 라벨은 실제 메서드 이름 전체(`#buildGridRole`).

**기대 (검증 ID `028-1`)**
```
yunhee compare … --grid Sys04_Tab_RoleAdmin              → (Sys04_Tab_RoleAdmin#buildGridRole, N컬럼)  ← 자동 선택
yunhee compare … --grid 'Sys04_Tab_RoleAdmin#buildGridRole' → ⚠ 그리드 못 찾음 아님, #buildGridRole
yunhee compare … --grid 'Sys04_Tab_RoleAdmin#gridRole'      → 필드 이름(var)으로도 같은 그리드
yunhee compare … --grid Sys05_Tab_PersonRole              → 027-3과 같음 (#buildRoleGrid, 4컬럼)
```
- pytest: `buildGrid`, `buildXxxGrid`, `buildGridXxx` 세 이름이 한 절에 섞인 경우 그리드 3개·라벨 3개.

## 2. `sql-check --old --tobe`가 매퍼 머리 주석의 경로 첫 단어를 statement로 읽음

**재현**
```
cd AssetERP_1
yunhee sql-check --old ~/oms-data/src/Asset-ERP --tobe backend/src/main/resources/mapper --only-tobe
→ - `EmpTransInfoMapper.searchTransInfos` ← emp00_trans_info.server (미존재) · emp00_trans_info.selectByText (바뀜)
  - `EmpCareerMapper.selectCareers` ← server (미존재) · emp07_career.selectByPersonId (바뀜)
  … 15건 중 6건에 `server (미존재)`
```
- TOBE 매퍼 머리(`EmpTransInfoMapper.xml` L6-10):
  ```
  AS-IS server/emp/mapper/emp00_trans_info.xml selectByText(L339) · selectById(L66) · selectOneByPersonId(L205)
  + common.emp00_trans_info(Common.xml L1372) · common.org00_org_info(L1511).
  ```
  `AS-IS ` 바로 뒤 `server`(경로의 첫 마디)를 statement id로 잡았다.

**수정**
1. `AS-IS <경로>.xml` 형식이면 경로는 namespace 추정에만 쓰고, statement는 `이름(L숫자)` 꼴만 읽는다.
2. `+ common.xxx(Common.xml L…)` 줄의 `common.xxx`는 include 조각 이름으로 읽는다(지금처럼).
3. `(미존재)`는 새 원본에 그 `ns.id`가 정말 없을 때만 낸다.

**기대 (검증 ID `028-2`)**
```
yunhee sql-check --old ~/oms-data/src/Asset-ERP --tobe backend/src/main/resources/mapper --only-tobe
→ 출력에 `server (미존재)`·`.server (미존재)` 없음
→ `EmpTransInfoMapper.searchTransInfos` ← emp00_trans_info.selectByText (바뀜) · common.emp00_trans_info (…)
```
- pytest: 머리 주석 두 줄 형식(경로+이름(L), `+ common.…`)과 statement 위 `<!-- AS-IS selectByText L339 … -->` 형식.

## 3. 이미 새 원본으로 고친 TOBE statement도 계속 "바뀜"으로 나옴 (규칙 추가)

**상황**
- 027-4 기대는 "A04에서 새 원본으로 고친 `EmpTransInfoMapper.searchTransInfos`는 목록에 없음"이었지만, 0.3.2는 그대로 낸다.
- 도구는 옛 원본과 새 원본만 비교하므로 TOBE에 반영했는지 알 수 없다. 027 요청서의 기대가 설계와 맞지 않았다(요청서 쪽 잘못).
- TOBE SQL은 원본을 줄여 옮긴 것이라(SELECT 목록을 응답 DTO 컬럼만) TOBE SQL을 새 원본과 직접 비교할 수도 없다.
- 주석의 줄 번호로 가리는 것도 안 된다: 같은 머리 주석에서 `selectByText(L339)`은 새 원본 줄과 같지만 `common.org00_org_info(L1511)`는 옛 줄(새 원본은 L1517)이다.

**수정 — 반영 표시 주석**
1. TOBE 매퍼 주석에서 새 원본 기준으로 옮겼거나 다시 맞춘 statement에 `IDMS-IC`(= 새 원본 폴더 이름) 표시를 인식한다:
   - statement 위: `<!-- AS-IS selectByText L339 (IDMS-IC) -->`
   - 파일 머리: `AS-IS(IDMS-IC) server/emp/mapper/…` → 그 파일 전체
   표시 문자열은 `--new` 폴더 이름(없으면 `YUNHEE_ASIS_SRC_DIR`의 마지막 마디)으로 고정하지 않고 정한다.
2. 표시가 있는 TOBE statement는 "바뀐 원본 SQL을 사용하는 TOBE statement" 목록에서 빼고 `#### 새 원본 반영 표시됨 (N개)`에 이름만 모은다(`--only-tobe`에서도 개수는 보인다).
3. AssetERP_1 쪽 규칙(05 §3 SQL 이식): 2026-10-13 뒤 옮기거나 다시 맞춘 statement에 `(IDMS-IC)`를 단다. 기존 것은 `--only-tobe` 목록을 하나씩 확인하며 단다.

**기대 (검증 ID `028-3`)**
```
# EmpTransInfoMapper.xml의 searchTransInfos 주석에 (IDMS-IC) 를 단 뒤
yunhee sql-check --old ~/oms-data/src/Asset-ERP --tobe backend/src/main/resources/mapper --only-tobe
→ "바뀐 원본 SQL을 사용하는 TOBE statement"에 searchTransInfos 없음, "새 원본 반영 표시됨"에 있음
```
- pytest: 표시 없음 → 목록, statement 표시 → 제외, 파일 머리 표시 → 파일 전체 제외.

## 4. Drift 출력 잡음 (대소문자·문자열 띄어쓰기·`--only-tobe` diff 없음)

**재현**
```
yunhee sql-check --old ~/oms-data/src/Asset-ERP -o json
→ changed 435개 중 62개는 old_norm.lower() == new_norm.lower() (대소문자만 다름)
   예: sys10_file.delete diff "- delete from / + DELETE FROM · - where / + WHERE"
   TOBE 영향 15건 중 3건이 이것: SysFileMapper.deleteById, SysCodeKindMapper.searchCodeKinds, SysCodeKindMapper.selectCodeKind
→ diff 표시가 원문과 다름: ' false ', # { companyId }, ! =, < / when >
```

**수정**
1. 정규화에서 **문자열 리터럴(`'…'`) 밖**은 대소문자를 무시한다(키워드·컬럼명. PostgreSQL은 따옴표 없는 식별자를 소문자로 본다). 리터럴 안과 `#{…}`·`${…}` 안은 그대로 비교한다. 027의 "대소문자 그대로"를 이것으로 바꾼다.
2. diff용 토큰화가 `'false'`, `#{companyId}`, `!=`, `</when>`을 쪼개지 않게 한다(리터럴·파라미터·연산자·태그를 한 토큰으로).
3. `--only-tobe` 출력에도 TOBE statement마다 바뀐 원본 SQL의 diff 요약 한 줄을 붙인다(지금은 전체 출력에만 있다):
   ```
   - `EmpTransInfoMapper.searchTransInfos` ← emp00_trans_info.selectByText (바뀜)
     + ||f_cdnm('EmpTitleCode', emp00_title_cd, …) · + , emp00_tdm_target_yn …
   ```

**기대 (검증 ID `028-4`)**
```
yunhee sql-check --old ~/oms-data/src/Asset-ERP -o json            → 바뀜 수가 435 - 62 근처(대소문자만 다른 것 빠짐)
yunhee sql-check --old … --tobe backend/src/main/resources/mapper --only-tobe
→ SysFileMapper.deleteById 없음, 각 항목 아래 diff 줄, 출력에 "' false '"·"# {" 없음
```
- pytest: 키워드 대소문자만 다름 → 같음, 리터럴 `'Y'`→`'y'` → 바뀜, `#{companyId}` 토큰 하나.

## 5. 작은 것

1. `sql-check --old`는 `-t`를 줘도 파일을 쓰지 않는다(화면에만 낸다). 기존 `docs/as-is/sql-check.md`를 덮지 않는 것은 좋지만 도움말과 다르다 → `--old`일 때 `-t`를 주면 그 파일에 쓰고, 안 주면 화면에만(기본 경로에 쓰지 않음). 도움말에 적는다.
2. `compare` 필드 대응에 `Address`↔`Addr`가 없다: `buildUserGrid`의 `emailAddress`가 API `emailAddr`인데 `missing: emailAddress`(거짓 경고). `Name`↔`Nm`처럼 줄임 대응 표에 `Address→Addr`를 더한다(0.3.2 전부터 있던 한계).
3. 027-5(배포 직후 미기동 경고)는 단위 테스트로만 확인했다. 실제 deploy 직후 확인은 다음 배포 때 AssetERP_1에서 한다(코드 변경 없음, 검증 항목만).
