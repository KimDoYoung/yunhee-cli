# 수정사항 030 — `port-sql` FROM 절 오류, `port-save` 회사 컬럼 이름, `analysis grid` 아이콘 셀을 편집기로 판정, `compare` 오탐·0건, `analysis sql --count` 값 (대상 0.3.5)

- 작성: 2026-10-15, yunhee **0.3.5** 기준. 반영하면 **0.3.6**.
- AssetERP_1에서 C05(고객별 문자사용량)·A16(고객별 서버사용량)·C06(고객별 문자발송)을 변환하면서 쓴 명령에서 찾았다. 세 화면 모두 분석·검증 명령(`analysis`·`compare`·`sql-check`·`api --log`·`log trace`·`run`)은 잘 동작했고, 아래는 **고쳐 주면 손으로 하는 일이 줄어드는 것**이다.
- 1·2는 결함(출력이 틀림), 3은 판정 오류, 4·5는 출력 개선, 6은 훅이다. 우선순위: **1 > 3 > 2 > 4 > 5 > 6**.
- 새 top-level 명령은 만들지 않는다.

## 1. `port-sql`이 FROM 절을 틀리게 만들고 SELECT 목록·DTO를 비움

**재현** (AssetERP_1)
```
yunhee port-sql sms02_history.selectByTotalCount --cols companyName,locName,runningTotalCount --getter-defaults --package kr.co.kfs.asseterp.biz.sms.dto
```
- 원본(`yunhee analysis sql sms02_history.selectByTotalCount -o sql`)은
  ```
  SELECT ROW_NUMBER() OVER() AS sms02_history_id, sys01_company_id AS sms02_company_id, sys01_company_nm AS sms02_company_nm, sys01_loc_nm AS sms02_loc_nm,
         a.total_count AS sms02_total_count, ( SELECT count(sms02_history_id) FROM sms02_history WHERE sms02_company_id = a.sms02_company_id ) AS sms02_running_total_count
    FROM ( SELECT sms02_company_id, count(*) AS total_count FROM sms02_history GROUP BY sms02_company_id ) a
         INNER JOIN sys01_company ON sys01_company_id = sms02_company_id
  ```
- 실제 출력:
  - `<sql id="historyColumns">`에 **상관 서브쿼리(`running_total_count`) 하나만** 들어가고 나머지 SELECT 열(`company_nm`·`loc_nm`·`total_count`)이 없다.
  - `<select>`가 `SELECT <include/> FROM sms02_history` 뒤에 **`( SELECT … ) a INNER JOIN …` 조각을 그대로 이어 붙여** `FROM sms02_history ( SELECT …) a …`가 된다(문법 오류).
  - Record DTO가 `Long runningTotalCount` **한 필드**뿐이다(`--cols` 세 개를 줬는데도).
- 같은 증상을 A27 작업기록에도 적었다("`port-sql`은 `FROM` 뒤 테이블명을 중복해서 손으로 씀"). 서브쿼리 FROM·상관 서브쿼리 열·`ROW_NUMBER() OVER()`가 있는 SQL에서 난다.

**원인(추정)**: SELECT 목록을 최상위 `,`로 자를 때 괄호 안(서브쿼리)·`OVER()`를 구분하지 못해 앞쪽 열이 버려지고, `FROM` 뒤 첫 토큰을 테이블명으로 보고 나머지를 본문에 이어 붙인다.

**수정**
1. SELECT 목록 분리는 **괄호 깊이 0의 쉼표**에서만 자른다(`( … )`·`OVER ( … )`·`CASE … END` 안은 한 열).
2. FROM 절은 최상위 `FROM`부터 `WHERE`/`GROUP`/`ORDER` 앞까지를 **원문 그대로** 복사하고 테이블명을 다시 붙이지 않는다.
3. `--cols`에 준 모든 속성이 DTO record 필드와 SELECT 별칭에 나온다. SQL에 없는 속성은 `⚠ SQL 열 없음: x`로 알린다(`actionCell` 같은 화면 전용 속성이 대표적).

**기대 (검증 ID `030-1`)**
```
yunhee port-sql sms02_history.selectByTotalCount --cols companyName,locName,runningTotalCount --getter-defaults --package …
→ SELECT 열 6개(historyId·companyId·companyNm·locNm·totalCount·runningTotalCount) 모두, FROM ( SELECT … ) a INNER JOIN sys01_company … 원문 그대로, record 필드 3개 이상
```
- pytest: ① SELECT 목록에 `( SELECT … ) AS x`가 있어도 다른 열이 유지됨 ② `FROM ( … ) a JOIN …`이 원문대로 ③ `--cols` 속성 수 = record 필드 수(+ SQL에 없는 것은 경고).

## 2. `port-save --company-col`이 준 이름을 그대로 컬럼 이름으로 씀

**재현**
```
yunhee port-save sms03_group_send --cols title,content,note --company-col company_id
```
- 실제 테이블 컬럼은 `sms03_company_id`(`yunhee table sms03_group_send`)인데 출력이 `INSERT INTO sms03_group_send (sms03_group_send_id, company_id, …)` · `WHERE … AND company_id = #{id}` · `DELETE … WHERE company_id = #{id}`다. 존재하지 않는 컬럼이다.
- `sys85_client_info`처럼 회사 컬럼이 없는 테이블은 `⚠ 회사 컬럼 없음`으로 잘 알려 준다 — 그 판정은 정확하다.
- 같이 보인 점: 회사 값의 파라미터 이름이 `#{id}`라서, 같은 문장 안의 `<foreach item="id">`와 이름이 겹친다(`deleteGroupSends`).

**수정**
1. `--company-col`에 준 이름이 테이블에 없으면 **`{테이블 접두사}_{이름}`**(`sms03_company_id`)을 먼저 찾고, 그래도 없으면 `⚠ 컬럼 없음: company_id (후보: sms03_company_id)`를 낸다. 가능하면 `--company-col` 생략 시에도 `*_company_id` 컬럼을 자동 후보로 쓴다.
2. 회사 값 파라미터는 `#{companyId}`로 하고 `foreach`의 `item`은 `id`가 아닌 이름(`groupSendId`·`item`)으로 해서 겹치지 않게 한다.
3. (선택) 화면의 `insertRow()`가 모델에 setter로 넣는 열(예: `setCompanyId`·`setPersonId`·`setStartDate`·`setRegDate`)을 `analysis method <화면>.insertRow` 결과에서 읽어 "INSERT 후보 열: person_id, start_date — 화면이 채움, 서버가 넣을 값인지 확인" 한 줄로 알려 준다. 이번에도 `sms03_person_id`·`sms03_start_date`, `sys85_reg_date`를 수동으로 추가했다.

**기대 (검증 ID `030-2`)**: 위 명령 → `sms03_company_id` 사용, `#{companyId}`, `foreach item`이 다른 이름. 없는 컬럼 이름을 주면 후보와 함께 경고.

## 3. `analysis grid`가 아이콘 셀(`addCell` + `ImageCell`)을 "편집기"로 보고 `CellEditGrid`로 판정

**재현**
```
yunhee analysis grid Sms02_Tab_TotalCount      → ### 그리드 `Sms02_Tab_TotalCount` (유형: `CellEditGrid`)
yunhee analysis grid Sms03_Tab_SendAdmin       → (유형: `CellEditGrid`)      # 같은 이유
yunhee analysis grid Sys10_Tab_TotalSize       → (유형: `SingleGrid`)         # 아이콘 셀이 없는 같은 모양 — 정상
```
- `Sms02_Tab_TotalCount`는 `setChecked(SINGLE)` + `addText`/`addLong` 3개 + `addCell(properties.actionCell(), 80, "발신기록", ImageCell("View", …))`뿐이다. **셀 편집기(`TextField` 등)가 하나도 없다.** `docs/grid-types.md`의 "CellEditGrid = `addXxx(…, IsField)` 편집기 있음"에 맞지 않는데, 표의 `actionCell` 행(`편집기` 칸 = `actionCell`)이 편집기로 세어졌다.
- 결과: 변환 명세가 `CellEditGrid`를 지시해 `useGridCrud`(체크 다중 삭제·변경 추적)를 쓰게 되는데, 실제로는 읽기 전용 단일 선택 그리드다. 이번에는 코드를 보고 `SingleGrid`로 바로잡았다.

**수정**: `addCell(…, ImageCell|ActionCell)`·`actionCell` 속성은 **편집기가 아니라 클릭 셀**이므로 GridType 판정에서 제외하고, 표의 `편집기` 칸도 `actionCell` 대신 비운다(또는 `클릭 셀`로 따로 표시). `TextField`·`NumberField`·`ComboBox`·`CheckBox` 편집기(`gb.*`의 `editor`)만 `CellEditGrid`로 센다. 색인 화면 파일 `## UI`의 `Cell 편집:actionCell` 표기와 `analysis ui`의 그리드 종류 열도 같이.

**기대 (검증 ID `030-3`)**: `analysis grid Sms02_Tab_TotalCount` → 유형 `SingleGrid`(선택 모드 SINGLE). `Sys85_Lookup_ClientInfoList`(`TextField` 편집기 5개)는 계속 `CellEditGrid`.

## 4. `compare`: 아이콘 컬럼 오탐, 0건일 때 빈 경고, 일부 그리드를 못 찾음

**재현**
```
yunhee compare GET /api/v1/sms/history-totals --sql sms02_history.selectByTotalCount --param useYn=true --grid Sms02_Tab_TotalCount
→ API rows=2, SQL rows=2 ✅  fields ⊇ grid cols ⚠️ (Sms02_Tab_TotalCount#buildGrid, 4컬럼)  (missing: actionCell)

yunhee compare GET /api/v1/sys/files/totals --sql sys10_file.selectByTotalSize --param useYn=true --grid Sys10_Tab_TotalSize     # 이 DB에선 0건
→ API rows=0, SQL rows=0 ✅  fields ⊇ grid cols ⚠️ (Sys10_Tab_TotalSize#buildGrid, 3컬럼)          # missing 목록 없음

yunhee compare GET /api/v1/sys/client-infos --sql sys85_client_info.selectByText --param 'searchText=%%' --grid Sys85_Lookup_ClientInfoList
→ API rows=1, SQL rows=1 ✅  ⚠ 그리드 못 찾음: Sys85_Lookup_ClientInfoList      # 그런데 `yunhee analysis grid Sys85_Lookup_ClientInfoList`는 정상
```

**수정**
1. 필드 비교의 "필요한 열"에서 **데이터 속성이 없는 컬럼**(`rowNumberer`·`checkBoxSelection`·`actionCell`, `addCell`/`ImageCell`)을 뺀다(3과 같은 기준). 지금은 `rowNumberer`·`checkBoxSelection`은 빼는 것으로 보이는데 `actionCell`만 남는다.
2. API·SQL 행이 0건이면 `fields ⊇ grid cols ⚠️`만 내지 말고 `필드 비교 못 함 (행 0건)`으로 쓴다(`missing` 없는 경고가 사람을 헷갈리게 한다).
3. `--grid <클래스>`를 못 찾는 경우를 줄인다: `analysis grid`가 찾는 클래스(연결·다른 도메인 컴포넌트 `Sys85_Lookup_ClientInfoList` 포함)를 `compare`도 같은 방법으로 찾는다. 못 찾으면 어떤 색인 폴더를 봤는지 한 줄 알린다.

**기대 (검증 ID `030-4`)**: 첫 명령 → `fields ⊇ grid cols ✅ (… 3컬럼)`. 둘째 → `필드 비교 못 함 (행 0건)`. 셋째 → 그리드를 찾아 `✅`.

## 5. `analysis sql --count`가 집계 SQL의 값 대신 결과 행 수(1)를 냄

**재현**
```
yunhee analysis sql emp01_person.selectByCompanyIdTotal --param companyId=% --param 'searchText=%%' --param useYn=true --count
→ 1                       # `SELECT count(*) …`라서 항상 1
yunhee analysis sql … -o sql > x.sql ; yunhee sql -f x.sql
→ rows=1  count=758       # 같은 SQL의 실제 값
```
- `--count`는 "행 수"를 세는 옵션이라 결과가 맞지만, `selectBy…Total` 같은 **총계 SQL**(결과가 1행 1열 정수)에서는 사용자가 원하는 값이 아니다. 이번에도 총계(사용고객 758·전체 801)를 보려고 `-o sql` → `yunhee sql -f`로 우회했다.

**수정**: `--count` 결과가 1행이고 SQL의 SELECT 목록이 `count(`·`sum(` 한 열이면 `rows=1 (count=758)`처럼 **그 값**을 함께 낸다(또는 `--value` 옵션). SELECT가 아닌 열이거나 컬럼이 여럿이면 지금처럼 행 수만.

**기대 (검증 ID `030-5`)**: 위 명령 → `rows=1 count=758`.

## 6. 훅(`.claude/hooks`)이 `tail`이 들어 있다는 이유로 파일을 만드는 명령 전체를 막음

**재현** (두 번 겪음)
- `cat > file <<'EOF' … EOF` 로 Java 파일 두 개를 만들고 끝에 `yunhee sql-check … | tail -15`를 붙인 한 줄 명령 → 훅 오류("AS-IS 원본·색인과 TOBE 소스를 cat/sed/head/tail/awk … 직접 읽지 않는다")로 **명령 전체가 실행되지 않음**(파일도 안 만들어짐). 같은 목적을 `Write` + 따로 실행한 `grep`으로 다시 해야 했다.
- `yunhee table sys06_menu | head -40; ls docs/as-is/src/ | head -30; …` 처럼 **yunhee·`ls` 출력을 `| head`로 줄인** 확인 명령도 같은 오류(색인 폴더 이름을 보려던 것). `grep -n … -A/-B`·`sed -n 1,25p <TOBE 소스>`는 훅 설명대로 소스를 읽는 경우라 맞지만, **yunhee·ls·gradle 출력 줄 수를 줄이는 `| tail`/`| head`**까지 막는 경우가 있다(같은 `| head`가 통과한 때도 있어 규칙이 일정하지 않다).

**수정(훅)**: ① 막는 대상을 "AS-IS/TOBE **소스·색인 파일**을 인자로 받는 `cat/sed/head/tail/awk`"로 좁힌다(파이프 뒤의 `tail`·`head`가 앞 명령(yunhee·gradle·ls) 출력을 자르는 것은 허용). ② 막을 때 메시지에 **어느 부분이 걸렸는지**(예: `tail`)를 같이 보여 준다 — 지금은 이유가 일반 문구뿐이라 heredoc 안의 단어인지 파이프인지 알기 어렵다.

**기대 (검증 ID `030-6`)**: `yunhee sql-check --tobe … | tail -5`·`ls dir | head -20`은 통과, `cat backend/src/main/java/….java`·`sed -n 1,20p 색인.md`는 계속 차단.

## 7. (작은 것) `analysis ui --tobe`가 연결 컴포넌트를 다른 폴더에 두면 따로 불러야 함

- `analysis ui Sms03_Tab_SendAdmin --tobe frontend/src/pages`는 `Sms03_*`·`Sms04_*` 4개 클래스만 표로 낸다. 연결 컴포넌트 `Sys85_Lookup_ClientInfoList`(`--list`에는 "연결·다른 도메인"으로 나온다)는 `--tobe frontend/src/pages/sys`로 **한 번 더** 불러 대조했다. `--tobe`를 폴더 여러 개(콤마 또는 반복)로 받거나, 상위 폴더(`frontend/src/pages`)를 재귀로 찾으면 한 번에 끝난다. 이번에는 `frontend/src/pages`를 줘도 `pages/sys`의 파일을 못 찾았다(재귀가 아닌 듯). 불편 정도로, 우선순위는 낮다.
