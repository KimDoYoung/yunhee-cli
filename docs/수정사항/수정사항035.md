# 수정사항 035 — `analysis sql -o json` 렌더링 실패 (대상 0.4.0)

- 작성: 2026-10-17, yunhee **0.4.0** 기준. 반영하면 **0.4.1**.
- 계기: 0.4.0(수정사항034 반영)을 `tools/yunhee-benchmark.sh`로 확인하다가 발견. 034-3 중 `analysis screen --list -o json`·`analysis ui -o json`은 정상이고 033(`sql -o tsv|json|csv`, `--builtin menus`, `drift --record-from`)·034-1·034-2도 모두 기대대로 동작했다. 이 하나만 실패한다.
- 새 명령 없음.

## 1. `analysis sql <ns.id> -o json`이 항상 실패함

**재현**
```
yunhee analysis sql sys27_login_manage.selectByText -o json -s <소스> --src-index <색인>
→ [ERROR] 렌더링 실패: Object of type PosixPath is not JSON serializable      (exit 1, 출력 없음)
```
- 같은 명령의 `-o md`(기본)는 정상이다(`파라미터`·`테이블`·`함수`·`ORDER BY`).
- 원인: JSON으로 만들 딕셔너리에 `pathlib.Path`(매퍼 XML 경로로 추정)가 그대로 들어 있다. `json.dumps(..., default=str)`로 처리하거나 만들 때 `str(path)`로 바꾼다.
- 034-3의 기대 출력 `{"id","file","line","params":[…],"tables":[…],"functions":[…],"order_by":"…"}` 형태도 이 수정 때 함께 확인한다.

**수정**
1. `Path` → 문자열(소스 루트 기준 상대 경로, `file`)로 변환한다. 다른 `-o json` 경로(`screen`·`ui`)에도 `Path`가 들어갈 수 있으니 JSON 직렬화 공통 함수 한 곳에서 `default=str`(또는 `Path` 처리)로 막는다.
2. 렌더링 실패 시 지금처럼 `[ERROR]`를 내되, `-o json`이면 stderr에만 쓰고 stdout은 비운다(스크립트가 빈 출력으로 실패를 알 수 있게).

**기대 (검증 ID `035-1`)**
```
yunhee analysis sql sys27_login_manage.selectByText -o json -s <소스> --src-index <색인> \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['id'], d['line'], d['params'], d['tables'])"
→ sys27_login_manage.selectByText 64 ['companyId', 'personId'] ['sys27_login_manage', 'sys01_company']
```
- pytest: ① JSON 파싱 가능 ② `id`·`file`(상대 경로 문자열)·`line`·`params`·`tables`·`functions`·`order_by` 키 ③ `-o md`와 값이 같음 ④ 존재하지 않는 statement는 Exit 1 + 메시지(JSON 아님).
- 우리 쪽 확인: `tools/yunhee-benchmark.sh 06j`(현재 0%, 이 수정이 반영되면 100%가 되어야 한다).
