# 수정사항 040 — `log --since-deploy` Docker exec 인자 공백 오류 (대상 0.4.3)

- 작성: 2026-10-20, yunhee **0.4.3** 기준. 반영하면 **0.4.4**.
- 계기: AssetERP에서 `./deploy.sh` 직후 `yunhee log errors --since-deploy`를 실행했을 때 `docker exec 실패 (t3600-tomcat): sh: 0: cannot open  -c: No such file` 오류 발생.

## 1. `log errors --since-deploy` Docker exec 실행 실패

**증상 및 재현**
```bash
yunhee log errors --since-deploy
→ docker exec 실패 (t3600-tomcat): sh: 0: cannot open  -c: No such file
```
- `log tail`, `log req`, `api --log` 등 다른 docker 기반 로그 조회 명령은 정상 동작하나, `--since-deploy` 플래그가 들어간 명령에서만 실패.
- 원인: `src/yunhee/tools/log_reader.py` L667의 `find_deploy_time_docker()`에서 `sh` 옵션 문자열이 `" -c"`(선행 공백 포함)로 작성되어 있어, 컨테이너 내부의 `sh`가 `-c` 옵션 플래그가 아닌 스크립트 파일명 ` -c`로 해석하여 `cannot open  -c: No such file` 오류 발생.
- 부수 영향: 039-11에서 추가된 `check_app_starting_after_deploy()`에서도 내부적으로 `find_deploy_time_docker(..., raise_on_error=False)`를 호출하므로 항상 `None`이 반환되어 컨테이너 배포 기동 시각을 정확히 감지하지 못함.

**수정**
1. `src/yunhee/tools/log_reader.py` L667에서 `" -c"`를 `"-c"`로 수정하고 로그 파일 경로(`{info_file}`)를 작은따옴표로 안전하게 인용:
   ```python
   cmd = ["docker", "exec", container, "sh", "-c", f"grep -E 'Started \\w+ in [0-9.]+ seconds' '{info_file}' | tail -n 1"]
   ```
2. `tests/test_log_reader.py`에 `test_find_deploy_time_docker` 단위 테스트를 추가하여 커맨드 인자 구성(`cmd[4] == "-c"`, 선행 공백 없음) 및 정상 시각 파싱, 에러 처리 검증.

**확인 (합격 기준)**
```bash
cd /home/kdy987/work/framework-sprt/AssetERP
yunhee log errors --since-deploy
```
- 결과: `docker exec 실패` 없이 오늘 배포 시각(예: `· 배포 04:13:59 UTC (13:13:59 KST)`) 헤더와 함께 정상 실행됨.
