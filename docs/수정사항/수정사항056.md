## 4. `drift-diff <화면 파일>`: 공백·import 걸러 보기 (낮음~중간)

- `yunhee drift-diff client/vi/ics/Ics31_Tab_ComplianceWrite.java`는 파일 전체 diff를 준다(됨 — 이번엔 몰라서 `git diff -w … | grep "^[+-]" | grep -v import`를 손으로 썼다).
- 화면 클래스 diff는 수백 줄이라 거의 매번 같은 거름을 했다: 공백 무시(`-w`), import·빈 줄·주석 줄 빼기, `+`/`-` 줄만.
- 고칠 것(옵션): `--compact`(위 거름) · `--since <커밋>`(기준선 대신 그 커밋 이후만 — 이번 #1311처럼 TOBE가 중간 커밋(V28)까지 이미 옮긴 경우, 그 뒤 변경만 보고 싶다).
- `--base`는 이미 `<커밋>`을 받으므로 `--since`는 `--base <커밋>`의 별칭이어도 된다(도움말 예시에 그 쓰임을 적어 주면 충분).

## 5. 색인이 화면의 파일을 놓쳐 대장에 "drift가 못 잡음" 행이 많다 (중간)

- 대장 비고 "drift가 못 잡음(n화면: 색인 파일 목록에 없음)"이 붙은 행: CH-0037~0044·0047·0048·0050·0052~0055·0095·0096·0098·0099·0101·0103~0106·0109·0110·0114·0117 등.
- 예: `ics30_compliance.selectByCompanyIdPaging`(#1311), `Sys99_Print.insertRdBookFundMngFee`(#1401), `ics32_relate_appr.*`(#1310) — 화면 색인(`docs/as-is/src/ics/screens/Ics31_Tab_ComplianceWrite.md` 등)의
  "함께 쓰는 파일"에 그 서버 파일·매퍼가 없다. 원인 추정: ① 클라이언트가 `ServiceRequest("ics.Ics32_RelateAppr.selectApprCheck")`를 **새 메서드**로 부르는데 색인 기준 커밋엔 메서드가 없었다,
  ② `Sys99_Print`처럼 큰 공통 파일을 화면 파일 목록에서 빼는 규칙, ③ `GridRetrieveData.retrieve("…")` 형태 호출.
- 고칠 것: `index-src`가 클라이언트의 서비스 문자열(`"dom.Class.method"` — `ServiceRequest`·`retrieve(…)`·`CommonComboBoxField(…)` 모두)을 따라 서버 메서드 → 매퍼 SQL ID까지 화면에 매단다.
  공통 파일은 파일 전체가 아니라 **그 화면이 부르는 메서드만** 매단다(그러면 Sys99_Print 95화면 잡음도 준다 — 수정사항054 `drift-unit`과 같은 생각).

## 6. 작은 것 (낮음)

- `grep`: `--files`를 쳤다가 실패(실제는 `-l`/`--files-with-matches`). 흔한 별칭(`--files`, `-r` 무시)을 받아 주거나, 모르는 옵션일 때 가까운 옵션을 제안("`--files-with-matches`?").
- `sql`: `information_schema`로 여러 열 존재를 한 번에 볼 때 `unnest(array[…])`를 손으로 썼다. `yunhee table --has <열…>`(없는 열만 출력) 같은 게 있으면 DB 변경(열 추가) 판단이 빠르다.
- `api`: 시스템 관리자만 되는 API(`/sys/companies/{id}/approval`)를 기본 계정으로 부르면 `ACCESS_DENIED`. 관리자 회사로 다시 부르는 방법(`YUNHEE_TEST_ADMIN_USER=admin … -u admin -c admin`)을
  `--help`나 오류 메시지 끝에 한 줄로 알려 주면 좋다.
