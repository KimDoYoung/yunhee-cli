## 13. EMP-BZ-0023(인사평가 항목) — 뼈대가 파이썬 문법 오류 (2026-11-16)

- 재현: `yunhee test-scenario-skel EMP-BZ-0023 --print > x.py && python3 -c "import ast; ast.parse(open('x.py').read())"` → `SyntaxError: '{' was never closed`.
- 원인: 본문 dict **한 줄 안**에 자리표시 주석을 넣었다(`"evalListStdId": sc.ctx.get("3", "3")  # 자리표시 <3>, "rows": [...]}`). `#` 뒤 나머지 줄(`rows`·닫는 `}`)이 모두 주석이 된다. 파일에 바로 붙이는 모드(`--print` 없이)였다면 `emp.py` 전체가 import 되지 않아 **시나리오 25개가 함께 멈췄을** 것이다.
- 바라는 것: ① 주석은 줄 끝에만 둔다. 본문 dict는 키마다 줄을 나누고 주석은 그 줄 끝에 붙인다. ② 만든 코드를 `ast.parse`로 검사하고, 실패하면 파일에 쓰지 않고 오류를 낸다. ③ `<3>`(3단계 응답)은 `sc.ctx.get("3", "3")`처럼 기본값이 키와 같은 이상한 값이 아니라, 3단계 결과를 변수로 받아(`sid = sc.step("3", …)`) 쓴다.
- `expect: { tables: {표: 증감} }` → `expect={"tables": {...}}`로 dig 키가 되었다. 5번(`table delta`)과 같은 문제이고, 표가 여러 개인 형식이다.
- `api: [PUT … { fixYn: false }, DELETE …/{id}]`(한 줄 목록 안 본문)에서 본문 `{ fixYn: false }`를 버렸다(`body=None`).

## 14. EMP-BZ-0024(인사평가 진행) — 문서 YAML이 깨져 있을 때 (2026-11-16)

- 이벤트 문서 YAML의 흐름 표기(`{ … api: POST …/{apprId}/confirm … }`, `[PUT …/{id}/ceo-score  # … , "…"]`)가 YAML 오류였다. 경로 안의 `{}`와 `[]` 안 `#` 주석 때문이다. 뼈대는 `[ERROR] YAML 파싱 오류`를 찍고 코드를 하나도 내지 않았다(이건 맞는 동작). 프로젝트 쪽에서 따옴표·블록 목록으로 문서를 고쳤더니 문법이 맞는 뼈대(10단계)가 나왔다.
- 바라는 것: ① 오류 때 종료 코드를 0이 아닌 값으로(일괄로 돌릴 때 걸러지게). ② 여러 이벤트를 한꺼번에 검사하는 모드(예: `test-scenario-skel --check EMP`)로 YAML 오류·중복 키(12절)·자리표시 미해결 수를 한 줄씩 낸다. 업무분석 문서를 쓰는 쪽이 미리 고칠 수 있다.
