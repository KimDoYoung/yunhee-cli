## 1. 원칙

1. **정적 데이터만 쓴다.** 로컬 LLM(qwen)을 쓰지 않는다. 같은 TSX면 같은 출력이 나와야 한다(결정적).
2. 생성기는 **"무엇을 누를지"만** 정한다. "어떻게 누를지"(선택자, 옵션 펼치기, 모달 기다리기, 오류 감시)는 프로젝트 쪽 실행기(`lib.cjs`)가 맡는다. 그래서 출력은 **실행 코드가 아니라 단계 목록(데이터)**이다.
3. 생성본은 사람이 고치지 않는다. TSX가 바뀌면 다시 생성한다. 손보는 것은 프로젝트 쪽 `screen-test-<번호>.cjs`가 생성본을 불러다 덧붙인다.
4. **데이터를 바꾸거나 밖으로 보내는 버튼은 절대 켜진 채로 생성하지 않는다**(4절 위험 type). 이 프로젝트는 메일·SMS·Teams 자동발송이 붙어 있다.

- 계정·비밀번호는 받지 않는다(생성은 정적). 계정은 실행할 때 프로젝트 쪽 스크립트가 받는다.
- 출력 폴더 기본값: `tools/tests/screen-test/gen/`, `-t`로 바꿀 수 있다.

## 3. 출력 형식 — 단계 목록(두 쪽의 계약)

    // AUTO-GENERATED by yunhee test-gen-screen 0.9.x — DO NOT EDIT
    // [1023] 문서작성 > 05. 메일관리 > 발신메일목록  SID=SG  file=frontend/src/pages/dcr/Dcr10_Tab_MailHistory.tsx
    module.exports = {
      screenNo: "1023",
      sid: "SG",
      source: { file: "...tsx", hash: "<sha1>" },
      steps: [
        { id: "s01", do: "open" },
        { id: "s02", do: "click", button: "조회", type: "search", src: "Dcr10_Tab_MailHistory.tsx:120" },
        { id: "s03", do: "selectEach", label: "메일구분", then: "s02" },
        { id: "s04", do: "fill", label: "제목", kind: "text", then: "s02" },
        { id: "s05", do: "lookup", label: "연관펀드", expectModal: "연관펀드" },
        { id: "s06", do: "tabEach" },
        { id: "s07", do: "rowClick", grid: 0, row: 0 },
        { id: "s08", do: "cellIcon", grid: 0, col: "내용", expectModal: "상세보기" },
        { id: "s09", do: "click", button: "삭제", type: "delete", danger: true, enabled: false },
      ],
      unknown: [ /* 정적으로 정하지 못한 것: { src, reason } */ ],
    };

(위 `id`는 예시. 실제로는 6절의 안정된 id를 쓴다.)

### 단계 종류(`do`)

| do | 뜻 | 정적으로 정하는 것 | 실행기가 정하는 것 |
|:---|:---|:---|:---|
| `open` | 메뉴로 화면 열기 | 화면번호 | 로그인·겸직 통과·탭 생성 |
| `click` | 버튼 누르기 | 버튼 글자, type | 화면에서 찾기, 잠김이면 건너뜀(SKIP) |
| `fill` | 검색·입력칸에 값 | label/placeholder, kind(text·number·date·dateRange) | 값(text=`[TEST-<번호>]`, number=`1`, date=오늘) |
| `selectEach` | 콤보 옵션 차례로 고르기 | label | 옵션은 **실행 중에 펼쳐서** 읽음(코드표 API 값이라 정적으로 모름) |
| `lookup` | 돋보기 → 모달 열림 확인 → 닫기 | label, 기대 모달 제목 | 모달 기다리기·닫기 |
| `tabEach` | 하위 탭 차례로 누르기 | 탭이 있음/탭 이름 | — |
| `rowClick` | 그리드 행 선택 | 그리드 순서 | 행이 없으면 SKIP |
| `cellIcon` | 그리드 아이콘·링크 셀 | 열 제목, 기대 모달 | — |
| `modalOpen` | 버튼이 여는 팝업 열림 확인 → 닫기 | 버튼, 기대 모달 제목 | — |

- `then`: 이 단계 뒤에 다시 할 단계 id(보통 조회).
- `src`: 근거가 된 TSX 파일:줄. 실패 보고에 쓴다.
- 모르는 것은 추측하지 말고 `unknown`에 이유와 함께 넣는다.

## 4. 위험 type 규칙(`docs/button-types.md` 기준)

| 분류 | type | 생성 |
|:---|:---|:---|
| 자동(켜짐) | search, view, expand, collapse, close, cancel, reset, select, org, settings, shortcut, goto, print, download | `enabled` 생략(켜짐) |
| 위험(꺼짐) | save, delete, removeRow, send, register, generate, calculate, assign, unassign, change, move, upload, attach, bookmark, plus, minus, group, addRow | `danger: true, enabled: false` |
| type 없음·모르는 글자 | — | 위험으로 취급 |

- `goto`·`print`·`download`는 데이터를 바꾸지는 않지만 새 탭·창·파일이 생긴다. 실행기가 처리한다.
- 분류표는 생성기 안에 하드코딩하지 말고 `button-types.md`에서 읽거나 설정 파일로 둔다(프로젝트에서 바꿀 수 있게).

## 5. 생성하지 않는 것

- 저장할 때의 필수값·선행조건·업무 검증, 시험 행 정리, 결과 값 검증(판정 기준). 위험 단계의 실제 시나리오는 프로젝트 쪽(사람·Claude)이 `screen-test-<번호>.cjs`에서 켜고 채운다.

## 6. 프로젝트 쪽에서 하는 것(참고)

- `lib.cjs`에 단계 실행기 `runSteps(page, gen, opts)`를 만든다. 판정은 list.cjs와 같다(PASS·WARN·FAIL·SKIP, 5xx·pageerror·console.error, 위험 단계 밖의 쓰기 요청 감시).
- `screen-test-<번호>.cjs` = `require('./gen/screen-test-<번호>.gen.cjs')` + 덧붙임. 단계는 `id`로 가리킨다(`enable: ["click:삭제"]`). 그래서 다시 생성해도 **id가 흔들리지 않아야 한다.** 순번(`s01`) 대신 do·버튼 글자·label로 만든 안정된 id(예: `click:삭제`, `lookup:연관펀드`)를 권한다. 정식 규칙은 9.2절.

### 결정(2026-11-17)

1. type 없음·아이콘 전용 버튼 → 위험(`danger: true, enabled: false`). 글자·라벨도 없으면 `unknown`에 기록. AntD의 `type="primary"`·`"default"` 등은 button-types의 type이 아니므로 **type 없음**으로 본다.
2. 조건부 요소 → `conditional: true`로 생성. 팝업·모달은 1단계(열림 확인 → 닫기)까지.
3. 4절 표 그대로 확정 — `goto` 자동(켜짐), `addRow`·`bookmark`·`register` 위험(꺼짐). 위험 버튼이 모달을 열더라도 `enabled: false` 유지.

5. 기존 `.gen.cjs`: 기본은 같으면 그대로·다르면 덮어쓰고 diff 요약, `--force`는 무조건 재작성.

## 9. 추가 (2026-11-17, 구현 중 보완)

### 9.1 SearchBar 조회 버튼 — TSX에 `<Button>`으로 나오지 않는다

- #1023 `frontend/src/pages/dcr/Dcr10_Tab_MailHistory.tsx:106`:

      <SearchBar onSearch={retrieve} loading={loading} style={{ flexWrap: 'nowrap' }}>
        <SearchBar.Field label="발신일자"> …
        <SearchBar.Field label="연관펀드"> …
        <SearchBar.Field label="검색">
          <SearchBar.Input style={{ width: 200 }} placeholder="제목" … />

- 조회 버튼은 `SearchBar` 부품이 안에서 그린다. TSX에는 `<Button type="search">`가 없고 `onSearch` 속성만 있다. `<Button>`만 모으면 **조회 단계가 생성되지 않는다**(1번 결정의 "type 없는 버튼"과 다른 문제 — 버튼 자체가 안 보인다).
- 바라는 것:
  1. `<SearchBar onSearch=…>`가 있으면 `{ do: "click", button: "조회", type: "search", via: "SearchBar" }`를 만든다. id는 `click:조회`.
  2. `SearchBar.Field`의 `label`을 그 안 입력 요소의 label로 쓴다. `SearchBar.Input`은 `placeholder`가 있으면 그것을 label로(`fill:제목`). 날짜(`DatePicker`·`RangePicker`)는 `kind: date|dateRange`, Select는 `selectEach`, LookupInput은 `lookup`.
  3. `fill`·`selectEach` 단계의 `then`은 SearchBar 조회 단계 id(`click:조회`).
- 같은 방식으로 **버튼을 안에서 그리는 공통 부품**을 표로 정리해 생성기가 읽게 한다(하드코딩 대신 설정). 최소 후보: `SearchBar`(조회), `LookupInput`(돋보기), 그리드 툴바·CRUD 훅(`crud.*`)이 그리는 버튼. 실제 목록은 `framework-sprt/AssetERP/docs/1-변환/11-프론트부품.md` 기준으로 framework-sprt 쪽과 확정.
- 참고(2026-11-17 기준): `frontend/src/pages` TSX 1,270개 중 797개 파일이 `<Button type="search|save|delete">` 형식을 쓴다(예: #1282 `Apr30_Tab_ApprStepGroup` — `search`·`register`·`save`·`delete`). AntD `type="primary"`는 3개 파일.

### 9.2 단계 id 규칙 — 순번 접미사 대신 컴포넌트 범위

- 결정 4의 "충돌 시 `#2`, `#3` 접미사"를 아래로 바꾼다. 순번 접미사는 앞에 버튼 하나가 생기면 밀려서, 손본 `.cjs`가 엉뚱한 단계를 켠다.
- 형식: `<컴포넌트>/<do>:<글자 또는 label>`
  - `<컴포넌트>` = 그 요소가 들어 있는 TSX 파일의 화면 클래스 이름(`Apr30_Tab_ApprStepGroup`, `Apr30_Page_ApprStep` …).
  - `<글자 또는 label>` = 버튼 글자 / Field label / placeholder / 탭 이름 / 열 제목. 그리드는 `rowClick:<그리드 순서>`, `cellIcon:<그리드 순서>.<열 제목>`.
  - 예: `Dcr10_Tab_MailHistory/click:조회`, `Dcr10_Tab_MailHistory/lookup:연관펀드`, `Apr30_Page_ApprStep/click:조회`.
- 메인 화면(Tab) 단계는 범위를 생략한 짧은 형태도 받는다(`click:조회` ≡ `Dcr10_Tab_MailHistory/click:조회`). 프로젝트 쪽 `.cjs`는 짧은 형태를 주로 쓴다.
- 같은 컴포넌트 안에서도 겹치면 그때만 `#2`를 붙이고, 겹친 사실을 `unknown`에 `{ src, reason: "id 중복" }`으로 남긴다(사람이 보게).
- 같은 하위 컴포넌트가 한 화면에 두 번 쓰이면(같은 Page 두 개) 컴포넌트 뒤에 그 JSX의 `key`·`title`·탭 이름을 붙인다(`Xxx_Page_Y[결재선]/click:조회`). 그것도 없으면 `#2`.
