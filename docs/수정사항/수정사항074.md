# 수정사항 074 — drift: "판단 끝난 공유 변경" 제외가 그 뒤 새 커밋까지 숨김 (변경 누락)

- 계기: framework-sprt 변경반영(2026-11-23). 원본 커밋 3개(`ad36c5e64`·`bfc5846cc`·`7db81bb7a`, 2026-11-20)를 `tools/make-change-docs.sh`(속은 `yunhee drift --all --done-only --base baseline -o json`)가 "새 줄 0"으로 넘겼다. 원본 git log와 대장의 해시를 손으로 대조해서야 찾았다(framework-sprt 대장 CH-0475~0477).
- 작성: Claude(framework-sprt 세션), 사용자 요청. **yunhee 코드는 고치지 않았다.** framework-sprt 쪽은 "시작할 때 원본 커밋 해시와 대장을 대조한다"(변경반영 README 원칙 7)로 막아 두었다.
- 변경반영은 "늦는 것은 괜찮지만 빠지는 것은 안 된다"가 원칙이다. 이 문제는 **조용히 빠뜨리는** 쪽이라 급하다.

## 2. 원인 (`src/yunhee/tools/as_is/drift.py`, 063 #3)

L1503-1541에서 대장과 `__units__`의 `해당없음·반영·완료·넘김·보류` 단위를 `done_shared_units[파일] = {단위 이름}`으로 모은다. L1749-1762에서는 공유 파일이 바뀌었을 때, 이 화면이 그 단위들 중 하나도 안 쓰면 **파일 전체를 제외**한다. 여기에 문제가 셋 겹친다.

1. **판단한 뒤의 새 커밋을 보지 않는다.** 대장 줄에는 `AS-IS 커밋`(판단할 때의 커밋)과 `처리일`이 있는데 쓰지 않는다. 한 번 `해당없음`이 된 단위는 그 뒤 몇 번을 고쳐도 계속 제외된다.
2. **제외가 단위가 아니라 파일 단위다.** "이 화면이 판단 끝난 단위를 안 쓴다"만 보고 파일의 변경을 통째로 건너뛴다. 이번에 바뀐 부분이 **판단 끝난 단위가 아닌 다른 메서드**여도 함께 사라진다(줄 범위로 어느 단위가 바뀌었는지 보지 않음).
3. **"이 화면이 그 단위를 쓰나" 판정이 틀린다.**
   - 키가 메서드 이름만이다(`u_clean = "update"`). `build_unit_screens_map`의 `method_screens["update"]`에는 **모든 클래스의 `update`**를 부르는 49개 화면이 섞여 있다(#1125 FLT 등).
   - 정작 `apr.Apr01_Appr.update` 키는 없다. 호출이 화면이 아니라 공용 팝업 `Apr01_Edit_ApprDoc`에 있어 따라가지 못한다.
   - 그래서 #1032 휴가신청·#1131 법인카드처럼 실제로 상신하는 화면이 "안 씀"으로 판정돼 제외됐다.

   확인(yunhee 파이썬으로 `build_unit_screens_map(Path('docs/as-is/src'))`): `'#1032' in m['update'] == False`, `'#1131' in m['update'] == False`, `len(m['update']) == 49`, `apr.Apr01_Appr.update` 키 없음.

덤: `webapp/` 정적 파일(`ckeditor/*.js`·`*.html`, `7db81bb7a`)은 색인 의존 파일이 아니라 drift가 아예 보지 않는다. 화면에 묶이지 않는 변경이니 `--new`나 별도 "기준선 뒤 커밋인데 아무 단위·화면에도 안 걸린 파일" 목록이 있으면 좋겠다(4번).

## 3. 제안

1. **판단 시점 이후 커밋이 있으면 제외하지 않는다** (필수)
   - 대장 줄의 `AS-IS 커밋` 칸에서 해시(백틱 안 7~9자리)를 읽고, `git log <그 해시>..HEAD -- <파일>`에 커밋이 있으면 그 단위는 "판단 끝남"에서 뺀다. 해시가 없으면 `처리일`을 쓰되 **같은 날 커밋은 새 커밋으로 본다**(날짜만으로는 앞뒤를 모름).
   - `__units__`도 같다. 기록할 때 커밋(또는 blob)을 남기고, 다르면 무효로 한다.
2. **제외는 "바뀐 단위"로 판정한다**
   - `base..HEAD` diff의 줄 범위를 단위(메서드·SQL ID)로 나눈다(framework-sprt `tools/make_change_docs.py`의 `split_units`·`unit_at`이 같은 일을 한다).
   - 바뀐 단위가 **모두** 판단 끝났고 이 화면이 그것들을 안 쓸 때만 제외한다. 하나라도 판단 전 단위가 있으면 그 파일은 보고한다.
3. **단위 키에 클래스를 붙인다**: `Apr01_Appr.update`(또는 `apr.Apr01_Appr.update`)로 찾고, 맨 이름 `update`로는 찾지 않는다. 화면 → 공용 팝업(`Apr01_Edit_ApprDoc` 등) 호출도 따라가거나, 따라가지 못하면 **제외하지 않는 쪽으로**(모르면 보고) 한다.
4. **제외한 것을 보이게**: `-o json`에 `excluded_done_shared: [{path, unit, ledger_key, ledger_commit}]`를 싣고, table 출력의 "판단 끝난 공유 변경 n건 제외"에 `--show-excluded`를 둔다. 이번 일도 이 목록이 있었으면 바로 보였다.
5. (작게) `--done-only` 끝에 "기준선 뒤 원본 커밋 중 어느 화면에도 안 걸린 커밋·파일" 요약 한 줄. 정적 파일·새 파일·누락을 한눈에 본다.

1·2가 있으면 이번 세 건 중 두 건(`ad36c5e64`·`bfc5846cc`)은 잡혔다. 3이 없으면 1·2를 해도 팝업으로 부르는 화면을 "안 씀"으로 보고 빼는 일이 남는다.

### 6-1. 대장만 읽고 `보관/*.md`는 안 읽는다 (다시 보고 — 큼)

- `resolve_ledger_path`는 `docs/3-변경반영/변경반영-대장.md` 하나만 연다(`drift.py` L1849). framework-sprt는 끝난 줄(`반영`·`해당없음`)을 실행마다 `docs/3-변경반영/보관/{YYYY-MM}.md`로 옮긴다(같은 열, README "끝난 줄은 보관으로"). 그래서 **판단 기록 대부분이 drift에 안 보인다.** 대장에 남는 것은 `대기`·`보류`·`넘김`뿐이다.
- 실측: 현재 작업 폴더 `drift --all --done-only` → `sys01_company.xml (199) · Sys01_Company.java (186)`이 "공유 변경"으로 뜬다. 대장+보관을 합친 임시 폴더에서 돌리면 둘 다 빠진다(CH-0404·0406으로 판단, 그 뒤 새 커밋 없음).
- 제안: 대장 옆 `보관/*.md`(같은 머리줄)도 읽는다. 또는 `--ledger-glob`/`.yunhee.toml`에 대장 파일 목록을 둔다.

### 6-2. import·빈 줄만 있는 hunk도 "단위 밖 → 모르면 보고"가 된다 (다시 보고 — 큼)

- `ad36c5e64`의 `Apr01_Appr.java` hunk는 import 3곳(`@@ -3,0 +4,2`·`-4,0 +7`·`-28 +30,0`)과 `update` 본문(`-602,0 +605,25`)이다. `update`를 CH-0475로 판단한 뒤에도 import hunk 때문에 `_changed_units`가 `None`이 되고, **155화면**에 계속 뜬다(대장+보관 합친 폴더에서도).
- 메서드를 고치면 import가 따라 바뀌는 일이 흔해서, 이대로면 공유 파일 제외(063 #3)가 거의 안 먹는다. `fnd00_fund.xml (138)`도 같은 종류로 보인다(6c322f4e5, CH-0412·0413 판단 — SQL 밖 삭제 줄, 추정).
- 제안: 바뀐 줄이 모두 `import`·`package`·빈 줄·주석(Java `//`·`/* */`, XML `<!-- -->`)인 hunk는 단위 판정에서 **중립**(막지도, 단위로 세지도 않음)으로 둔다. 또는 대장의 `` `파일` · `(import)` `` 줄(framework-sprt `make_change_docs.py`가 "import·필드·파일 머리만"으로 자동 해당없음 처리)을 그 hunk의 판단으로 인정한다.
