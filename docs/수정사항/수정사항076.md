# 수정사항 076 — 매뉴얼 버튼 표기: `screen-capture --boxes`에 버튼 색·아이콘 기록 + `yunhee kbd` 신설

- 계기: framework-sprt `AssetERP/docs/6-매뉴얼`(매뉴얼 작업) #1007 문서양식등록 매뉴얼(2026-11-24). 매뉴얼 md의 버튼 표기를 Claude가 TOBE 소스(`<Button type>` → `index.tsx` → `button.css`)를 읽어 손으로 맞추고 있다. 틀리기 쉽고 토큰이 든다.
- 작성: Claude(framework-sprt 세션), 사용자 요청.
- **고칠 것은 A·B·C 세 가지다.** A는 기존 명령 보완, B·C는 새 명령 `yunhee kbd`.

## 0. 배경 — A-Man 버튼 표기

매뉴얼은 A-Man(도움말 시스템, `~/work/aman`, 소스 수정 금지)에 올린다. A-Man은 md의 인라인 코드(백틱)를 버튼으로 그린다(`frontend/src/components/shared/AssetKbdRenderer.tsx`).

| md | A-Man이 그리는 것 |
|:---|:---|
| `` `저장` `` | `button-defines.json`에 그 글자가 있으면 그 색·아이콘(L137-145). 없으면 그냥 코드 글자 |
| `` `0F7F90:check:저장` `` | `색:아이콘:글자` 직접 지정(L147-154). 아이콘에 `fa-`가 없으면 `fas fa-`를 앞에 붙인다(L113-117) |

- 정의: `http://localhost:8081/aman/button-defines.json` — `[{color:"17A2B8", icon:"fas fa-check", texts:["저장", …]}, …]` 31묶음, 글자 305개, 같은 글자가 두 묶음에 있는 경우는 없다(2026-11-24). A-Man은 글자 → 묶음을 `map[text] = …`로 만든다(L36-42, 같은 글자가 생기면 뒤 묶음이 이김).
- 정의는 AS-IS `myApp/client/color/ColorButtonBar.java`(글자 → 색·FontAwesome 아이콘)를 옮긴 것이다.

**문제**: TOBE 버튼(React, Ant Design 아이콘)은 AS-IS와 색·아이콘이 다를 수 있다. 그때 `` `저장` ``으로 쓰면 A-Man에는 화면과 다른 버튼이 그려진다. #1007에서 실제로 나온 것:

| 버튼 | TOBE 화면 | A-Man 정의 | 원인 |
|:---|:---|:---|:---|
| 저장 | `0F7F90` check | `17A2B8` fas fa-check | TOBE UX-15(`.erp-btn-type-save:not(:disabled)`가 더 진한 색) |
| 구분추가 | `6AB6CF` eye | `E89646` fas fa-eye | TOBE `view` 타입이 lightBlue(AS-IS는 orange) |
| 닫기·수정·미리보기·내보내기 | 있음 | 없음 | TOBE에서 생긴 제목 |

그래서 규칙은 이렇다(사용자 결정 2026-11-24 — A-Man은 그대로 두고 버튼은 늘 TOBE 색·아이콘으로 보이게 쓴다. framework-sprt `docs/6-매뉴얼/README.md` "버튼 표기"):
- A-Man에 그 글자가 있고 **색·아이콘이 TOBE 화면과 같으면** `` `글자` ``
- 다르거나 A-Man에 없으면 `` `색:아이콘:글자` ``(색 = TOBE 화면 배경색 6자리 대문자, 아이콘 = FontAwesome 이름)

이 판정을 yunhee가 하게 한다. **TOBE 소스를 읽지 않고, 캡처할 때 브라우저에 실제로 그려진 색·아이콘을 쓴다**(CSS 덮어쓰기·UX 보강까지 저절로 반영된다).

## A. `screen-capture --boxes`: 버튼 요소에 `style` 추가

### 지금
`src/yunhee/tools/screen_capture.py` L1935-2006(버튼 수집). `kind: "button"`·`"icon-button"` 요소에 `name`·`text`·`box`·`area`·`parent`·`disabled`만 있다.

### 고칠 것
1. 버튼마다 `style`을 더한다(`kind`가 `button`·`icon-button`일 때만).
   ```json
   {"name": "저장", "kind": "button", "text": "저장", "box": [880, 883, 76, 32], "area": "modal", "parent": "문서양식 등록", "disabled": false,
    "style": {"bg": "0F7F90", "fg": "FFFFFF", "icon": "anticon-check", "fa": "check", "class": ["erp-btn", "erp-btn-mint", "erp-btn-type-save"]}}
   ```
   - `bg`·`fg`: `getComputedStyle(btn).backgroundColor`·`color`를 6자리 대문자 hex로(`rgb(15, 127, 144)` → `0F7F90`). 투명(`rgba(0,0,0,0)`)이면 `null`.
   - `icon`: 버튼 안 `.anticon`의 `anticon-…` 클래스(없으면 `null`). L1982-1984가 이미 찾는다 — 그 값을 그대로 둔다.
   - `fa`: `icon`을 아래 표로 바꾼 FontAwesome 이름. 표에 없으면 `null`.
   - `class`: 버튼의 `erp-btn*` 클래스만(그 밖의 antd 클래스는 뺀다).
2. **마우스 위치**: 스타일을 읽기 전(=boxes 수집 전)에 `page.mouse.move(0, 0)`으로 마우스를 화면 밖 쪽으로 옮긴다. `[조회]`를 클릭한 뒤 마우스가 그 버튼 위에 남으면 hover 색(`597EB1`)이 읽힌다. 캡처 이미지에도 hover가 찍히지 않아 좋다.
3. `disabled: true`인 버튼도 그대로 기록한다(꺼진 색). 켜진 색 판단은 B에서 한다.
4. `docs/boxes-json-규격.md` 4절(요소)·6절(kind)에 `style`을 적는다. 기존 키는 바꾸지 않는다(`yunhee mark`는 영향 없음).

### Ant Design → FontAwesome 표 (TOBE 공통 버튼이 쓰는 것 전부)

TOBE `frontend/src/components/button/index.tsx` L22-56의 `TYPES`와 framework-sprt `docs/button-types.md`의 "← fa-…" 열에서 뽑았다. yunhee 안에 기본표로 두고, `.env.yunhee`의 `YUNHEE_KBD_ICON_MAP`(JSON 파일 경로, `{"anticon-xxx": "fa 이름"}`)이 있으면 그것으로 덮어쓴다.

## B. 새 명령 `yunhee kbd` — 버튼 표기 표

```bash
yunhee kbd <boxes.json | 폴더>...  [--defines <URL|파일>] [--json]
# 예
yunhee kbd AssetERP/manual/1007/src
```

### 하는 일
1. 받은 `*.boxes.json`(폴더면 그 안 전부)에서 `kind: button`·`icon-button` 요소를 모은다. 같은 `text`+`parent`는 하나로 친다.
   - 같은 버튼이 켜짐·꺼짐 둘 다 있으면 **켜진(`disabled: false`) 것**의 `style`을 쓴다. 꺼진 것만 있으면 표에 `⚠꺼짐`을 달고, `class`에 `erp-btn-type-save`가 있으면 켜진 색 `0F7F90`… 같은 추측은 하지 않는다(사람이 본다).
   - 모달 오른쪽 위 X 버튼(L1950 `ant-modal-close`, 이름 "닫기")은 뺀다(`style.bg`가 `null`이고 글자 버튼이 아니다).
2. A-Man 정의를 읽는다. 순서: `--defines` → `.env.yunhee`의 `YUNHEE_AMAN_URL` + `/button-defines.json`(새 설정 키. framework-sprt는 `http://localhost:8081/aman`). 받으면 `~/.yunhee/cache/button-defines.json`에 저장하고, 서버가 꺼져 있으면 그 캐시를 쓴다(쓸 때 "캐시 사용(날짜)"를 알린다).
3. 버튼마다 판정한다. A-Man 쪽 `icon`은 `fas fa-`를 뗀 이름으로, 색은 대문자로 비교한다.
   - 글자 찾기: 정확히 같은 글자 → 없으면 공백을 뺀 글자끼리(`행추가` ↔ `행 추가`). 공백을 빼고 찾았으면 A-Man 쪽 글자를 `표기`에 쓴다.
   | 판정 | 표기 |
   |:---|:---|
   | `같음` (글자 있음, bg·fa 같음) | `` `저장` `` |
   | `색다름` / `아이콘다름` / `둘다다름` | `` `0F7F90:check:저장` `` |
   | `A-Man없음` | `` `E89646:ban:닫기` `` |
   | `아이콘없음` (`fa`가 null — 표에 없는 anticon) | `` `색::글자` `` + `⚠anticon-xxx` |
4. 출력(md 표, 기본):
   ```
   ### 버튼 표기 (1007, A-Man 정의 31묶음·305글자, http://localhost:8081/aman/button-defines.json)
   | 버튼 | 창 | TOBE | A-Man | 판정 | 표기 |
   |:---|:---|:---|:---|:---|:---|
   | 조회 | 본 화면 | 456EA6 search | 456EA6 search | 같음 | `조회` |
   | 저장 | 문서양식 등록 | 0F7F90 check | 17A2B8 check | 색다름 | `0F7F90:check:저장` |
   | 구분추가 | 본 화면 | 6AB6CF eye | E89646 eye | 색다름 | `6AB6CF:eye:구분추가` |
   | 닫기 | 문서양식 등록 | E89646 ban | - | A-Man없음 | `E89646:ban:닫기` |
   ```
   - `--json`: 같은 내용을 `[{text, parent, tobe:{bg,fa}, aman:{color,icon}|null, verdict, notation}]`로.

## C. `yunhee kbd --check <md>` — 매뉴얼 md 검사·고치기

```bash
yunhee kbd --check "AssetERP/manual/1007/1007 문서양식등록.md" --boxes AssetERP/manual/1007/src [--fix]
```

### 하는 일
1. md에서 인라인 코드(백틱 한 쌍, 코드 블록 안은 제외)를 모두 뽑는다. `색:아이콘:글자`면 글자만 떼어 낸다.
2. 각 글자를 B의 표(같은 `--boxes`로 만든 것)에서 찾는다.
   | 경우 | 보고 |
   |:---|:---|
   | 표에 있고 md 표기 = B의 표기 | 통과 |
   | 표에 있는데 md 표기가 다름 (예: `` `저장` `` 인데 B는 `0F7F90:check:저장`) | `❌ L58 \`저장\` → \`0F7F90:check:저장\`` |
   | 표에 없음 (화면에 없는 버튼 이름) | `⚠ L120 \`예\` — 캡처에 없는 버튼(확인창 등)` |
   | 글자가 버튼이 아닌 것 같음 (공백 포함 20자 넘음·숫자만 등) | 건너뜀 |
   - 같은 글자가 창마다 다른 표기면(예: 본 화면 `닫기`와 팝업 `닫기`가 색이 다름) `⚠ 창마다 다름`으로 알리고 고치지 않는다.
3. `--fix`: ❌ 줄만 B의 표기로 바꿔 쓴다(파일 덮어쓰기 전에 `<md>.bak`). ⚠는 고치지 않는다.
4. 끝에 요약 한 줄: `버튼 표기 23개: 통과 19 · 고칠 것 2 · 캡처에 없음 2`. ❌가 있으면 종료코드 1.

## 확인 방법 (framework-sprt, 2026-11-24 캡처 그대로 씀)

`AssetERP/manual/1007/src/`에 #1007 캡처 6장과 boxes.json이 있다. A를 구현한 뒤에는 다시 캡처해야 `style`이 생긴다:
```bash

yunhee screen-capture 1007 --login kfstest/121/1111 --boxes -o /tmp/kbd-1007
yunhee kbd /tmp/kbd-1007/1007_Dcr05_Tab_DocType
yunhee kbd --check "manual/1007/1007 문서양식등록.md" --boxes /tmp/kbd-1007/1007_Dcr05_Tab_DocType
```
기대:
1. 본 화면 `조회` `456EA6`·`등록` `2EAC7E`·`삭제` `DD5E5E`·`구분추가` `6AB6CF` — 모두 hover 색이 아니다(`조회`가 `597EB1`이면 A-2 실패).
2. `저장`(문서양식 등록·코드추가) `0F7F90:check:저장`, `구분추가` `6AB6CF:eye:구분추가`, `닫기` `E89646:ban:닫기`, `수정`·`미리보기` `6AB6CF:eye:…`, `행 추가` `같음`, `행 삭제` `같음`.
3. `--check`: 지금 md는 Claude가 손으로 고친 판이라 버튼 표기가 모두 통과해야 한다. `예`(삭제 확인창)는 ⚠ 캡처에 없음. 고치기 전 판(`저장`·`구분추가`를 글자만 쓴 것)으로 바꿔 넣으면 `저장` 3곳(L67·L111·L114)과 `구분추가` 3곳(L27·L52·L109)이 ❌로 나와야 한다.
4. A-Man 서버를 끄고 다시 돌리면 캐시를 쓰고 그렇게 알린다.
