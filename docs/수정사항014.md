  1. outline Java 파싱 (tools/outliner.py _outline_java)

  1-A. 메서드 위 애너테이션에 =가 있으면 메서드가 사라짐

  증상: FileController.uploadFile(L37)이 빠집니다.

  원인: 메서드 후보의 prefix를 검사하는 순서가 잘못됐습니다.
  - if "=" in prefix_str or "return" in prefix_str: continue가 애너테이션을 지우기(clean_prefix = re.sub(...)) 전에
    실행됩니다.
  - 그래서 @PostMapping(value = "/upload", consumes = …)의 = 때문에 메서드가 대입문으로 판정돼 버려집니다.
  - @GetMapping(value = …), @Transactional(readOnly = true)처럼 메서드에 붙는 애너테이션 전부 같은 문제가 생깁니다.

  수정: 애너테이션을 먼저 지우고 나서 =·return을 검사합니다. 애너테이션 인자에 괄호가 중첩될 수
  있으니(@PreAuthorize("hasRole('X')")) 지울 때 paren_end로 짝을 찾습니다.
  def _strip_annotations(s: str) -> str:
      out, i = [], 0
      while i < len(s):
          m = re.match(r"@[\w.]+", s[i:])
          if m:
              j = i + m.end()
              k = j
              while k < len(s) and s[k].isspace():
                  k += 1
              if k < len(s) and s[k] == "(":
                  j = paren_end(s, k, "(", ")") + 1
              i = j
              continue
          out.append(s[i]); i += 1
      return "".join(out)

  clean_prefix = _strip_annotations(prefix_str).strip()
  if "=" in clean_prefix or "return" in clean_prefix.split():
      continue

  1-B. 본문 문장이 메서드로 새어 나옴

  증상: L 41: log. info(...), L 42: when(...). thenReturn(...)처럼 문장이 메서드로 출력됩니다.

  원인: 바깥 메서드를 못 잡으면(1-A, 1-C) 중첩 필터가 동작하지 않습니다. 그러면 obj.method(...);가 ";로 끝나는 인터페이스
  메서드"로 통과합니다.

  수정: 원인을 고쳐도 다른 예외 상황에서 또 샐 수 있으니, 두 가지 방어 검사를 추가합니다.
  # 이름 바로 앞(공백 제외)이 '.'이면 호출이다
  k = name_start - 1

  if ret_type_tokens and not re.fullmatch(r"[\w$<>\[\],.?\s]+", " ".join(ret_type_tokens)) or (ret_type_tokens and

  method_ident_pat = re.compile(r"\b([^\W\d]\w*)\s*\(")

  1-D. 인자 없는 enum 상수 요약

  증상: RedisTokenService.RotationStatus { ROTATED, GRACE, MISMATCH, NOT_FOUND, REUSED }의 상수 줄이 없습니다.

  원인: 상수 요약을 "인자 있는 상수"를 찾을 때만 만듭니다.

  수정: 상수 구간(enum 본문 {부터 최상위 첫 ; 또는 }까지)을 최상위 ,로 나눕니다. 각 조각의 첫 식별자(앞의 애너테이션은
  건너뜀)를 상수 이름으로 쓰고, 인자 유무와 관계없이 같은 형식으로 출력합니다.

  2. api --timeout

  현재: 타임아웃이 코드에 고정돼 있습니다(api_client.py L246·L279 요청 15초, L105 로그인 10초). 시간 초과도 연결 실패와
  같은 문구(API 요청 실패 … timed out)로 나옵니다.

  수정
  1. CLI에 --timeout <초>를 추가합니다. 기본값은 .env.local의 YUNHEE_API_TIMEOUT, 없으면 15초입니다. 첫 요청과 401 재시도
     요청 모두에 적용하고, 로그인은 지금처럼 10초로 둡니다.
  2. httpx.TimeoutException을 따로 잡아서 원인이 보이게 합니다.
  오류: 응답 시간 초과 (15s) — GET /api/v1/sys/login-histories
        서버 처리가 느립니다. 필요하면 --timeout 60 으로 늘리세요.
     느린 SQL을 찾는 신호로도 쓸 수 있도록, 시간 초과는 일반 연결 실패와 구분된 문구여야 합니다.

  검증
  yunhee api GET /api/v1/sys/menus/company --timeout 0.001     # → "응답 시간 초과 (0.001s)" 문구, 연결 실패 문구 아님
  yunhee api GET /api/v1/sys/menus/company --timeout 30        # → HTTP 200 / Rows: 94
  YUNHEE_API_TIMEOUT=0.001 yunhee api GET /api/v1/sys/menus/company   # → env 기본값 적용 확인
  단위 테스트에서는 httpx.request가 httpx.ReadTimeout을 던지게 monkeypatch해서 문구를 확인하고, 전달된 timeout 인자 값도
  확인합니다.
