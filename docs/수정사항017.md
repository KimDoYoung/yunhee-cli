`framework-sprt/AssetERP_1`에서 A15(고객별 시스템정보 관리)를 원본 UI대로 만들면서 0.2.1을 실제로 썼다.

## 1. `sql-check --tobe`가 XML 문법 오류를 통과시킨다

**증상**
TOBE 매퍼 XML 주석에 `--`가 들어 있었다.
```xml
<!-- 관리정보 탭: AS-IS selectById(L115) 중 Info01 그리드 컬럼 (yunhee port-sql --cols). … -->
```
- XML 규칙상 주석 안에는 `--`를 쓸 수 없다. 그래서 MyBatis가 시작할 때 `SAXParseException`으로 실패했다(테스트 8개 실패, 서버도 뜨지 않음).
- 그런데 `yunhee sql-check --tobe backend/src/main/resources/mapper`는 같은 파일의 모든 문장을 ✅로 보여 줬다.
- 같은 종류의 실수: `&`·`<`를 그대로 쓴 SQL(`a < b`), 닫히지 않은 태그, 잘못된 엔티티.

**원인**
`tools/as_is/sql_checker.py` L33 `parse_xml`은 정규식 토큰 파서(`TOKEN_RE`)다. AS-IS 매퍼에 깨진 XML이 섞여 있어서 일부러 관대하게 만들었다. 그러다 보니 MyBatis가 실제로 거부하는 문서도 그대로 읽는다.

**수정**
1. `--tobe`일 때는 문장을 검사하기 전에 파일마다 **엄격한 XML 파서**로 한 번 읽는다(`xml.dom.minidom.parse`나 `xml.etree.ElementTree`, DTD는 내려받지 않음).
   - 실패하면 그 파일을 `❌ XML 오류 L{줄}:{열} {메시지}` 한 줄로 내고, 그 파일의 문장 검사는 건너뛴다.
2. 흔한 원인에는 힌트를 붙인다.
   - 주석 안 `--` → "XML 주석 안에는 `--`를 쓸 수 없다"
   - SQL 안 `<`·`&` → "`&lt;` 또는 `<![CDATA[ ]]>`"
3. AS-IS 매퍼(`--tobe` 없음)는 지금처럼 관대하게 읽는다. 원본은 고칠 대상이 아니다.

**검증**
- 아래 파일을 둔 임시 매퍼 폴더(프로젝트 안, 예: `backend/src/main/resources/zz_tmp`) → `❌ XML 오류 L…: … 주석 안에는 '--'`
  ```xml
  <mapper namespace="x.Y"><!-- a --b --><select id="s">SELECT 1</select></mapper>
  ```
- `<select id="s">SELECT 1 WHERE 1 < 2</select>` → `❌ XML 오류` + `&lt;` 힌트
- 정상인 `AssetERP_1/backend/src/main/resources/mapper` → 지금과 같이 모두 ✅, 경고 0

## 2. `port-sql`이 대소문자 섞인 별칭을 그대로 낸다

**증상**
```bash
yunhee port-sql sys02_user.selectByName
#  → to_decrypts(sys02_passwd)   AS decPasswd
#     record UserRes(..., String decPasswd)
```
- AS-IS 별칭이 `sys02_decPasswd`(대소문자 섞임)다. 그래서 접두어만 떼어 `decPasswd`가 됐다.
- PostgreSQL은 따옴표 없는 별칭을 소문자로 바꾸므로 결과 컬럼 이름은 `decpasswd`다. `map-underscore-to-camel-case`로는 `decpasswd`가 `decPasswd`로 매핑되지 않는다.
- MyBatis 자동 매핑이 대소문자를 무시해서 맞을 때도 있다. 하지만 생성자(record) 인자 이름 매핑(`arg-name-based-constructor-auto-mapping`)에서는 결과가 보장되지 않는다.
- AssetERP_1에서는 손으로 `AS dec_passwd`로 고쳤다.

**원인**
`tools/as_is/sql_porter.py`의 별칭 변환이 "접두어(`sys02_`) 제거"만 하고 snake_case 정규화를 하지 않는다.

**수정**
1. TOBE 별칭은 항상 **소문자 snake_case**로 만든다.
   - camel·Pascal 경계에 `_`를 넣고 소문자로 바꾼다: `decPasswd` → `dec_passwd`, `sys02_decPasswd` → (접두어 제거 후) `dec_passwd`
   - 이미 snake면 그대로 둔다.
2. record 필드 이름은 그 snake 별칭의 camelCase로 만든다(`dec_passwd` → `decPasswd`). 별칭과 필드가 항상 짝이 맞는다.
3. AS-IS resultMap의 `property`(예: `decPasswd`)와 필드 이름이 다르면 주석으로 알린다. 지금 예에서는 같다.
4. `sql-check --tobe`의 DTO 대조도 같은 규칙으로 맞춘다. 따옴표 없는 대소문자 섞인 별칭은 "PostgreSQL이 소문자로 바꿈 → 필드와 안 맞을 수 있음" ⚠로 보여 준다.

**검증**
- `yunhee port-sql sys02_user.selectByName` → `to_decrypts(sys02_passwd) AS dec_passwd`, record 필드 `decPasswd`
- `yunhee port-sql sys04_role.selectByName` → 지금과 같다(A01 `roleColumns`와 같음)
- 임시 매퍼에 `AS decPasswd`를 두고 `sql-check --tobe` → ⚠ "소문자로 바뀜"

## 3. 새 기능: `yunhee screen` — 브라우저 확인 결과 요약 (우선)

**배경**
- 지금 AssetERP_1에서 토큰을 가장 많이 쓰는 곳은 화면 확인이다.
- 화면마다 Playwright 스크립트를 쓴다: `tools/screens/A15.js`, `A15-info01.js`, `A15-user.js`(06 확인 항목 6·7·10). 스크립트는 JSON(헤더 30개, 버튼 목록, 메시지 …)을 통째로 출력하고, 실패하면 스택과 Playwright 호출 로그가 수십 줄 나온다.
- A15에서는 선택자 실수, 가로 스크롤 밖 컬럼, 체크박스 편집 문제를 찾으려고 같은 스크립트를 열 번 넘게 돌렸다. 매번 그 출력을 다 읽었다.

**제안**
```bash
yunhee screen tools/screens/A15-user.js --out <스크린샷 폴더> [--expect tools/screens/A15-user.expect.json] [-- <스크립트 인자…>]
```
1. 스크립트를 실행한다. `NODE_PATH`(playwright-core 위치)와 브라우저 경로는 `.env.local`·`.yunhee.toml`에서 채운다. 원시 출력은 `yunhee run`처럼 `.yunhee/runs/`에 저장한다.
2. 스크립트가 마지막에 찍는 JSON(`console.log(JSON.stringify(out))`)을 읽어 요약한다.
   - **기대값 파일이 있으면** 다른 항목만 보여 준다.
     ```
     ✅ 14/16 일치 (A15-user, 9.8s)
     ❌ lookupButtons: 기대 ["조회","펼치기","감추기","저장","닫기"] / 실제 ["조회","저장","닫기"]
     ❌ toggleAfter: 기대 true / 실제 false
     ```
   - **기대값 파일이 없으면** 키별 한 줄로 줄여 보여 준다. 배열은 길이와 앞 3개만, 문자열은 60자까지.
     `errs`·`msgs`처럼 이름이 정해진 키는 항상 전체를 보여 준다(콘솔 오류, 화면 메시지).
3. 실패(예외·타임아웃)하면 **Playwright 오류 첫 줄 + 기다리던 선택자 + 마지막 스크린샷 경로**만 보여 준다(호출 로그 전체는 runs 파일에).
4. `--update-expect`: 이번 결과로 기대값 파일을 만들거나 고친다(처음 한 번 확인한 뒤 고정).
5. 기대값 파일 형식: JSON. 키별 값 그대로, 또는 `{"$len": 30}`(길이만), `{"$contains": "저장 후 시도해주세요"}`, `{"$any": true}`(값 무시).

**검증**
- `yunhee screen tools/screens/A15-user.js --out /tmp/shots`(기대값 없음) → 20줄 이내 요약. `errs: []`, `msgs` 전체가 보인다.
- `--update-expect` 뒤 다시 실행 → `✅ n/n 일치` 한 줄
- 스크립트의 선택자 하나를 일부러 틀리게 → 오류 첫 줄 + 선택자 + 스크린샷 경로, 3줄 이내

## 참고: 0.2.1에서 잘 동작한 것
- **`sql-check --tobe`**: 새 매퍼 6개(`SysCompanyMenuMapper`, `DcrClassTreeMapper`, `SysLoginSecureMapper`, `SysUserMapper`, `SysAdminUserMenuMapper`, `SysCompanyMapper` 추가분)를 컴파일 전에 확인했다. DTO 대조 오탐 0.
- **`sql`**: 읽기 전용 강제가 동작한다. 데이터 확인과 시험 뒤 남은 행 0건 확인에 psql을 한 번도 쓰지 않았다.
- **`port-save`**: 공인IP·관리자 계정의 INSERT/UPDATE/DELETE를 거의 그대로 썼다. 회사 조건을 대상 회사(경로 변수)로 바꾼 것만 손으로 했다.
- **index-src**: "저장 시 부수 효과" 절 덕분에 원본 공용 저장 클래스를 직접 열 필요가 없었다.
