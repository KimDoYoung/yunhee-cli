## 1. `req`·`errors`·`tail`의 `--archived`가 아무것도 하지 않음

**재현** (2026-10-08 16:39:15 KST에 `GET /api/public/companies` 요청이 있다 — `trace abd1f6520f3647c6 --archived`로 확인)
```
yunhee log req GET /api/public/companies --archived --from "2026-10-08 16:30" --to "2026-10-08 16:45"
→ GET /api/public/companies 최근 0:  (일치하는 요청 없음)
yunhee log tail --archived --from "2026-10-08 16:39" --to "2026-10-08 16:40"
→ 선택 범위: 요청 0, …  (기록 없음)
yunhee log errors --archived --from "2026-10-08 09:00" --to "2026-10-08 18:00"
→ WARN/ERROR 선택 범위: 0줄, 0종  (기록 없음)
```
`--archived`를 빼도 결과가 같다. 옵션은 `--help`에 있고 받기도 하지만, `archived`를 쓰는 곳은 trace 경로(L200~209 docker, L298~300 local)뿐이다. 범위 명령의 `read_logs_docker`(tail -n)·`read_logs_local`은 오늘 파일만 읽는다.

**수정**
1. 범위가 정해진 `req`·`errors`·`tail`에 `--archived`가 있으면, 범위에 걸치는 **날짜의 gz만** 읽는다: `archived/yyyy-MM/{app}-info-yyyy-MM-dd.N.log.gz`(`errors`는 `-error-`), 날짜는 범위 시작~끝을 **로그 시간대(UTC)** 로 바꾼 날짜들. 범위 끝이 오늘이면 오늘 파일도 더한다. docker면 `docker exec … zcat <파일들>`(B-5: `zcat`만), local이면 `gzip.open`.
2. 같은 날 `.0`·`.1`… 여러 개면 모두 읽는다. 읽은 뒤에는 기존 시각 필터·중복 제거(022 §2)를 그대로 쓴다.
3. `--archived`인데 범위가 없으면(`--since`·`--from`·`--since-deploy`·`--since-run` 모두 없음) 기본 범위(10m·1h·24h)라 지난 파일이 필요 없다 — 한 줄 알림 `(--archived: 범위가 오늘이라 지난 파일을 읽지 않음)`만 낸다.
4. 범위 시작이 오늘 파일 첫 줄보다 앞인데 `--archived`가 없으면 021 B-3(0) 규칙 8의 안내("오늘 파일은 HH:MM부터 — 그 전은 --archived")를 낸다. 지금은 `(기록 없음)`만 나와서 "그 시간에 요청이 없었다"로 오해한다.

**기대 (검증 ID `023-1 archived 범위`)**
- `yunhee log req GET /api/public/companies --archived --from "2026-10-08 16:30" --to "2026-10-08 16:45"` → `trace abd1f6520f3647c6` 포함.
- 같은 명령에서 `--archived`를 빼면 → `(일치하는 요청 없음)` + `오늘 파일은 … 부터 — 그 전은 --archived`.
- 픽스처: `tests/fixtures/log/archived/2026-10/AssetERP-backend-info-2026-10-08.0.log.gz`(B-1 줄을 날짜만 바꿔 gzip)로 `--file` 없이 `--source local --dir tests/fixtures/log` 시험.

## 2. `trace --archived`로 찾은 결과의 안내·시각

**재현**
```
yunhee log trace abd1f6520f3647c6 --archived
요청: GET /api/public/companies → 200 (5ms) · - · 172.18.0.1 · 07:39:15 UTC (16:39:15 KST) · trace abd1f6520f3647c6
…
원문: yunhee log trace abd1f6520f3647c6 --raw
```
- 마지막 줄을 그대로 실행하면 `로그에 없음`이다. `--archived`로 찾았으면 안내에도 붙인다: `원문: yunhee log trace abd1f6520f3647c6 --raw --archived`.
- 시각에 날짜가 없어서 오늘 것처럼 보인다. 레코드 날짜가 오늘(로그 시간대)이 아니면 날짜를 붙인다: `2026-10-08 07:39:15 UTC (10-08 16:39:15 KST)`. `req`·`tail` 목록 줄도 같은 규칙(오늘이 아니면 `10-08 07:39:15`).
- `api --log`가 붙이는 안내는 그대로(그쪽은 항상 오늘).

**기대 (검증 ID `023-2 archived 안내`)**: 위 명령 출력에 `--raw --archived`와 `2026-10-08 07:39:15`.

## 3. `--archived`로도 못 찾았을 때의 문구

**재현**: `yunhee log trace deadbeef00000000 --archived` → `trace deadbeef00000000: 로그에 없음 (오늘 파일만 봄 — 지난 날은 --archived)` (L581). 이미 `--archived`를 줬는데 같은 안내다.

**수정**: `--archived`이면 `trace deadbeef00000000: 로그에 없음 (오늘 파일 + archived gz N개 검색)`. Exit 1은 그대로.

**기대 (검증 ID `023-3 archived 없음 문구`)**: 출력에 `archived gz`, `!지난 날은 --archived`, Exit 1.
