# 수정사항 025 — `analysis run`에 `--stderr`가 없음 (대상 0.2.8)

- 작성: 2026-10-12, yunhee **0.2.8** 기준. 반영하면 **0.2.9**.
- AssetERP_1 A09(메뉴 관리) 화면 스크립트를 돌리다가 찾았다. 결함이 아니라 빠진 기능이다.

## 1. 실패한 run의 STDERR를 볼 방법이 없음

**재현**
```
yunhee run "bash -c 'NODE_PATH=… node tools/screens/A09.js <폴더>'"   # Exit 1
→ ❌ … (요약에는 STDOUT 끝 몇 줄만)
yunhee analysis run last --stdout
→ 결과 JSON(중간까지) — 실패 이유 없음
yunhee analysis run last --stderr
→ Error: No such option: --stderr (Possible options: --later, --server, --stdout)
```
- 화면 스크립트(playwright)는 결과 JSON을 STDOUT에, 실패 이유(`locator.click: Timeout 30000ms exceeded.` + Call log)는 STDERR에 쓴다. 실패 이유는 STDERR에만 있다.
- A09에서 실패 4번의 원인(`ag-body-horizontal-scroll … intercepts pointer events`)을 보려고 runs 로그를 직접 `sed -n '/--- STDERR ---/,$p' .yunhee/runs/<id>.log | head -16`으로 잘라 읽었다. 05 §7 "셸 직접 실행, 로그 grep 하지 않는다"를 어긴 것이다(A09 작업기록 비용).
- gradle·tsc는 실패 내용이 STDOUT에도 나와 `--stdout`·`--tests`로 충분했지만, node·python 스크립트는 예외가 STDERR로만 나간다.

**원인**
- `tools/analysis/run.py` L44-51은 로그를 `--- STDOUT ---`과 `--- STDERR ---`로 나누지만 STDOUT 쪽만 `stdout`으로 돌려주고, STDERR 쪽은 버린다(L53-58 반환 dict에 없음).
- `cli.py` L1138-1141 `analysis` 옵션에 `--stdout`만 있다. `run.py` L142-144가 `stdout_opt`만 처리한다.
- 로그 형식은 `tools/runner.py` L201-213(`--- STDOUT ---` … `--- STDERR ---` … 끝)이라 나누기는 이미 된다.

**수정**
1. `run.py`의 로그 파싱에서 `stderr_text = rest.split("--- STDERR ---", 1)[1].strip()`(없으면 "")을 만들고 반환 dict에 `"stderr"`를 넣는다.
2. `cli.py` `analysis`에 `--stderr` 옵션(`"실행 로그의 STDERR 부분만 출력"`)을 더하고 `opts["stderr"]`로 넘긴다. `run.py`는 `--stdout` 처리 바로 뒤에 `if stderr_opt: return stderr_text`(비어 있으면 `(STDERR 없음)`).
3. 길이: STDERR는 playwright Call log처럼 길 수 있다. `--stdout`과 같게 전부 출력하되, `-n <줄 수>`(또는 기존 공통 옵션이 있으면 그것)로 앞에서 N줄만 받을 수 있게 한다. 제안 기본값은 전부.
4. `yunhee run` 실패 요약(Exit ≠ 0)에 STDERR 첫 줄이 있으면 한 줄 보여 주고 `→ yunhee analysis run last --stderr` 안내를 붙인다(지금은 STDOUT 꼬리만 보여 줘서 실패 이유를 놓친다).
5. `--stdout`과 `--stderr`를 같이 주면 STDOUT, 빈 줄, STDERR 순서로 둘 다 낸다.
6. `analysis --list`와 `agent-guide`의 run 항목에 `--stderr`를 적는다.

**기대 (검증 ID `025-1 run stderr`)**
```
yunhee run "bash -c 'echo out-line; echo err-line >&2; exit 1'"
yunhee analysis run last --stderr
```
→ `err-line`만 나온다(`out-line`은 없음). `--stdout`은 `out-line`만.
- 4번: 위 `yunhee run` 요약에 `err-line`과 `--stderr` 안내가 보인다.
- pytest: STDERR 절이 비었을 때 `(STDERR 없음)`, `--- STDERR ---` 표시가 없는 옛 로그에서 빈 문자열, 두 옵션을 같이 줄 때의 순서.
