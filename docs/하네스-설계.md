# yunhee-cli Agentic Harness (에이전트 하네스) 설계서

- **작성일**: 2026-10-21 (개정: claude-cli 호환성, 하네스 역할 재정의 및 인프라 자원 생태계 연계 반영)
- **목적**: 기존 CLI 서브커맨드 기반 yunhee의 도구 자산을 Claude Code / Gemini CLI 스타일의 자율 대화형 에이전트(Agentic Chat)로 전환하고, Docker 인프라 자원(ChromaDB, RDBMS, Gotenberg, Aman 등)을 결합하여 고부가가치 마이그레이션 성과물을 자율 생산하기 위한 종합 아키텍처 및 구현 설계.
- **기반 코드 및 인프라**:
  - 하네스 프로토타입: `examples/v1.py` ~ `v4.py`, `examples/harness.py`
  - 사내 서비스 및 네트워크 인프라: `examples/docker-compose.yml`, `examples/default.conf` (Nginx 리버스 프록시)

## 0. 핵심 철학 및 불변의 원칙 (Strict Principles)

### 0.1 기존 CLI 서브커맨드 100% 보존 및 무수정 원칙 (claude-cli 호환성 절대 보장)
- **배경**: 현재 yunhee의 인자형 명령어(`events`, `table`, `analysis`, `sql-check`, `port-sql`, `port-save`, `compare`, `api`, `log`, `value` 등)와 옵션들은 사용자가 직접 칠 뿐만 아니라, **상용 vibe-coding 도구인 `claude-cli` 에이전트가 마이그레이션 컨텍스트를 압축·추출하기 위해 실시간으로 실행하는 핵심 인터페이스**입니다.
- **철칙**:
  1. 하네스(대화형 에이전트) 기능을 추가하더라도, **기존의 모든 CLI 서브커맨드, 인자, 옵션, 표준 출력(stdout) 형식, 에러 코드(exit code)는 절대 수정하거나 변경하지 않습니다.**
  2. 하네스 기능은 기존 CLI 도구를 변경하는 것이 아니라, 오직 `yunhee <enter>`(인자 없이 실행 시 진입하는 대화 모드) 내부에서만 독립적으로 동작합니다.
  3. 하네스에서 기존 도구(테이블 조회, 로그 확인 등)가 필요할 때도 기존 코드를 건드리지 않고, 이미 완성된 내부 함수를 **읽기 전용으로 안전하게 호출(소비)**만 합니다.

### 0.2 `yunhee <enter>` 대화 모드의 역할 정의 (일상 보조 + 인프라 자원 오케스트레이션)
- **고정밀 고난도 코드 생성**: 상용 `claude-cli`가 yunhee CLI 서브커맨드를 호출하여 정밀하게 처리합니다 (DTO 생성, 복잡한 비즈니스 로직 포팅, 정밀 SQL 정합성 검증 등).
- **로컬 대화 모드 (`yunhee <enter>`)**: 로컬 `qwen2.5-coder:14b` 모델의 현실적 한계(14B 규모, 16k 컨텍스트)를 감안하여 모델에게 무리한 순수 코드 생성 오케스트레이션을 맡기지 않는 대신, **호스트에 구비된 풍부한 인프라 자원(Docker: ChromaDB, Gotenberg, PostgreSQL, Aman 등)을 레버리지**하여 다음과 같은 실용적 생산성 작업을 전담합니다:
  - 파일 및 디렉터리 탐색, 내용 확인 및 합치기 (`v1~v2` 기반)
  - **Gotenberg 연계**: 마이그레이션 분석 결과 및 명세서를 **스타일링된 전문가급 PDF 보고서**로 원클릭 발간
  - **ChromaDB(bge-m3) 연계**: 이미 마이그레이션된 TOBE 코드 패턴 및 문제 해결 지식의 **시맨틱 검색(Similar Pattern RAG)**
  - **R-DBMS(PostgreSQL/MariaDB) 연계**: 수백 개 화면의 **마이그레이션 진척도 원장(Migration Ledger)** 관리 및 정합성 검증 로그 축적
  - **Aman(업무 매뉴얼) & Sofia(UI 이미지) 연계**: 화면 코드만으로 알기 힘든 **실제 업무 도메인 규칙 및 UI 컨텍스트 주입**
  - 사용자 선호도 및 프로젝트 작업 메모 관리 (`v4` 기반 `memory.md`)
  - 일상적인 코딩 질의응답 및 로컬 테스트 자동화 보조
- **설계 방향**: 14B 로컬 모델은 복잡한 다단계 논리 추론에는 한계가 있지만, **"사전에 잘 준비된 인프라 API(Gotenberg 변환, ChromaDB 검색, DB 기록)를 적절한 시점에 트리거하는 오케스트레이터"** 역할에는 매우 뛰어납니다. 따라서 사내 인프라 자원을 도구(Tool)로 묶어 다양한 고품질 성과물을 손쉽게 뽑아내도록 구성합니다.

## 1. 배경 및 필요성

### 1.1 현재 yunhee-cli의 현주소와 한계
1. **강력한 CLI 도구 보유**:
   - `events`, `outline`, `table`, `sql`, `sql-check`, `port-sql`, `port-save`, `compare`, `analysis`(screen/layout/method/model/grid/sql/servlet), `api`, `log`, `run` 등 AS-IS(GXT/Java8) → TOBE(Spring Boot/React/Java21) 마이그레이션에 필요한 정밀 분석 도구들이 풍부하게 구현되어 있음.
2. **수동 인자 조합의 높은 피로도**:
   - 사용자가 수십 개의 서브커맨드와 옵션을 외워서 하나씩 손으로 실행해야 함.
   - 예: 특정 화면의 마이그레이션을 위해 `analysis screen` → `table` → `analysis layout` → `port-sql` → `sql-check`를 순차적으로 직접 호출하고 그 결과를 수동으로 취합해야 함.
3. **현재 REPL의 무력함**:
   - 인자 없이 `yunhee`를 실행했을 때 진입하는 REPL(`src/yunhee/ui/repl.py`)은 단순 Ollama 텍스트 스트리밍 챗봇에 불과함.
   - yunhee가 가진 강력한 도구들을 대화창 내부에서 전혀 호출하거나 활용하지 못함.

### 1.2 목표: 대화형 하네스 (`yunhee <enter>`)의 현실적 역할
- **상용 AI (`claude-cli`)와의 완벽한 역할 분담**:
  - **`claude-cli`**: 초정밀·고난도 추론 작업 담당 (기존 `yunhee` CLI 서브커맨드들을 직접 실행하여 무손실 컨텍스트를 공급받음).
  - **`yunhee <enter>` (하네스)**: 사용자가 터미널에서 로컬 LLM(Qwen 14B)과 가볍게 대화하며, **정밀도가 비교적 낮아도 되는 일상적·탐색적 작업과 사내 인프라 자원의 오케스트레이션**을 보조받음.
- **하네스 대화 모드의 주요 사용 시나리오**:
  1. **파일/코드 탐색 및 취합**: "workspace 안의 a.txt와 b.txt 내용 읽어서 합쳐줘", "docs 폴더 목록 보여줘" (`v1~v2` 기반)
  2. **가벼운 상태/로그 조회**: "현재 설정값 보여줘", "최근에 발생한 에러 로그 어떤 게 있어?"
  3. **인프라 자원 연계 성과물 자동 발간**: "Sys01_Company 화면 분석 결과로 PDF 보고서 만들어줘", "비슷한 패턴의 TOBE 코드 찾아줘"
  4. **장기 기억(메모) 관리**: "내 작업 선호도를 기억해줘" (`v4` `memory.md` 기반)
  5. **일상적 코딩 질의응답**: 외부 상용 API 토큰 소모 없이 로컬에서 가볍게 물어보는 Q&A
- **핵심 원칙**: 하네스는 기존 CLI 명령어들을 '대체'하는 것이 아니라, 사용자가 `yunhee <enter>`로 들어왔을 때 로컬 모델이 손발(파일/메모리)과 강력한 인프라(Gotenberg, ChromaDB, RDBMS, Aman)를 활용해 실질적인 마이그레이션 산출물을 생산하도록 지원하는 **자율 보조 공간**입니다.

### 1.4 자원 연계를 통한 고부가가치 성과물(Artifacts & Deliverables) 파이프라인
단순히 텍스트로 대답하는 수준을 넘어, 위 인프라 자원들을 하네스의 도구(Adapters)로 묶어 다음과 같은 구체적이고 실질적인 마이그레이션 산출물을 자율 생성합니다:

```
[AS-IS GXT 소스 + MyBatis XML]
                │
                ├─► yunhee 분석 도구 (analysis, events, table, port-sql)
                │
                ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                   yunhee Agentic Harness (오케스트레이션)                    │
└──────┬──────────────────────┬──────────────────────┬─────────────────┬──────┘
       │                      │                      │                 │
       ▼                      ▼                      ▼                 ▼
[ Gotenberg 연계 ]     [ ChromaDB 연계 ]      [ RDBMS 연계 ]     [ Aman 연계 ]
       │                      │                      │                 │
       ▼                      ▼                      ▼                 ▼
 1. 마이그레이션         2. 유사 TOBE 패턴      3. 진척 원장       4. 도메인 업무
    기술명세서 PDF         시맨틱 추천 (RAG)      대시보드 적재      규칙/용어 주입
```

1. **성과물 ①: 전문가급 마이그레이션 기술 명세서 및 종합 분석 보고서 자동 발간 (Markdown + Gotenberg -> PDF)**
   - **생성 방식**: yunhee 내부의 `analysis screen/layout`, `events`, `table`, `port-sql` 결과를 종합하여 구조화된 마크다운 문서(`docs/migration/<화면코드>_spec.md`)를 생성하고, Gotenberg API를 호출하여 회사 표준 CSS 템플릿(표지, 목차, 코드 블록 하이라이팅, 페이지 번호)이 입혀진 **출력/제출용 PDF 명세서**로 즉시 변환.
   - **포함 내용**: 화면 컴포넌트 계층 트리, GXT Grid/Form 레이아웃 스펙, 버튼 및 이벤트 처리 흐름, 연관 DBML 테이블 스키마, 포팅된 TOBE SQL 및 Record DTO 명세.
   - **가치**: vibe coding 작업자뿐 아니라 PM, 고객사, QA 엔지니어가 즉시 확인할 수 있는 공식 산출물 자동화.

2. **성과물 ②: 지능형 유사 패턴 RAG 및 트러블슈팅 지식베이스 (ChromaDB + Ollama bge-m3)**
   - **생성 방식**: 이미 변환이 완료된 TOBE 컴포넌트(React UI, Spring Boot Service, Record DTO, MyBatis XML)를 `bge-m3`로 임베딩하여 ChromaDB에 적재.
   - **동작 방식**: 사용자가 새로운 화면(예: `Ast01_Trade`)을 작업할 때, 하네스가 "이 화면의 그리드/트랜잭션 구조와 가장 유사한 기존 TOBE 화면 찾아줘"라는 명령을 받아 벡터 검색을 수행하고, 가장 모범적인(Golden Path) TOBE 코드 조각을 추천.
   - **지식베이스**: 마이그레이션 과정에서 발생한 빌드 에러, 복잡한 MyBatis dynamic SQL 포팅 노하우를 색인하여 에러 해결 시간 단축.

3. **성과물 ③: 엔터프라이즈 마이그레이션 진척도 원장(Migration Ledger) 및 정합성 검증 DB (PostgreSQL / MariaDB)**
   - **생성 방식**: 수백 개 레거시 화면의 전환 라이프사이클(`ANALYZED` → `PORTED` → `API_TESTED` → `COMPLETED`)과 복잡도 지표(참조 테이블 수, SQL 수, 그리드 컬럼 수)를 PostgreSQL 테이블(`migration_progress`)에 기록.
   - **검증 아카이빙**: `compare`(HTTP API vs AS-IS SQL) 실행 결과와 `sql-check`(EXPLAIN 정합성) 통과 기록을 DB에 적재하여, 마이그레이션 전체 진척률과 데이터 무결성 검증 통계를 실시간으로 집계.

4. **성과물 ④: 레거시 업무 매뉴얼(Aman) 및 UI 캡처(Sofia) 연동을 통한 비즈니스 컨텍스트 주입**
   - **생성 방식**: 소스 코드에는 드러나지 않는 현업의 비즈니스 규칙과 용어 설명을 Aman 매뉴얼 시스템 컨테이너에서 조회하여 마이그레이션 프롬프트 및 명세서에 주입.
   - **UI 에셋 연동**: Sofia 이미지 서버의 AS-IS 화면 스크린샷을 명세서에 자동 임베딩하여, 변환된 TOBE React 화면과의 시각적 1:1 비교 검증 지원.

## 2. 핵심 제약 조건 및 극복 전략

### 2.1 로컬 모델 환경의 제약
- **모델**: Ollama `qwen2.5-coder:14b` 고정 (단일 모델)
- **VRAM**: 16GB 한도
- **컨텍스트 윈도우**: 16,384 토큰 (`NUM_CTX = 16384`)

### 2.2 상용 모델(Claude 3.7 / Gemini Pro)과의 차이 및 대응책
상용 클라우드 모델(컨텍스트 100만~200만 토큰, 뛰어난 도구 선택력)의 방식을 로컬 14B 모델에 그대로 적용하면 실패합니다:

| 문제점 (상용 방식 그대로 적용 시) | 로컬 14B 모델 특화 해결책 |
| :--- | :--- |
| **도구 수 과다 시 혼란**: 30개 넘는 도구 스키마를 프롬프트에 넣으면 스키마만으로 수천 토큰 소모 & 모델이 엉뚱한 도구 호출 | **계층형 툴킷(Tiered Tooling)**: 기본 5~6개 핵심 도구만 상시 로드하고, 전문 도구는 의도에 따라 동적 로딩 |
| **도구 호출 포맷 불안정**: 모델이 `tool_calls` 대신 본문 텍스트, 마크다운 코드블록, 괄호 누락 JSON 등으로 출력 | **다중 Fallback 파서(v2~v3 기반)**: 유니코드 따옴표 정규화 + 괄호 깊이(`depth`) 기반 JSON 객체 추출기 내장 |
| **컨텍스트 폭발**: 도구 실행 결과(수백 줄의 소스/로그/DBML) 한 번에 16k 컨텍스트 초과 | **결과 압축 가드(Result Compactor)**: 1,500자 초과 결과는 요약본만 LLM에 전달, 원문은 로컬 파일에 격리 |
| **동일 도구 무한 루프**: 목표를 달성하지 못하고 같은 도구를 계속 호출 | **시그니처 기반 루프 가드(v2 기반)**: 동일 도구/인자 연속 호출 감지 시 강제 중단 및 조기 완료 판정 |

## 5. 핵심 모듈별 상세 스펙

### 5.1 `parser.py` (견고한 도구 호출 파서)
`examples/v2.py` 및 `v3.py`에서 검증된 파서를 고도화하여 내장합니다:
1. **문자 정규화 (`sanitize_json_text`)**: 유니코드 특수 따옴표(`“`, `”`, `‘`, `’`) 및 전각 공백을 표준 ASCII로 치환.
2. **다중 패턴 탐색**:
   - Case 1: OpenAI SDK 표준 `message.tool_calls`
   - Case 2: 마크다운 코드블록 (````json ... ```` 또는 ``` ... ````)
   - Case 3: JSON 배열 형태 (`[{"name": "...", "arguments": ...}]`)
   - Case 4: **괄호 깊이 추적 파서 (`depth-bracket parsing`)**: 텍스트 본문 중에 섞인 `{ "name": ... }` 객체를 문자열 이스케이프 상태를 고려하여 정확히 발라냄.
3. **가상 함수 구조 구출**: 모델이 `print(...)`나 `final_answer(message="...")` 같은 비표준 함수를 불렀을 때 메시지 내용을 최종 응답으로 복구.

### 5.2 `loop.py` (자율 에이전트 루프)
- **최대 스텝 수 제어**: 기본 10회 (설정 가능).
- **무한 루프 방지**: 직전 호출 시그니처(`last_calls_signature`)와 현재 호출 시그니처가 동일하면 즉시 중단.
- **스트리밍 & 실시간 피드백**: LLM의 추론 생각(Thinking)과 도구 호출 결정을 실시간으로 UI 이벤트로 전달.
- **합성 메시지 주입 (`synthetic_tool_calls`)**: 텍스트 fallback으로 도구를 호출하더라도 메시지 히스토리에는 표준 `tool_calls` 및 role `tool` 형태로 변환 저장하여 컨텍스트 규격 유지.

### 5.3 `registry.py` & 도구 계층화 (Tiered Tooling)
Qwen 14B의 컨텍스트(16k)와 도구 선택력을 보호하고, **claude-cli가 쓰는 기존 CLI 인터페이스를 절대 오염시키지 않기 위해** 도구를 4계층으로 명확히 분리합니다:

1. **상시 활성 기본 도구 (Core Always-On, `v1~v4` 기반)**:
   - `list_files(directory)`: 작업 디렉터리 내 파일 목록 조회 (`v1~v3`)
   - `read_file(filename)`: 파일 내용 읽기 (`v1~v3`)
   - `write_file(filename, content)`: 파일 작성/저장 (`v2~v3`)
   - `save_memory(fact)`: 사용자 선호도 및 중요 사실을 장기 기억(`memory.md`)에 저장 (`v4`)
   - *이 도구들만으로도 `v1~v4`에서 다룬 파일 합치기, 요약, 메모 관리 등 일상적인 보조 작업을 완벽히 수행 가능*
2. **보조 조회 도구 (선택적 읽기 전용 어댑터)**:
   - `lookup_config(key)`: 현재 yunhee 설정값 확인 (`yunhee value` 로직 읽기 전용 호출)
   - `read_recent_errors()`: 최근 서버 에러 로그 확인 (`yunhee log errors` 읽기 전용 호출)
   - *주의: 기존 CLI 서브커맨드 코드 자체는 전혀 수정하지 않고, 이미 존재하는 함수를 읽기 전용으로 임포트하여 스키마만 연결함.*
3. **인프라 자원 연계 확장 도구 (Resource-backed Extended Tools)**:
   - 사내 Docker 인프라와 Nginx 프록시를 통해 고부가가치 성과물을 자동 생산하는 특화 도구:
   - `export_pdf(markdown_path: str, output_name: str = "", template: str = "report")`:
     - Gotenberg API (`http://localhost/gotenberg/forms/chromium/convert/markdown`)를 호출하여 마크다운 분석서를 공식 양식(표지, CSS, 페이지 번호)이 입혀진 PDF로 변환 및 저장.
   - `search_patterns(query: str, domain: str = "", n_results: int = 3)`:
     - ChromaDB (`:8000`)에 색인된 완료 화면(TOBE) 컴포넌트, Spring Service, Record DTO, MyBatis 매퍼 패턴 중 질의와 가장 유사한 구현 예제를 bge-m3 벡터 유사도로 검색하여 반환.
   - `record_progress(page_code: str, stage: str, status: str, note: str = "")`:
     - PostgreSQL (`jskn_postgres:5432`)의 `migration_progress` 테이블에 해당 화면의 마이그레이션 단계(`ANALYSIS`, `SQL_PORT`, `DTO`, `UI`, `VERIFIED`, `DONE`) 및 상태를 기록.
   - `get_progress_summary(domain: str = "")`:
     - PostgreSQL에서 도메인별/전체 마이그레이션 진척 통계(완료율, 잔여 화면 수, 검증 통과 현황)를 집계하여 반환.
   - `fetch_manual(page_code: str)`:
     - Aman 매뉴얼 시스템 (`http://localhost/aman`)에서 해당 화면의 공식 업무 설명, 입력 필드 검증 규칙, 업무 흐름도를 조회하여 도메인 컨텍스트 보강.
4. **외부 MCP 도구 (Extensible MCP, `v3~v4` 기반)**:
   - `.yunhee/mcp.json`에 등록된 외부 Stdio MCP 서버 도구를 동적으로 병합.

### 5.4 `memory.py` (장기 기억 및 세션 관리)
`examples/v4.py` 및 `harness.py`의 구조를 발전시킵니다:
- **`load_memory()`**: `.yunhee/memory.md`에서 사용자 선호도, 프로젝트 아키텍처 규칙(예: "모든 DTO는 Java Record로 작성", "테넌트 코드는 admin 사용" 등)을 로드하여 시스템 프롬프트에 자동 주입.
- **`save_memory(fact: str)`**: 에이전트가 대화 도중 기억할 가치가 있는 사실을 발견하면 `memory.md`에 추가.
- **세션 대화 압축 (Compactor)**: 대화 턴 수가 길어져 16k 토큰 한계에 근접하면, 오래된 턴의 상세 도구 실행 결과를 핵심 요약문으로 치환하여 컨텍스트 윈도우 확보.

### 5.5 `ui/repl.py` (Claude CLI 스타일 사용자 경험)
- **Rich Live 렌더링**:
  - 도구 실행 중 스피너 표시: `⠋ export_pdf(Sys01_Company_spec.md) Gotenberg 변환 중...`
  - 도구 실행 성공/실패 시 상태 태그: `✔ read_file (120 lines)`, `✔ export_pdf -> docs/pdf/Sys01_Company_spec.pdf`, `❌ run_command (exit code 1)`
- **Human-in-the-Loop (변경 승인 모달)**:
  - 파일 읽기나 DB 조사는 **자율 자동 실행**.
  - `edit_file`, `write_file`, 외부 프로세스 실행 시 터미널에 **컬러 diff**를 출력하고 `[y] 승인  [n] 취소  [e] 수정` 선택을 유도.
- **하이브리드 슬래시 커맨드**:
  - 대화 도중 사용자가 `/table sys01_company` 또는 `/log errors`를 입력하면, 해당 CLI 도구의 정밀한 출력 결과를 즉시 확인하고 그 결과를 현재 대화 컨텍스트에 바로 첨부.
  - 신규 인프라 단축 커맨드: `/pdf <file.md>` (즉시 PDF 변환), `/patterns <키워드>` (유사 TOBE 패턴 검색), `/progress` (진척 현황 요약).

## 7. 기대 효과

1. **상용 에이전트(claude-cli) 파이프라인 100% 안전 보장**:
   - `claude-cli`가 사용하는 기존의 모든 CLI 명령어와 옵션, stdout 규격이 조금도 변하지 않으므로 기존 마이그레이션 자동화 워크플로우에 아무런 영향이 없음.
2. **로컬 14B 모델의 현실적인 역량 극대화**:
   - 로컬 모델에게 무리한 고정밀 추론을 강요하지 않고, 파일 탐색, 요약, 메모 관리 등 실용적인 가벼운 보조 작업을 대화로 편하게 수행.
3. **토큰 절약 및 비용 절감**:
   - 단순한 파일 확인, 텍스트 합치기, 프로젝트 설정 확인 등의 작업을 상용 AI를 쓰지 않고 로컬 `yunhee <enter>`에서 무료로 신속하게 처리.
4. **고품질 산출물(PDF 보고서) 자동 발간으로 협업 및 감리 비용 획기적 절감**:
   - 화면 분석서, Grid Spec, 변환된 SQL 및 DTO를 Gotenberg를 통해 스타일링된 공식 PDF 문서로 원클릭 발간하여 PM, QA, 고객사 제출 문서 작업 자동화.
5. **ChromaDB 시맨틱 RAG를 통한 TOBE 아키텍처 일관성 유지**:
   - 기존에 변환 완료된 모범 화면 패턴(Golden Path)을 벡터 유사도 기반으로 즉시 검색·재사용하여 개발자별 코딩 스타일 파편화 차단 및 시행착오 최소화.
6. **RDBMS 기반의 정량적 마이그레이션 거버넌스 및 진척 통제력 확보**:
   - 수백 개 화면의 전환 단계, 검증 통과율, 복잡도 지표를 PostgreSQL에 실시간 적재하여 전체 마이그레이션 프로젝트의 진행 상황을 한눈에 파악.
7. **레거시 업무 매뉴얼(Aman) 결합으로 도메인 비즈니스 무결성 보장**:
   - 소스코드 주석에 부재한 숨은 업무 규칙을 자동으로 주입하여, 단순한 프레임워크 문법 변환을 넘어 실제 금융/자산운용 업무 로직의 완전한 보존 실현.
